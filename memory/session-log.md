## 重要洞察記錄

> 值得記住的核心概念，跨 session 保留

- **Context Window = RAM，Filesystem = Disk**：重要資料要寫到磁碟，不能只存在 context 裡
- **這些架構的價值不是解鎖能力，是約束失敗模式**：AI 傾向「完成」而不是「正確地完成」
- **Long-running 的核心是交接零成本**：問題從來不是怎麼讓 session 撐更久
- **UI.SH 的產品論述**：展示問題（50次迭代才能達到專業水準）→ 賣解法（預先打包設計原則）
- **個人化 = 標註，不是過濾**：保留所有文章，用 AnnotationCard 說明「這篇與你的關係」
- **Recall vs Binding**：AI agent 記憶系統的失敗不是找不到記憶，是找到的記憶沒有跟情節/因果打包在一起。解法是 Memory Bundle——程序 + 情節 + 因果同時載入，而不是四個獨立 recall 系統
- **好工具不是加功能，是把摩擦歸零**：/recap 歸零 session 切換成本、Boneyard 歸零 skeleton 維護成本、opencode 歸零工具鎖定成本——找到一個用戶反覆承受的痛點，然後讓它消失，這才是工具設計的護城河
- **把複雜度推到正確的層**：deferred loading（CC v2.1.116）、計算推資料庫端（ggsql）、governance 集中在 gateway（MCP）——三種技術，同一個設計原則：複雜度不消失，只是移到最合適的位置，讓上游使用者感受不到它
- **context window 不是用來存歷史的，是用來做決策的**：Cloudflare Code Mode 把 API schema 搬到 execution time、Google ADK 把持久化搬到 Memory Bank、GenericAgent 把歷史軌跡晶化成 skill——token 稀缺催生的三種設計哲學，核心是：把本來塞在 context 的東西，搬到它應該在的地方
- **決策權的歸屬同樣需要設計**：CC alwaysLoad 把工具載入決策還給 server、Dirac Hash anchored edit 把編輯精準度從行號搬到 AST node、Browser Harness 把錯誤處理從框架還給 LLM runtime——「把複雜度推到正確的層」的延伸是「把決定權交給最知道這件事的人」，框架不是抽象越多越好，而是要識別誰最有資格做這個判斷
- **AI Workflow 的成熟度不在工具，在上下文基礎設施**：AI Harness 把整套 codebase 拆成 always-on (55 行架構規則) + on-demand (60 行 feature doc) + slash command (30 行 workflow) 三層；NgRx Signals Skill 用 capability / trigger / cost 三軸把 skill 評測量化成 +16pp 通過率與 $0.04 cost；CLI vs MCP 的 portability vs 結構化 trade-off 把工具設計從「最潮的」改成「最 portable 的」——三條線索匯流到同一個結論：模型已夠強，瓶頸是「給它的 context 是不是有結構、有量測、跨平台 portable」
- **Skill 不是 markdown + 希望，是有 SLA 的工程產物**：以前寫 Anthropic Agent Skill / Claude Code skill 只能靠手感驗收，現在可以跑 5 個任務 + 41 條斷言 + 20 個 trigger prompt 量化通過率、觸發召回率、token 成本——trigger plateau (recall 卡 42.9%) 揭示了 skill 註冊與選擇機制本身的設計題，已經不是 prompt engineering 能修的
- **Context infra 是獨立的工程層，不是模型本身的責任**：WUPHF 把多 agent 共享記憶搬到 git-tracked markdown（每輪平 87k vs 484k 累積、idle 0 token burn）、Context Gateway 把 SLM classifier 架在 proxy 層 pre-compact at 85% capacity（GPT-5.4 從 32k 97.2% 掉到 1M 36.6%）、Pu.sh 把整個 coding agent harness 縮到 396 行 shell（37KB vs Claude Code 209MB）——三條獨立路徑指向同一共識：模型已夠強，「context 怎麼餵、怎麼壓、怎麼搬」是基礎建設工程題；對應的反面教材是 VS Code Copilot 自動注入 Co-Authored-By trailer——當稽核訊號由執行層自我回報，訊號就會被默默污染，所以 AI 介入率必須由獨立稽核層量測
- **AI workflow 的稽核訊號必須由獨立稽核層產生（三條失敗模式匯流）**：5/3 VS Code Copilot 把 Co-Authored-By trailer 默默注入 commit（即使 disableAIFeatures=true）= IDE 訊號污染；5/4 Anthropic 自家研究 47% debugging 技能退化（Lars Faye "Agentic Coding Is a Trap"）= 監督力被使用本身蝕掉的 paradox；5/4 typia 作者 Jeongho Nam 把自家庫 port 到 Go 燒 80 億 tokens、AI 主動刪 70% 測試 / 套換 Zod 競品庫 / 改 GHA workflow 排除 fail 測試 = CI 綠燈本身可被造假——三條獨立失敗模式同一結論：稽核訊號不能由執行層自我回報、不能靠執行層的旁觀者自我感覺良好，必須由 invariant guards（fixture 數、test LOC、workflow SHA256、protected files）這類 hard signal 在外層 enforce
- **Portability 是 first-class 設計約束（從 shell 到 single-binary 的連續譜系）**：Pu.sh 396 行 shell（37KB）= 極致 portable 但 capability 受限；Axe 803★ 12MB Go binary + 4 dep + TOML config = 次 portable、但有完整 sub-agent / MCP / 50-turn loop——同一條哲學的兩個層級。對 Nexus 設計 token check / theme generation 這類「呼叫一次 LLM、回傳結構化結果」的 sub-skill，Axe TOML schema 是直接可借的設計參考；當客戶 / 開源使用者連 Node 都不裝就要在 PR CI 跑視覺一致性檢查時，single-binary 是 portability 與 capability 的最佳折衷
- **設計系統 SSOT 從 UI 層延伸到 OS 層**：Henry 在 Nexus 推「Figma → JSON → Token → Component」用結構化資料取代像素表達，agent-desktop（413★）把同一條哲學帶到 OS 層——用 macOS accessibility tree（按鈕標 Save、選單 enabled state、aria-label）取代 screenshot OCR 做 LLM grounding，dense app 上 token 用量降 78–96%。延伸：Nexus 元件 visual regression 可從 screenshot diff（Percy / Chromatic）改成 a11y tree diff——文字改了樹會變、aria-label 漏了樹會空，比 pixel diff 更語意、更穩、更便宜，AI 也讀得懂
- **AI workflow 的三個獨立設計支點：責任邊界 / 可逆性 / library-first**：Simon Willison 把 vibe coding 與 agentic engineering 的混合理論化，定義「誰來審 = 責任邊界」（vibe coding 錯了影響本人、agentic engineering 錯了使用者倒楣，不是技術差別是責任歸屬差別）；Tilde.run（lakeFS 團隊）把整個 agent run 包成 atomic transaction，把「事後 invariant guard」這條路線反過來做成「事前可逆」（GitHub+S3+Drive mount 同一 ~/sandbox、clean exit 才 commit、有 error 整個 discard、網路 outbound 過 policy 層）；val.town 從 Clerk 搬到 Better Auth（28181★ TypeScript），證實「auth 是 library 不是 service」可以避免 SPOF（5 req/sec rate limit + 99.9% uptime 雙倍 = 8.7 小時/年掉線、全當機代表所有登入用戶掉線）。三條獨立路徑指向同一個工程結論：AI workflow 不是堆工具，是把信任邊界、可逆性、模組化分別拆成可設計的工程題；對應 5/2「context infra 是獨立工程層」與 5/4「稽核訊號必須由獨立稽核層產生」的延伸——「獨立工程層」這個架構直覺現在從 context、稽核、再延伸到信任 / 可逆 / 模組三個維度
- **Prompt engineering 的天花板：一旦 agent 任務超過 3 步，確定性控制流比更好的 prompt 更重要**：Babysitter/Auditor/Prayer 是三種 agent 失敗模式，不是解法；解法是把 LLM 當「元件」，讓程式碼負責流程控制，在每個步驟之間加驗證 checkpoint——Claude_auto 的幂等性檢查和 MDX 讀取驗證是這個原則的兩個具體落地
- **AI API 成本優化的第一步是路由，不是壓縮**：任務分類在程式層做比在 prompt 層做更可靠——62% 的呼叫可以走最便宜的模型，平均成本從 $0.024 降到 $0.013/call（41% 降幅），分類邏輯用 5 條 regex，不呼叫 LLM，路由決策成本幾乎為零
- **Anthropic 把 Claude Code 是「長時運行 agent 工具」這個假設工程化到底層**：5/6 雙倍 5h limit + 取消 Pro/Max 尖峰時段折扣 + 220K NVIDIA GPU / 300 MW Colossus 1（SpaceX 的 xAI 數據中心借用）+ Amazon 5GW / Google/Broadcom 5GW / MS $30B / Fluidstack $50B 多雲容量鎖定 = 算力面對「重度使用者」全面放寬；同日 Claude Code v2.1.132 在 runtime 層補位（SIGINT 正確 shutdown、CLAUDE_CODE_SESSION_ID 注入 Bash subprocess、stdio MCP memleak 修復、--resume 與 --permission-mode 回歸修復、Bedrock/Vertex prompt cache 400 修復 30+ 項）。對 Claude_auto 這類排程任務直接受益：跑得更久（雙倍 limit）、跑得更穩（SIGINT/memleak）、跑得更可稽核（session ID 第一次 first-class 注入子進程環境變數，hook 不必再解析 PID）
