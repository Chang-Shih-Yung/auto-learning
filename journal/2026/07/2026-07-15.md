## Claude Code v2.1.210——`isolation: 'worktree'` subagent 曾在跑 git 動到主 repo，這版才真的關上

**你能做什麼**

如果你昨天照著 v2.1.208 的建議把 Claude_auto 排程改成 `isolation: 'worktree'`，那今天請立刻升到 v2.1.210——因為在 v2.1.209 之前，這條隔離其實還漏水：worktree 內的 subagent 有機會執行 git 命令時穿透邊界，直接動到主 repo 的 branch、tag、config，v2.1.210 才把這個路徑關上。同一版還做了三件連動修補：`ultracode` keyword 之前會被 webhook 之類非人類輸入觸發，現在只在真人輸入時才啟動；Agent 工具對「subagent 回傳內容裡藏的 prompt injection」做了硬化；bundled `/dataviz` skill 的 palette validator 換成 OKLab 感知色差為判準，配色驗證不再只看 RGB 距離。還加了一個小但實用的 UI 修正：collapsed tool summary 這行現在有 live elapsed-time counter，長跑任務不用點開就知道跑了幾秒。

**背後怎麼運作**

`isolation: 'worktree'` 這件事的設計預期是：subagent 啟動時 git worktree add 一個新目錄、subagent 所有工具呼叫的 CWD 都綁在新目錄裡、離開時 worktree remove。這條保護預設 CWD 不會回主 repo，但 git 命令有一個尷尬性質——`git` 找 repo 是往上一路找 `.git`，如果 subagent 呼叫 `git checkout main` 而它剛好在某個 nested 目錄或 symlink，命令會沿著 filesystem 往上走進主 repo。v2.1.210 的修法是把 subagent 的 git 呼叫綁死在 worktree 的 `.git` file 上（`GIT_DIR` + `GIT_WORK_TREE` 雙軸），不讓它 walk 出去。`ultracode` 修法則是把「這個 keyword 觸發需要 tty attached 且 stdin 是人類輸入」寫進判定，斷開自動 pipe 觸發的路徑。dataviz palette validator 用 OKLab 是因為 RGB 距離跟人眼感知色差可以差 3 倍以上——同樣「距離 30」在藍色跟紅色區看起來完全不同，OKLab 把這條非線性壓平。

**這改變了什麼**

以前你相信 vendor 說「worktree 是隔離的」就照做，subagent 動了主 repo 也只能事後靠 `git reflog` 找回來——現在起這條路徑 v2.1.210 之前是有洞的、之後才真的關上，可以驗證。以前 `ultracode` 這種 keyword-driven 行為，只要有任何 webhook 或自動化管道把它塞進 stdin 就會誤觸；現在只在人類真的按下鍵盤時才會 fire。以前 palette 驗證用 hex 距離只擋得住明顯撞色，關掉「這兩個顏色人眼分不出來」這個更常見的問題；現在 OKLab 感知色差把 accessibility contrast 跟 color harmony 兩個維度一次驗到位。搭昨天的 v2.1.208「顯式 cache bound + `CLAUDE_CODE_PROCESS_WRAPPER` 企業 audit hook」→ 今天 v2.1.210「subagent 邊界從假隔離翻真隔離 + Agent 對抗 injection 硬化 + skill validator 感知色差第一級」，Claude Code 這 48 小時把 subagent 從「跑得動的實驗性 primitive」升到「隔離邊界跟色感一起校準過的 production primitive」。

## `agent-memory-2026-07-22` beta header——Anthropic 把「agent 記了什麼」拉成跨 SDK 一致的 first-class 資源

**你能做什麼**

今天起你在 Anthropic Python SDK 0.116.0、TypeScript 0.110.0、Go 1.56.0、Java 2.48.0、Ruby 1.55.0、PHP 0.36.0、C# 12.35.0、CLI 1.16.0 任何一家 SDK 上呼叫 memory store API，都會自動送 `agent-memory-2026-07-22` 這個 beta header，取代舊的 `managed-agents-2026-04-01`。這代表什麼？`GET /v1/memory_stores/{id}/memories` 這條 API 有三件行為被鎖死：`order_by` 跟 `order` 參數會被伺服器忽略，永遠回傳一個 stable 的伺服器定義順序；`depth` 只接受 `0`、`1` 或不傳，其他值直接 400；`path_prefix` 必須以 `/` 結尾且比對整段路徑而非 substring。搭 Anthropic Managed Agents 這個 April 已經 public beta 的 filesystem-based memory 層——memories 存成可 export 的檔案、內建 audit log、版本 rollback、內容 redaction、scoped permissions——實測結果 Rakuten 客服 agent 首次通過率提升 97%、成本降 27%、延遲降 34%，Wisedocs 文件驗證快 30%，Netflix 拿來做跨 session 上下文保留。

**背後怎麼運作**

過去 memory listing 沒有 stable order 是個真實痛點：同一批 memories 兩次呼叫可能回傳不同順序，做 pagination + 一致性快取都會踩坑。Anthropic 把 order 決策從 client 側「你要 asc/desc / by created / by path」翻成 server 側「我只給你一個穩定順序，你別自訂」，配上「page cursor 只在同一組 header 內有效」的規則，等於把 memory listing 當作一條 append-only 資料流來設計——不是 SQL 表任你排。`path_prefix` 從 substring 改成整段路徑比對是關掉一個 injection 面：如果 subagent 生成 `/user/../admin/secret` 這種奇怪路徑，舊 substring 比對可能被 `/admin` 的 prefix 撈到，新規則要求 `/admin/` 尾斜線且以整段 segment 為單位，等於把路徑當 filesystem 而非字串。`depth` 只允許 0、1、不傳三值，意思是伺服器要 pre-index 這幾個深度，避免任意深度 depth 讓 server 端做無界遞迴。

**這改變了什麼**

以前 agent memory 是 vendor 私有實作，跨 SDK 行為未必一致、跨版本 API 可能靜默轉向、pagination 拿不到穩定順序就得客戶端自己排——今天起這條 API 被四件事同時鎖住：跨 8 家官方 SDK 都送同一個 beta header、listing 永遠回穩定順序、path_prefix 只吃整段路徑、depth 只吃有限值。以前 memory 「agent 記了什麼」這條 introspection 路徑是黑盒，只能看 model output 的表現去反推；今天起 memory 是可 audit log 追、可 version rollback、可 redact、可 scope permission 的顯式資源，Rakuten 97% 首次通過率提升就是把黑盒翻可管理狀態帶來的實測差。這條 API 收斂搭 Managed Agents 的檔案系統模型（memories mount 進 agent filesystem、agent 用 bash + code exec 直接讀寫）等於一句話：agent memory 從「模型隱式記住」升級成「工程可管理的檔案系統資源」。

## OpenAI Codex 開始加密 sub-agent prompt——跟 Claude Code 同一條戰線的相反解法

**你能做什麼**

如果你昨天有跑 OpenAI Codex 且用了 Sol 或 Terra 模型（都是 GPT-5.6 變體），今天你會發現 sub-agent 的 prompt 在 log 裡變成一堆密文——你在 client 端看到的是加密後的 ciphertext，不再是明文 prompt。原本 debug 用的 log 現在只剩「有東西送出去了、有東西回來了」，具體 sub-agent 收到什麼 instruction、怎麼被 orchestrator 分派任務，你完全看不到。目前 Luna 模型還沒受影響、早期 GPT-5.5 也沒加密。HN 上這條 issue（[openai/codex#28058](https://github.com/openai/codex/issues/28058)）8 小時衝到 410 點 240 留言，最多人罵的一句話是 issue 作者的原話：「I can't understand how the team thought this was a good idea」——加密讓 debug 變不可能，跑到一半炸掉沒人知道哪裡出錯。

**背後怎麼運作**

OpenAI 這個決策的商業邏輯，HN 上一位叫 `bartread` 的留言講得最清楚：「the value is probably within its prompts, how they're built, and how they're sequenced」——sub-agent 的 prompt 是 OpenAI 花大錢調出來的最有價值資產，比 model weights 本身還敏感。第二個推測是 hansihe 提出的：Codex 的 ultra 模式讓多個 sub-agent 協作，OpenAI 顯然把這些 prompt 當成「跟 reasoning trace 同等級」的機密——他們早在 GPT-5.5 就開始 hide reasoning traces，這次把 sub-agent prompt 一起遮起來是同一條保護 IP 的策略。技術上 encryption 發生在 server 端下發之前，client 端收到的就是 ciphertext，本地根本沒有 decryption key。這一步跟 Claude Code v2.1.210 剛好方向相反——Anthropic 選「Agent 對抗 injection 硬化 + subagent 隔離邊界拉緊 + memory 拉成可 audit 資源」（三件都是**讓你看得見 + 邊界更明確**），OpenAI 選「加密 sub-agent prompt」（**讓你看不見 + 邊界隱在 backend**）。

**這改變了什麼**

同一個工程問題——「sub-agent 的 orchestration 邊界該怎麼設計」——今天出現了兩條截然相反的路。Anthropic 這條走 visibility + explicit isolation：Agent 邊界該對抗 injection、subagent 該有真 worktree 隔離、memory 該有 audit log 讓你查——所有一切開給你看，但每一層都有硬邊界。OpenAI 這條走 opacity + backend enforcement：你不用知道 sub-agent 拿了什麼 prompt、我 backend 自己顧、你 debug 不了是 tradeoff——這條路 vendor lock-in 深、debug 成本高、但保護 vendor 的 prompt engineering IP。對開發者的意義是 fallback chain 排序邏輯要加一條新維度：「這家 vendor 加密 sub-agent prompt 嗎？」——加密的 vendor debug 成本天然高，不加密的 vendor 你有機會做 wire-level 稽核（呼應 7/13 xAI Grok Build CLI 稽核事件）。

## Bonsai 27B——把 27B dense 模型硬塞進 iPhone 17 Pro，Apache 2.0 免費

**你能做什麼**

Bonsai 27B 給你兩個變體：1-bit 版 3.9 GB 直接跑進 iPhone 17 Pro、Ternary 版 5.9 GB 適合筆電。base model 是 Qwen 3.6 27B dense（不是 MoE），透過 ternary `{−1, 0, +1}` 跟 binary `{−1, +1}` + group-wise scaling 兩種極端量化把權重壓到 1.125 到 1.71 有效 bit/weight。M5 Max 上 1-bit 版跑 87 tok/s、Ternary 版 58 tok/s；RTX 5090 上 1-bit 版飆到 163 tok/s、Ternary 134 tok/s。context window 開到 262K token——你的手機可以吞完整份技術白皮書，或整份 Nexus packages/ui 的原始碼加 DESIGN.md 上下文一次讀進來。15 benchmark 平均分數：Qwen 3.6 27B baseline 85.0 → Ternary Bonsai 80.5 → 1-bit Bonsai 76.1，HumanEval+ 上 Ternary 86.0 vs baseline 88.7、1-bit 81.9——1-bit 掉約 11%、Ternary 掉約 5%。Apache 2.0 授權、Hugging Face + GitHub + MLX + CUDA + Locally AI app 都可以拿。

**背後怎麼運作**

這件事的關鍵不是「又一個 27B model」，是三段工程被同時解決：ternary/binary 量化把 27B dense 從 54 GB fp16 壓到 5.9 GB / 3.9 GB，落進手機記憶體；MLX 跟 CUDA 兩條後端同時 ship 讓 Apple Silicon 跟 NVIDIA 都跑得動；262K context 不是虛標，dense 架構本來 KV cache 就吃記憶體，這次是量化把 KV cache 一起壓掉才撐住。HN 上有質疑聲音——`verdverm` 貼出 wikitext perplexity 16.75 vs baseline 8.00（差兩倍以上）指出「他們 4-bit 量得太狠」——所以你選變體時 Ternary 掉 5% 的性價比比 1-bit 掉 11% 好，若手機是 iPhone 17 Pro 才選 1-bit 換記憶體。跟 7/13 Atomic Chat + Google TurboQuant（16GB Mac 跑 Qwen3.5-9B 50K context）比，Bonsai 27B 是往下一步——「9B 跑筆電」升到「27B 跑手機」，量化技術從 KV cache 壓縮進到權重直接壓到 1-bit。

**這改變了什麼**

以前 27B dense 模型你要一台配大顯卡的工作站或 Google 雲端算力才跑得動，走 API 每 token 都付錢——現在同樣尺寸的模型 3.9 GB 塞進 iPhone 17 Pro，一次下載、Apache 2.0 永久免費、所有推理在你手機上、資料不出裝置。以前手機端 AI 你只能玩 3B / 4B 小模型做簡單分類跟摘要——今天起 27B dense + 262K context 讓「手機當你的第二台 dev machine」變真的：搭飛機沒 Wi-Fi 你可以拿整份 codebase 進手機讓 Bonsai 做 refactor 建議，晚上不在電腦前 side project code review 也不用等回家開 M5 Max。Anthropic 說 memory 該是 first-class 資源、OpenAI 說 sub-agent prompt 該加密、Bonsai 說 27B 模型該塞進口袋——三件同一天發生的事情合起來一個訊號：AI 的**部署形態**在往兩極分化，一極是 vendor cloud 上鎖越來越死的 managed 服務，另一極是本地端能跑的模型越來越大越開放。

## 今日總結

四條線今天同時打到「AI agent 執行邊界」的下一個維度——**introspection**：

1. **Claude Code v2.1.210 把昨天 v2.1.208 的 worktree 隔離補完**：subagent 之前還可以走出 worktree 動主 repo git（v2.1.209 之前有洞、v2.1.210 才真關），加上 `ultracode` webhook 誤觸修正、Agent 對抗 subagent 內容 injection 硬化、dataviz palette OKLab 感知色差驗證。這條的訊號是**邊界從可審計 primitive 升到真正關上的 primitive**。

2. **`agent-memory-2026-07-22` beta header 跨 8 家官方 SDK 統一**：memory listing 永遠回穩定順序、`depth` 只接受 0/1/omitted、`path_prefix` 必須尾斜線且比對整段 segment。這條的訊號是**agent memory 從模型隱式記憶升到工程可管理資源**——Rakuten 首次通過率提升 97%、成本降 27% 就是「黑盒翻可管理狀態」的實測差。

3. **OpenAI Codex 開始加密 sub-agent prompt（Sol/Terra = GPT-5.6）**：使用者 client 端只看到密文，debug 路徑被斷。這條的訊號是**兩派 vendor 對 sub-agent 邊界的解法今天正式分裂**——Anthropic 走 visibility + explicit isolation，OpenAI 走 opacity + backend enforcement，Nexus fallback chain 需要加「sub-agent transparency」第六維中立性。

4. **Bonsai 27B（Qwen 3.6 27B base + 1-bit 量化）3.9 GB 塞進 iPhone 17 Pro**：262K context、Apache 2.0、MLX/CUDA 都跑、M5 Max 87 tok/s。這條的訊號是**AI 部署形態往兩極分化**——一極 vendor cloud 越鎖越死（Codex 加密），另一極本地端越開越大（Bonsai 27B 塞手機）。

延續 7/13「default posture 被翻可稽核」→ 7/14「AI agent 執行邊界從 vendor 承諾翻可審計 primitive」→ **今天「introspection 兩極分化：Anthropic 走可見+邊界硬、OpenAI 走不可見+backend 收攏、本地端跳出這條 dichotomy 直接不需要 vendor」**。對 Henry 三條工作脈絡今天可同時動：
