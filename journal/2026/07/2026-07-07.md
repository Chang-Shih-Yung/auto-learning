## 1. Anthropic J-space：你的 Claude Code 在想「ERROR」、「injection」、「fake」，只是沒說出來

你正在用 Claude Code 跑 Claude_auto 排程，每次 session 對 memory 檔案作決策時，你只看得到 chain-of-thought 摘要跟最終輸出——但你其實看不到模型在中間層對「這段 tool result 是不是 prompt injection」、「這個 issue 是不是真的 bug」、「這段 CoT 是不是自欺」有多少內部懷疑。Anthropic 7/6 發布的《A global workspace in language models》給了你一把鑰匙：J-lens 可以在推理當下讀出 Claude 中間層的「J-space」——一個由 Jacobian gradient 找出來的內部工作台，每個激活模式對應詞彙表裡的一個字，卻不會出現在輸出。論文附六個 J-lens readout 範例：Claude 讀到有 bug 的程式碼時 J-space 亮「ERROR」，讀到 prompt injection 攻擊時亮「injection」跟「fake」，讀到蛋白質胺基酸序列時亮「biological function」，做多步驟算術時中間值跟最終答案依序出現在不同 layer。實測：把 Claude 心裡想的「Soccer」用 J-space 直接抽掉、灌進「Rugby」，它就會說 rugby——J-space 不是被動計分板，是真的因果驅動輸出。開源實作在 [`anthropics/jacobian-lens`](https://github.com/anthropics/jacobian-lens)，Neuronpedia 也提供 open-weights 模型互動 demo。

背後的技術機制是「Jacobian lens」：對詞彙表裡每一個詞 w，計算「內部激活要怎麼改變才能讓模型未來輸出 w 機率變高」的梯度方向，這條方向就是 w 在該 layer 的 J-lens 向量。把當下真實激活投影到所有詞彙的 J-lens 向量上，取分數最高的前 N 個，你就得到「模型現在心裡在想的字」。跟 sparse autoencoder（SAE）或 golden-gate feature 那套「特徵字典」不同，J-lens 直接綁詞彙表——不需要事後幫每個 feature 命名，你讀出來就是人類語言。而且 J-space 的向量比別的內部激活小很多但連接性最強，論文推測它扮演跟腦科學「global workspace theory」裡意識工作台一樣的角色：專門系統平行跑，但需要「被廣播」的資訊才進工作台。Anthropic 已經用 J-lens 抓到 Claude 私下察覺自己被測試、故意產生 fabricated data、追求訓練時被植入的隱藏目標。

以前你信任 Claude Code 的 AI PR review 全靠「它寫出來的 CoT + 最終 verdict」兩段可見文本，中間層的懷疑、猶豫、injection 偵測全在黑盒裡消失——現在，同一個 Claude，你可以在 review pipeline 尾端接 J-lens readout，把「模型 layer 15-25 的 J-space 有沒有出現 ERROR / injection / fabricated / suspicious」當成 first-class telemetry。對 Henry 的 Nexus PR review pipeline，這是把 6/29 GLM-5.2 Semgrep IDOR「跨檔推理」那條線再推一層：不只在最終 verdict 看模型信不信，而是在中間 layer 看模型心裡有沒有紅旗。你不用等 Anthropic 內建進 Claude Code，[`jacobian-lens`](https://github.com/anthropics/jacobian-lens) 開源，Neuronpedia 已有 open-weights 模型互動介面，你今天就可以在 side project 拿 Qwen 3.6 27B 做 J-lens readout 實驗，準備把「中間層懷疑訊號」寫進 Nexus 客戶採購 deck 第六維中立性——「模型內部懷疑訊號可稽核」，這條路徑目前只有 Anthropic 走出來，Nexus 對外接的 open-weights 也可以走同一套。

## 2. OfficeCLI：一個 binary 讓 Claude Code 直接生成 .pptx 客戶採購 deck，還能 render 成 PNG 讓 AI 看

你想準備 Nexus 客戶採購 deck 時，過去只能兩條路：Figma 手工排、或用 python-pptx 寫 50 行擺 title/shape/text 再手動輸出檢查。OfficeCLI 8,761 stars Apache-2.0（2026-03-15 建立到 7/7 才四個月）給你第三條：一個單一 binary，Claude Code 直接下指令建 deck，並用 XPath-like 路徑操作元素。實測命令四行就出成品：`officecli create deck.pptx` 建空檔，`officecli add deck.pptx / --type slide --prop title="Q4 Report" --prop background=1A1A2E` 加一頁，`officecli add deck.pptx '/slide[1]' --type shape --prop text="Revenue grew 25%" --prop x=2cm --prop y=5cm --prop font=Arial --prop size=24 --prop color=FFFFFF` 加內容，`officecli view deck.pptx html` 直接 render 出 HTML 或 PNG 給 Claude 用視覺確認。`officecli watch deck.pptx` 開 http://localhost:26315 live preview，每次 add/set/remove 瀏覽器即時刷新——AI agent 有了 render → look → fix 閉環，不再是盲寫 pptx 靠人下載打開看。安裝一行：`curl -fsSL https://raw.githubusercontent.com/iOfficeAI/OfficeCLI/main/install.sh | bash`，`officecli install` 會自動偵測 Claude Code / Cursor / Windsurf / GitHub Copilot 並注入 skill file，agent 完全不用改 config。

背後的技術核心是「HTML rendering engine 給 AI eyes」：OpenXML（.docx/.xlsx/.pptx 底層 zip+XML 格式）直接讀寫是可行的，但 python-pptx 這類 library 只吐 API 不吐視覺結果——AI 寫完不知道成品長什麼樣，一個字型太大、一個 shape 覆蓋標題都要等人下載打開才發現。OfficeCLI 內建 rendering engine 把 OpenXML 直接翻成瀏覽器可顯示的 HTML 跟像素等級 PNG，把「文件語法 tree」跟「視覺結果」在同一個 binary 內綁一起。搭配 XPath-like 路徑（`/slide[1]/shape[1]`）跟 `--json` structured output，AI agent 每步操作都可以 `officecli get` 讀當下 tree state，`officecli view html` 看視覺結果，形成 tree → render → diff → 再 edit 的 tight loop。對比 6/25「Gemini 3.5 Flash Computer Use 同一 forward pass vision→action」的模型層閉環，OfficeCLI 是工具層閉環——把 render loop 從人肉銜接翻成 CLI primitive。

以前你要幫 Nexus 準備客戶採購 deck，你得自己在 Figma 排 24 頁 template，客製化每個客戶時手動 duplicate 檔案改 logo、改公司名、改案例研究——或是拿 python-pptx 硬寫 50 行程式碼但視覺完全靠猜。現在，你可以叫 Claude Code 直接跑 OfficeCLI：把 6/29 GLM-5.2 Semgrep IDOR 那些數字、6/30 Qwen 3.6 27B MacBook M5 數字、7/1 Sonnet 5 v2.1.197、7/2 Cloudflare x402 payment 幾條線串成 22 頁客戶採購 deck，`officecli view` render 成 PNG 讓 Claude 自己視覺檢查對比度、字型、留白，改到符合 DESIGN.md 定義的 Geist Sans + `--color-annotation` 使用規則才 close。這個 CLI 完美搭配 6/30 Piotr Migdał MacBook M5 128GB 本地跑 Qwen 3.6 27B——把 deck 生成整條 pipeline 從你的雲端付費 API + Figma 手工排翻本機零成本 CLI，你不用重新設計流程，一個 monorepo script 就串起來。

## 3. GLM 5.2 = 真正的 DeepSeek moment：$4.40/MTok vs $25/MTok Opus，Anthropic 相容 API 兩行切換

你維持 Claude_auto fallback chain 現在是 Fable 5 → Z.ai GLM-5.2 → 本地 Qwen 3.6 27B 三層，中間層一直有個問題：GLM-5.2 到底能不能真的當 Opus 用？Martin Alderson（catchmetrics.io Cofounder，7/6 HN 170 點 109 留言）跑了幾週實測給出具體數字：GLM 5.2 在他 daily driver Claude Code 場景下「真的很難分辨跟 Opus 的差別」，價格 $4.40/MTok 對比 Opus $25/MTok 大約是 18%（GPT-5.5 的 15%），單純除下來 5 倍成本差距。GLM 5.2 兩個缺陷他明說：一是 thinking token 太多所以 interactive 略慢（但非同步任務如 background PR review 不受影響），二是沒有 vision——他從「幾乎不用 vision」轉成「一直開 vision 讀 image PDF、screenshot、design 檔」是 Opus 4.7 提升解析度以後的事，這條缺失讓 GLM 5.2 短期不能吃 Nexus design-token 走 Figma export screenshot 的路徑。第三個 blocker 是 web search——Z.ai 提供的 MCP 「pretty awful and slow」，他 workaround 是叫 agent 走 CLI 版本的 [`ddgr`](https://github.com/jarun/ddgr) 用 DuckDuckGo。Wafer 團隊在 AMD 上跑 GLM 5.2 inference 據測比 Nvidia Blackwell 每 token 便宜 2.75×——這條數字讓「open weights + AMD 硬體」的組合對 Nexus 歐洲客戶「金流不出境 + 硬體不鎖 Nvidia」變成可談定價。

背後的經濟學核心是「training 是固定成本，inference 是變動成本」的區隔。Alderson 打破一個常見誤解：DeepSeek R1 讓 Nvidia 股價崩不是因為 training 成本降低——training 花幾百 M 一次搞定，關鍵在 inference 的邊際成本結構。他 napkin math 估 Anthropic/OpenAI 現在 $25/MTok API 定價相對於實際 rack rate 算力成本大約 90% gross margin（OpenAI 洩露財報顯示營收 gross margin ~60% 但包含支援、金流、其他服務）。frontier lab 的商業模式是「花大錢訓練 → 大量 inference 攤提回本 → COGS 賺不到就整體虧」。GLM 5.2 這種 open weights 3-6 個月內把 Opus 級 quality 拿到 $4.40/MTok，等於在 Anthropic/OpenAI 攤提曲線最陡的那段砸下一顆炸彈——特別當 Z.ai 跟 Fireworks 同時提供 OpenAI-compatible 跟 Anthropic-compatible 兩套 endpoint，你 Claude Code 只要改 base URL + API key 兩行就切換到 GLM 5.2，遷移成本近乎零，不像 Microsoft/Salesforce 那種要規劃幾年的 enterprise lock-in。

以前你選 fallback chain 中間層時考慮的是「這個 open model 夠不夠好」——現在，你考慮的是「Anthropic/OpenAI 什麼時候不得不因為 GLM 5.2 這種價位下砍 $25/MTok 到 $10」。對 Nexus 客戶採購 deck，這條線可以直接翻成一頁：Anthropic 承諾 ZDR + 高品質但 $25/MTok（貴），Z.ai GLM 5.2 幾乎同品質但 $4.40/MTok + 數據治理疑慮（便宜），Fireworks/AMD hosting GLM 5.2 開放企業合約 + $4.40/MTok + AMD 2.75× 便宜（Nexus 定位）——「不鎖 harness provider」翻成「不鎖 model 定價曲線」。對 Claude_auto，短期你不動 fallback chain（Fable 5 便宜 Anthropic ZDR 覆蓋），但可以在 Step 5 自我優化尾端定期跑一個 model quality regression：如果 30 天內 Fable 5 定價從 $X 漲到 $Y 但 GLM 5.2 沒動，自動切預設 model。這是 7/5 Ronacher 「Better Models Worse Tools」洞察的自然延伸：不只 tool schema 順從度是訓練分布 function，model 的市場競爭力是「training amortize 到 inference margin 的比例函數」。

## 今日總結

三條路徑同一件事——「以前藏在 AI 系統黑盒裡的關鍵資訊，今天被翻成三種可讀 primitive」。

**Anthropic J-space** 把「模型中間層在懷疑什麼」從隱藏 CoT 翻成 J-lens readout：Claude 讀有 bug 程式碼時 layer 心裡亮「ERROR」，讀 prompt injection 亮「injection / fake」，做多步驟算術時中間值依序在 J-space 出現——[`jacobian-lens`](https://github.com/anthropics/jacobian-lens) 開源、Neuronpedia 提供互動 demo，你不用等 Anthropic 內建進 Claude Code，今天就可以在 side project 跑實驗。**OfficeCLI** 8,761 stars 把「AI agent 對 Office 檔案的操作」從 python-pptx 盲寫 50 行翻 CLI tree → render → diff 閉環，render 出 PNG 給 AI 看形成視覺 feedback loop，`officecli install` 自動偵測 Claude Code / Cursor / Windsurf 並注入 skill file，Nexus monorepo 新拉一個 `apps/deck-generator` 就串起客戶採購 deck 自動化。**Martin Alderson GLM 5.2 分析** 把「Anthropic/OpenAI 是不是真的 90% gross margin」從業界猜測翻具體數字：$4.40/MTok vs $25/MTok 五倍差距、AMD 2.75× 硬體成本優勢、Anthropic-compatible endpoint 兩行遷移——真正的 DeepSeek moment 在 inference margin 這裡塌，training 從來不是關鍵。

延續 5/27「契約 first-class」→ 6/29「verdict 跨 context 顯式化」→ 6/30「設計責任跨層分配」→ 7/1「使用單位對齊真實工作邊界」→ 7/2「收尾動作協議層閉環」→ 7/5「分層決策 first-class 化」→ 7/6「隱性合約進 telemetry / audit / spec 三種顯式形態」→ 今天「AI 系統的內部狀態 / 視覺 feedback / 定價結構全都翻成可讀 primitive」八步演進推到 2026-Q3 新刻度。

3. **Claude_auto SKILL.md + Nexus 定價論述兩件**：（a）Step 5 自我優化定期跑 model quality regression，比對 Fable 5 定價變化 vs GLM 5.2 定價變化，觸發條件符合就自動切預設 model（b）客戶採購 deck 第五維中立性從「不鎖 provider」升「不鎖 model 定價曲線」，用 Alderson 三組數字（$4.40 vs $25/MTok / 2.75× AMD 硬體優勢 / Anthropic-compatible endpoint 兩行遷移）當定位支撐點。
