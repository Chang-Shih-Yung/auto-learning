# 2026-07-17 學習日誌

今天五條線同時打向同一件事——**AI agent 的「autonomy」正在被業界集體重新校準**：Claude Code v2.1.212 給 subagent spawn 跟 WebSearch 都加了硬上限，Kimi K3 把「開源前沿模型」規模拉到 2.8T 級別但同時全部走 MXFP4 量化訓練，Salesforce 承認過去 Agentforce 太信 LLM 現在退回 deterministic automation，Pydantic 用一整篇文章講「human-in-the-loop is tired」，LM Studio 推出獨立的 Bionic app 專門跑開源模型 agent。從 vendor 硬邊界、開源硬體實用化、企業客戶認錯、supervision 疲勞、本地推理路線——同一天五個角度都在說：pure LLM autonomy 這條敘事到頂了。

## Claude Code v2.1.211 + v2.1.212——subagent spawn 上限 200、WebSearch 上限 200、`/fork` 從 in-session 拆成獨立 background session

**你能做什麼**

如果你昨天照著 v2.1.210 的建議把 Claude_auto 排程升上來，今天再升一次——因為 v2.1.212（2026-07-17 UTC）加了三件對「跑得久的 agent」直接相關的硬邊界：**session 期間 WebSearch 呼叫預設上限 200 次**（防 runaway search loop）、**單一 session 產生的 subagent 預設上限 200 個**（防 delegation 無限遞迴）、**MCP tool 呼叫超過 2 分鐘自動搬到背景**（不再卡住主 session）。同版本還修了一個很嚴重的 bug——**plan mode 之前會直接執行會改檔案的 Bash 命令而不出 permission prompt**（等於 plan mode 的「只計畫不動」承諾破功），這版關上了。`/fork` 命令重新設計：以前是 in-session subagent，現在是「把你當前對話複製一份到新的 background session」，讓你原 session 繼續跑；原本 in-session 用法改名叫 `/subtask`。Windows 上 `/background` 跟 `claude --bg` 之前在 Group Policy 擋 PowerShell 5.1 時整條掛掉，這版 daemon 會優先選 PowerShell 7。

還有 v2.1.211（2026-07-15）三件事跟你相關：**`--forward-subagent-text` flag 加 `CLAUDE_CODE_FORWARD_SUBAGENT_TEXT` env var** 把 subagent 的文字跟 thinking 打進 stream-json 輸出，方便你稽核 subagent 到底在想什麼；**permission preview 轉發到 chat channel 時會 neutralize bidirectional-override / zero-width / 相似字元 quote**（防 Unicode 混淆攻擊）；**Auto mode 遇 PreToolUse hook 回 ask 決策不再被 Auto mode 蓋掉**——hook 說 ask 就 ask，Auto mode 沒權覆寫。

**背後怎麼運作**

這兩版一起看，Claude Code 這 48 小時做了一件很清晰的事：**把 agent 的「autonomy 表面積」從無邊界翻成 quota-gated**。過去 subagent 可以無限 spawn subagent（潛在無限遞迴）、WebSearch 可以連呼叫上百次（燒 token 且往往是 hallucinated loop）、MCP tool 卡 2 分鐘會拖死主 session、plan mode 只是「模型自律」（模型答應不動檔但 Bash 命令實際會執行）——這些都是「相信 agent 自己會收斂」的隱式契約。v2.1.212 把這四條路徑一次改成「vendor 幫你 enforce 硬邊界」：subagent 上限、WebSearch 上限、MCP 逾時搬背景、plan mode 真的攔 Bash。`--forward-subagent-text` 是同一條哲學的另一面——當 subagent 邊界被 vendor 硬控住，你需要顯式看得見它裡面在想什麼，才能反推「這個上限應該調多少」。

**這改變了什麼**

以前 Claude Code 的 agent autonomy 敘事是「盡量放，vendor 相信 agent 會自律」，這一版翻成「vendor 給你預設 quota，你要放寬得顯式改 setting」——subagent 200 / WebSearch 200 / MCP 2 分鐘背景化四個門檻，直接對應四種過去只能靠 CLAUDE.md prompt 說「請節制」但根本擋不住的失敗模式。以前 plan mode 你信「模型不會亂執行」，實際上會——現在 plan mode 是真的攔在 Bash 執行之前。以前你把 Claude_auto 排程跑成 24 小時無人值守，最怕就是 subagent 遞迴爆炸把 API 額度燒完，這版預設 200 個 subagent 就是自帶保險絲；以前 permission preview 傳到 Slack 或 mobile push 可以被 Unicode 混淆騙過去（U+202E right-to-left override 之類），這版 preview 送出前自動 neutralize。搭 7/15 v2.1.210「subagent worktree 邊界真正關上 + Agent 對抗 injection 硬化」→ 今天 v2.1.211/212「autonomy 表面積 quota 化 + subagent thinking 顯式化 + Unicode 混淆神經化」，Claude Code 這一週把「長時運行 agent 的信任邊界」從「相信 agent 收斂」全面翻成「vendor enforce + 讓你看得見」。

## Kimi K3——2.8T 參數、16/896 experts active、1M context、MXFP4 量化訓練，7/27 全權重開源，「世界第一個開源 3T 級模型」

**你能做什麼**

7/27 之後你可以下載 Kimi K3 的完整權重跑本地推理，這是目前開源界規模最大的模型——2.8T 總參數、但走 Stable LatentMoE 只 activate 16/896 experts，實際推理成本大約等同一個 50B dense 模型；context window 1M token 原生（跟 Claude Sonnet 5 同級）、內建 vision；DeepSWE 67.5、Terminal Bench 2.1 88.3、GPQA-Diamond 93.5、MathVision 94.3、CharXiv 84.8。API 已經上：cache-hit input $0.30/M tokens、cache-miss input $3.00/M tokens、output $15.00/M tokens——比 Claude Opus 4.8（$5/$25）便宜 5 倍。Moonshot 官方表明「integrated quantization-aware training (QAT) using MXFP4 weights and MXFP8 activations」——訓練時就用低精度，不是 post-training 量化，所以硬體需求跟同尺寸 FP16 模型比大幅下降。

**背後怎麼運作**

過去開源模型走過幾波方向：DeepSeek V4 拉 MoE、Qwen 拉多模態、Llama 拉小型化、Bonsai/Gemma 拉手機端。Kimi K3 選了不同路線——**訓練階段就走 MXFP4 量化，讓 2.8T 級別的模型能被商用機房甚至 workstation 級硬體實際跑起來**。Kimi Delta Attention（KDA）是他們自研的 attention 變體，配 Attention Residuals（AttnRes）——選擇性地跨層 retrieve representation，讓 1M context 不是 sliding window 或 sparse attention 折衷，而是真的 attention span。Stable LatentMoE 的 Quantile Balancing + Per-Head Muon optimization 解決過去 MoE 訓練不穩的老問題——每個 expert 的活躍度靠 quantile-based routing 拉平衡，避免某幾個 expert 被過度使用。2.5× scaling efficiency 對比 K2 意思是「同樣的計算預算，K3 能訓到 2.5 倍的有效參數」——這條 scaling law 的斜率變陡，代表未來開源模型的「規模天花板」還會被推更高。

**這改變了什麼**

以前開源模型「規模」跟「可跑」是二選一——Llama 3 405B 開源但你根本跑不動、Mistral Large 你要一整台 8xH100、Bonsai/Gemma 你手機跑但只有 12B。Kimi K3 打破這條 tradeoff：**規模 2.8T（開源史上最大）+ 訓練用 MXFP4（記憶體需求砍到 1/4）+ 只 16/896 active（推理計算量剩 1.8%）= 3T 級別的能力跟商用機房級的硬體需求首次同時成立**。定價 $0.30/$3/$15 直接把 Anthropic 定價腰斬（Sonnet 5 標價 $2/$10、Opus 4.8 標價 $5/$25），且是可下載權重跑本地，等於「你要付錢或自己搭都可以」。對比 Claude Fable 5 跟 GPT-5.6 Sol 官方描述「trails on overall capability but consistently outperforming other tested models」——Moonshot 沒過度宣稱是 SOTA，但把「可執行 3T 級模型」的門檻從 API-only 拉到 open weights。這條 open weights 路線今天跟 vendor cloud 路線（Claude Code v2.1.212 vendor 收斂）在同一天出手——「vendor cloud 越收越緊 vs. open weights 越開越大」，兩派分裂在 2026-Q3 已經是明面上的產業結構，不再是趨勢預測。

## Salesforce Agentforce 退回 deterministic automation——大企業客戶第一次公開承認 LLM 分工邊界被錯估

**你能做什麼**

如果你在做企業 AI 導入的採購決策或架構決策，今天有一個直接可引用的公開資料點：Salesforce 官方承認過去對 Agentforce 這條 LLM-driven 客服 agent 路線**「we were more confident than warranted」**（比實際該有的信心更高），Support 團隊從 9,000 人砍到 5,000 人以後，剩下的部分現在**改回 deterministic automation**——rule-based、data-driven、可解釋、可預測的決策路徑，而不是靠 LLM 自己判斷。CEO Marc Benioff 講的原話是他們需要「strong data foundations to support AI-driven decisions」——白話翻譯：LLM 直接吃 unstructured 資料回覆客戶那條路走不通，得先把資料結構化才餵給 AI，且 AI 的角色從「決策者」降級為「推薦者」。同步的財務數字：Agentforce 年營收目標 $500M（比公司整體規模小得可以）、股價從 2024-12 高點跌 34%、$300M 重組費用。

**背後怎麼運作**

Salesforce 這條退路走得不是因為 LLM 能力不夠——Claude Fable 5 跟 GPT-5.6 Sol 都能在客服對話上表現不錯——**而是因為「LLM 判斷 + 後端執行」這條完整鏈路在企業客服場景失敗率無法降到可接受**。客服場景的失敗模式特殊：一個錯誤退款、一個誤刪工單、一個把客戶掛到錯的 workflow，都是 hard failure（實際傷害客戶）而不是 soft failure（重試就好）。LLM 在這種場景的固有問題不是幻覺率有多高——是幻覺率不會歸零、且每次幻覺的 blast radius 是「整個客戶關係」。Salesforce 的解法回到 Atlas reasoning engine——**LLM 只用來理解意圖跟摘要 context，決策路徑走 deterministic rule engine**，routine inquiries 走 rule、複雜案例才 escalate 到人。這條路線幾乎完全對應 antirez 5/14「Control Ideas Not Code」的架構主張——LLM 產出 code，人審 DESIGN.md，但 Salesforce 更激進：**LLM 不做決策，只做理解跟推薦**。

**這改變了什麼**

以前企業客戶採購 AI 的敘事是「LLM 越強越好，我們 build 一個 agent 讓它做完整流程」——Salesforce 這條路走到 4,000 人裁員 + 34% 股價跌，官方公開認錯的公信力是「這條路業界第一個大企業級失敗案例被說出來」。今天起企業採購 AI 的敘事會變成兩層架構：**理解層走 LLM（越強越好、可換 vendor）+ 決策層走 deterministic pipeline（rule engine / workflow / audit trail）**——決策不能給 LLM 一定要在 deterministic 層被卡住。對建 AI 產品的人的意義：以前你賣「AI 直接解決客戶問題」，現在你賣「AI 幫人解決客戶問題 + audit trail + rollback」——後者是 Salesforce 這條退路走完之後，企業採購委員會的預設問題。這條動作跟 Claude Code v2.1.212 給 subagent / WebSearch 加 quota 是同一個方向——**vendor 側跟 customer 側今天同一天承認 LLM 不能 unbounded autonomy，得加顯式邊界**。

## Pydantic「Human-in-the-loop is tired」——supervision 疲勞是 LLM autonomy 的第二個天花板

**你能做什麼**

如果你這 6 個月用 Claude Code / Cursor / Copilot 越用越覺得「產出多但 review 累」，Pydantic 這篇文章給了你這個感覺的名字：**human reward function problem**。LLM-assisted programming 自動化掉的正好是工程師覺得滿足的部分（寫程式、解問題、compile 成功那一刻）——留給你的是原本就不喜歡但強度變大的部分（監督、review、抓 LLM 幻覺）。作者的原話「the satisfying part shrank. The exhausting part grew. And there are no new rewards to fill the gap.」——滿足感縮水、疲勞感放大、沒有新的回報填補這個 gap。同事 Douwe 一早進辦公室有 30 個 PR 等他 review，「to delegate review to AI itself」的誘惑很大但危險。文章給兩個具體技術對策：**pre-mortem on complex plans**（用另一個 fresh LLM session 假設任務失敗、反推 spec gap），跟**engineering judgment distillation**（把幾千條 code review comment 抽成規則寫進 `AGENTS.md` 給 LLM 當前置指令）。

**背後怎麼運作**

作者的核心洞察是 LLM 產出的錯誤類型很特別——不是「不會做」而是「以為在做但做錯」（errors of coherence）——**發明不存在的 component、讀錯 spec、把兩個 requirement 混起來**。這種錯誤不能靠 LLM 自我檢測（同一個模型不會發現自己的 coherence 錯誤），也不能靠 test suite 100% 覆蓋（因為 spec 本身就有 gap），最後 fallback 到「人類 review」是唯一 catch 這類錯誤的路徑。問題是「人類 review」原本就是產出的 20% 精力，現在因為 LLM 產出量翻倍變成 60%——同樣 8 小時工作、比較多的 review 比較少的實作，工程師的自我認知從「builder」翻成「supervisor」，reward function 崩盤。作者的 pre-mortem 對策不是解決疲勞而是重新分配——用另一個 fresh LLM 提前 catch spec gap，把「人 review LLM 產出」的一部分工作前移成「人審 LLM 找出的 spec gap」（後者是設計工作，前者是校對工作，工程師心理成本天差地遠）。AGENTS.md 這條路是同一條哲學的另一面——**把「工程師的判斷 pattern」變成 machine-readable 前置指令**，讓 LLM 產出時就少犯 coherence 錯誤，review 階段的心理負擔下降。

**這改變了什麼**

以前討論「AI 會不會取代工程師」的敘事都在講「AI 能不能寫出正確的程式碼」——今天 Pydantic 這篇把問題翻成完全不同的層：**AI 寫出正確的程式碼跟工程師的工作滿足感不對齊**。「AI 產出 + 人 review」這條分工不永續不是因為技術不夠，是因為人的 reward function 承受不住。以前 human-in-the-loop 是「AI 系統的必要安全網」，現在起 human-in-the-loop 是「AI 系統的耗損資源」——會枯竭、會 burnout、會 delegate 給 AI 自己（退回 rubber-stamp）。這條洞察搭 Salesforce Agentforce 退路一起看方向清晰：**LLM autonomy 的天花板不是能力也不是幻覺率，而是「監督成本無法 scale」**——Salesforce 是企業側承認、Pydantic 是工程師側承認、Claude Code v2.1.212 是 vendor 側承認，三個層次同一天同一件事。對 Nexus 這種 AI 輔助設計工具的產品定位有直接影響：**產品價值不在「產出多」而在「產出時已經降低了 review 負擔」**——AGENTS.md、DESIGN.md 前置指令、pre-mortem 這些機制不是額外功能，是產品的核心體驗設計。

## LM Studio Bionic——把「跑 open weights 模型」跟「用 AI agent 做事」拆成兩個獨立 app

**你能做什麼**

如果你桌機或筆電上已經有 LM Studio 跑 GLM 5.2 或 Kimi 這類開源模型，7/16 開始你可以下載 **LM Studio Bionic**——這是**跟原本 LM Studio 平行的獨立 app**，專門作為 AI agent 做 coding、research、文件處理的 harness。功能面：codebase inspection、code explanation、debugging、處理 PDF/PPT/Excel 文件、內建 Voxtral（Mistral AI 的語音模型）做本地 voice input transcription。運算來源可選三種：**本地模型**（跑你自己 LM Studio 那邊的權重）、**LM Link 連線**（連你另一台機器）、或**雲端推理**。對隱私敏感的使用者官方明講：「For all LM Studio Bionic users, we commit to Zero Data Retention and never training on your data」，雲端請求 processed transiently、request 結束不留。目前公告支援 GLM 5.2、Kimi K2.7 Code、Voxtral 三個模型。

**背後怎麼運作**

LM Studio 過去定位是「open weights 模型的 desktop runtime」——你下載模型、跑 chat、透過 OpenAI-compatible API 讓其他 app 呼叫。Bionic 這個獨立 app 走的路線很清楚：**不是把 agent 功能塞進原本 LM Studio 讓它變雜——是拆成兩個 app 各專注一件事**。原本 LM Studio 繼續作為 model runtime，Bionic 作為 agent 消費層。這條分工模式跟 7/2 ZCode（Z.ai 為 GLM 家族做的官方 harness）走同一條路——**open weights + 官方 harness 二元組合成為 vendor 標配**——但 LM Studio 這條更中立：Bionic 不綁單一模型家族，你可以掛 GLM、掛 Kimi、掛 Mistral，甚至混雲端跟本地。Voxtral 內建語音轉錄的意思是**輸入層的隱私邊界也移到本地**——不用送 OpenAI Whisper API，語音直接在你機器上轉文字，agent 只吃文字。ZDR 承諾配上 transient processing 是明確對標 7/13 xAI Grok Build CLI 上傳 5.10 GiB 事件——LM Studio 用「拆分獨立 app + 明確不留資料 + 本地優先」三件事把「AI harness telemetry」這個結構性風險從默契翻成合約級別的產品承諾。

**這改變了什麼**

以前跑本地開源模型跟用 AI agent 是同一個裝置的兩個模式，但通常你會用 Claude Code / Cursor 這種綁 Anthropic/OpenAI API 的 harness——因為 harness 這層過去只有這幾家有能力做。今天起 LM Studio Bionic 這條路把「open weights model runtime」跟「AI agent harness」拆成兩個獨立可組合的 layer——你可以用 GLM 5.2 跑 Bionic、用 Kimi K3 跑 Bionic（等 7/27 權重出來）、用本地 fine-tune 跑 Bionic。這條分工重要在**「harness vendor 跟 model vendor 解耦」在桌面級首次落地**——過去 harness 內建預設 model（Claude Code 綁 Anthropic）、model runtime 沒有原生 agent 能力（LM Studio 過去只是 chat + API server）、二者中間靠 OpenAI-compatible API 半勉強對接。Bionic 這條 vertical 是「跟你已經在跑的 LM Studio 綁定但獨立 process」讓桌面級 open weights 使用者第一次拿到跟 Claude Code 對等的 agent 體驗，而不需要送資料到 Anthropic 雲端。這條動作跟 Kimi K3 開源、Claude Code vendor 收斂、Salesforce 退回 deterministic、Pydantic 講 supervision 疲勞——今天五條線裡最直接針對「歐洲 GDPR / 日韓資料主權 / 醫療合規客戶」的解法，因為它是唯一「執行層完全不出裝置」的 AI agent 選項。

## 今日總結

**核心洞察：AI agent autonomy 這條敘事到頂了——五個獨立角度同一天同一件事。**

- **vendor 側（Claude Code v2.1.212）**：subagent spawn 加 200 上限、WebSearch 加 200 上限、MCP 2 分鐘自動背景化、plan mode 真的攔 Bash——vendor 自己給 agent 加硬邊界，承認「相信 agent 自律」這條路走不通
- **open weights 側（Kimi K3）**：2.8T MoE 開源、MXFP4 量化訓練、$0.30/$3/$15 定價腰斬 Anthropic——vendor cloud 越收越緊，open weights 越開越大，兩派分裂已是明面上產業結構
- **企業客戶側（Salesforce Agentforce）**：9000→5000 支援團隊裁員後承認 LLM overconfident、退回 deterministic automation、CEO 講「strong data foundations to support AI-driven decisions」——大企業第一個公開承認「LLM 分工邊界被錯估」的案例
- **工程師側（Pydantic）**：human reward function problem、supervision 疲勞、pre-mortem + AGENTS.md distillation 對策——「AI 產出多但 review 累」有名字了，且被論證為結構性不永續
- **本地端側（LM Studio Bionic）**：harness 跟 model runtime 拆兩個 app、ZDR 承諾、Voxtral 本地語音——桌面級「執行層完全不出裝置」的 agent 選項首次落地
