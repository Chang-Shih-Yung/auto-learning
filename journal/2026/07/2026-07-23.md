# 2026-07-23 學習日誌

## Next.js 16.2.11：一次公佈 10 條 CVE，App Router + Server Actions 表面被全面補丁

如果你的 Next.js 專案跑在 Vercel、用 App Router + Server Actions（Claude_auto 就是這個組合），你應該在今天升級到 16.2.11。這一版一次公佈 10 條安全建議，其中 5 條 High severity：Server Actions on custom servers 的 SSRF、rewrites 用攻擊者可控 hostname 的 SSRF、App Router + Server Actions 的 DoS、App Router + Turbopack 單一 locale 設定下的 middleware bypass，還有 5 月的 segment-prefetch middleware bypass 後續補強。另外 5 條 Moderate 涵蓋 Edge runtime 未限制的 Server Action payload、request body 帶 invalid UTF-8 導致的 cache confusion、Image Optimization API 處理 SVG 的 DoS、內部 Server Function endpoint 未認證外洩。

這批 CVE 的共同點是：攻擊面全落在「App Router 引入之後新增的 primitive」。SSRF 兩條都出在 Vercel 為了讓 App Router 更靈活提供的動態能力——rewrites 可以指到 remote host，Server Actions 可以在 custom server 上直接接觸 outbound request。DoS 兩條在 Server Actions 的資源限制沒設 hard cap（Edge runtime 的 payload 沒 bound、SVG parser 沒有 memory limit）。Cache confusion 兩條在 App Router 的 fetch cache 沒把 request body 納入 cache key，導致同一 URL 不同 body 打到同一份 cache。Middleware bypass 兩條在 Turbopack 的路由計算與 segment prefetch 對 middleware 執行順序判斷不一致。

以前你用 Pages Router 只有 API Routes + getServerSideProps，攻擊面小、行為可預測；現在 App Router 把 Server Actions、Server Components、Streaming、Turbopack、middleware、Image Optimization 全推到 default，攻擊面翻好幾倍，Vercel 一次補 10 條就是這條技術債的直接反映。對 Claude_auto 這種每天自動 build + deploy 的專案，最小成本的動作是：把 `next` 依賴 pin 到 `^16.2.11`、Vercel Dashboard 檢查有沒有用 custom server（沒有就少擔心兩條 SSRF）、確認 `next/image` 有把 SVG 排除或限制檔案大小。

## Claude Code 一週連發四版（v2.1.215 → v2.1.218）：subagent 收斂 + `/code-review` 翻背景執行

如果你是每天讓 Claude Code 自動跑排程（Claude_auto 就是這樣），你這週會被三件事直接打到：v2.1.216 加了 `sandbox.filesystem.disabled` 讓你能保留 network egress 控制但關掉檔案系統隔離、修好長 session 裡 message normalization 成本 quadratic 增長的慢速問題、修好 auto mode 遇到 OAuth token 過期時把命令誤判成「HTTP 401」拒絕的 bug；v2.1.217 加 subagent concurrency cap default 20、預設關掉 nested subagent（要 nest 得顯式打開）、修好 truncated MCP tool output 保留全文導致的 memory leak；v2.1.218 把 `/code-review` 翻背景 subagent 執行、修好 Windows 路徑帶 `\u` 前綴段被誤轉 CJK 字元、修好 `/ultrareview` 接 descriptive 參數（例如 "review my auth changes"）會 fail 的 bug。

這四版連在一起看，Anthropic 在做兩件事。第一件是「subagent 從默默 fan-out 翻顯式資源管制」——過去 subagent 可以無限 nest、無限併發，這週 concurrency cap 20 + nested 預設 off 是明確承認過去 subagent 成本失控。第二件是「slash command 從主線程執行翻背景執行」——`/code-review` 過去會把 review 對話塞回主 conversation 佔 context，v2.1.218 起 review 走 background subagent，主線程不受污染。連著 7/19 v2.1.215「skill 從 model auto-invoke 翻使用者顯式呼叫」，一路是同一條方向：agent 資源使用從隱式判斷翻顯式管制。

以前你寫 SKILL.md 只要標 `requiredMinimumVersion` 就完事，subagent 開幾條、要不要 nest、`/code-review` 佔多少 context 都靠 Claude 自己判斷；現在起你要顯式決定「這步驟要不要開 subagent、要不要允許 nested、review 要不要跑背景」，SKILL.md 從「宣告需求」翻「配置資源」。對 Claude_auto 排程，最小成本的三件事：把 `requiredMinimumVersion` 升到 2.1.218、SKILL.md 補一段「本 skill 不使用 nested subagent，若未來需要請顯式打開」、Step 4 lint 邏輯若未來要背景化直接用 `/code-review` background 模式而不是自己 spawn subagent。

## Bento：把整個 slide editor + viewer + 資料 + 協作 塞進 560KB 一份 HTML

你在瀏覽器打開 `bento.page/slides` 那瞬間，你已經下載完整套 PowerPoint 替代品——編輯器、演示器、動畫引擎、圖表函式庫、儲存邏輯、加密協作，全部在一個 560KB 的 HTML 檔裡。你能離線編輯、你能 email 送檔給對方而對方不用裝任何 app，你能 Ctrl+S 讓這個 HTML 把自己改寫成含你新內容的新版本。20 小時內 HN 875 讚，重點不是「單檔案」這個 gimmick，重點是它拿真實生產級的網頁技術（reveal.js、GSAP、ECharts、File System Access API、Cloudflare Durable Objects）疊出了一個能取代 Google Slides 的完整產品。

技術面它做了三件事：頂部一塊 JSON data block 存 slide 內容讓 grep 或 AI harness 直接讀寫、主體是 base64 編碼壓縮過的整個 app 用瀏覽器原生 DecompressionStream API 解壓、儲存靠 File System Access API 加 ECDSA 簽章防篡改。協作端用 Cloudflare Durable Objects 當中繼但 relay 對內容加密所以 Cloudflare 看不到 payload。有意思的是作者原本用 ECharts，但因為 bundle size 跟效能問題自己 fork 重寫了一版——這個決策直接對應你 Nexus 元件庫也在用 ECharts 該考慮的相同 tradeoff。

以前一份簡報要不就寄 pptx 讓對方裝 Office、要不就 Google Slides 連結但對方要有 Google 帳號、要不就 PDF 但失去互動；現在你 email 一份 560KB 的 .html 檔對方雙擊瀏覽器就能看能編能存能重寄。這條「web app 反過來走單檔案 distribution」路線對你 Nexus 有一個直接的問法：Nexus 元件庫能不能出「單一 HTML demo 檔」給採購 IT——不用讓對方裝 npm 不用連你的 CDN，收到附件就能看能點能改，這條 distribution channel 對 Fortune 500 內部審查流程差異巨大。

## Cactus Hybrid：教小型端上模型「知道自己什麼時候答錯」

Cactus 團隊給 Gemma 4 E2B 加了一層 probe——當模型輸出一個答案，probe 讀 hidden state 給 0 到 1 的 confidence 分數，你的 app 根據 confidence 決定要不要 handoff 到更大的雲端模型。三組數字讓這件事有意義：mean AUROC 0.814 相對 token entropy baseline 只有 0.549、只用 15–35% 的 query 走雲端就能匹配 Gemini 3.1 Flash-Lite 的整體表現、probe 從未看過 audio 資料的情況下在 audio benchmark 仍達 0.79–0.88 AUROC（也就是它學到的是跨模態的「答錯 signal」而非某個 domain 的 pattern）。

技術機制上，probe 是後訓練加上去的小網路，訓練目標是預測「這個答案跟 ground truth 的差距」，它輸入不是模型的輸出 token 而是中間層 hidden state——這代表 probe 抓到的是模型「內在的不確定性」而不是輸出的表面樣態。實務行為的 handoff rate 是隨 task 難度浮動：ChartQA 這種視覺辨識類 15–20% 就走本地、MMLU-Pro 這種需要推理的知識題升到 45–55%。這一層 confidence 分數的存在讓「小模型跑本地大模型跑雲端」這條 hybrid 路線第一次有了資料驅動的 routing 決策。

以前你設計端上 + 雲端混合推理，routing 邏輯要不是靠 prompt 分類（易錯）、要不是全丟本地（結果差）、要不是全丟雲端（貴且慢）；現在你能拿 confidence 分數當 routing 訊號，本地做主、雲端只接手 15–35% 的困難 query。這條「模型知道自己什麼時候該求救」對你 Nexus MCP server 有一個直接對應：MCP tool 呼叫可以走同一套邏輯，本地 tool 先答、confidence 低才 escalate 給 Claude Cloud，成本模型從「每次都上雲」翻「大部分在本地」。

## 今日總結

今天四條路徑同一個工程動作——「AI + Web 基礎設施這週被『從隱式便利翻顯式控制』全面壓力測試」：

- **Next.js 16.2.11** 一次補 10 條 CVE，App Router + Server Actions + Turbopack 全表面被打補丁——過去「default 開啟一堆便利 primitive」翻「default 收緊每個 primitive 的攻擊面」；
- **Claude Code v2.1.215 → v2.1.218** 一週四版連發，subagent concurrency cap 20 + nested 預設 off + `/code-review` 翻背景執行——過去「Claude 自己判斷該開幾條 subagent」翻「使用者顯式管制資源預算」；
- **Bento 單一 HTML 560KB** 塞完整 slide app——過去「web app 靠 CDN + npm 分發」翻「web app 反過來走單檔 distribution」，讓 Fortune 500 內部審查流程繞開；
- **Cactus Hybrid confidence probe** 讓 Gemma 4 端上模型知道自己什麼時候該求救——過去「hybrid 推理 routing 靠 prompt 分類猜」翻「routing 靠模型 hidden state 產出的 confidence 分數決策」。

延續本週的敘事線：7/19「AI agent 從雲端 vendor 往你機器上搬」→ 7/20「AI 產出的價值主張被工程 / 資源 / 認知三軸真實化壓力測試」→ 今天「AI + Web 基礎設施的『隱式便利』預設值被 vendor 主動翻成『顯式控制』」。三條 vendor（Vercel Next.js + Anthropic Claude Code + Bento 團隊）加一條研究團隊（Cactus）都在同一個方向上退——安全邊界不能靠 default、資源使用不能靠 auto、distribution 不能靠 CDN、hybrid routing 不能靠 prompt 分類。每一條都可獨立看，但拼起來構成 2026-Q3 的新刻度：「vendor 側的 default 越激進，客戶側就越需要顯式控制的介面」。
