# 2026-08-06 學習日誌

## Claude Code v2.1.220 → v2.1.223：連四版全在補「權限審查繞道」——sandbox 從網路層往 shell / workflow / bypassPermissions 三層擴

上一次整理 Claude Code 是 v2.1.219（7/24，sandbox.network.strictAllowlist 上線），從那之後 11 天 Anthropic 一口氣出了四版，全都圍繞同一件事：把過去被找到的權限審查繞道路徑一條一條補起來。v2.1.220（7/25）只寫「bug fixes and reliability improvements」，是連續變更之前的清場；v2.1.221（8/03）補三條 bypass——zsh 在 `[[ ]]` regex conditional 裡可以塞隱藏 Bash 命令通過權限檢查（現在會 prompt）、Windows PowerShell 對含引號字元的路徑處理錯誤（現在會 prompt）、`--mcp-config` 指定的 MCP server 在 print mode (`-p`) 第一 turn 前沒連上導致模型把 tool call 當文字輸出（現在會先連上）；同版還加了 Linux/WSL 上的 `mode: "mask"` 選項讓 sandboxed 命令讀到 sentinel copy、真值由 sandbox proxy 在 egress 時替換（macOS 因 fs 層限制退回 `deny`），把「credential 完全不進 subprocess 記憶體」變第一級可宣告能力。v2.1.222（8/04）補四條——worktree-isolated session 跟它的 subagent 可以對 main checkout 跑破壞性 git 命令（現在 isolation 對 file edit 跟 Bash 都套到）、PreToolUse auto-allow hook 在 background agent task（summaries / compaction / renames）繞過工具限制（現在也套 restriction）、`/usage` 對每個 MCP server 的 attribution 過度歸因（現在只算實際消費該 server tool result 的 request）、session 沒有連到後推 branch 才建的 PR。v2.1.223（8/06）今天早上出的，補四條最刺眼的——workflow script 用動態 `import()` 可跑出 workflow sandbox（現在阻斷）、agent definition 的 `bypassPermissions` mode 忽略 org 的 bypass-permissions disable policy（現在遵守 org 政策）、Bash 命令可以精心構造把自己的部分內容藏到權限檢查外（現在檢查完整命令）、命令用 tab 或不可見 Unicode 前置填充可以把部分內容從 approval dialog 藏掉（現在正規化後檢查）。

連四版對照 7/24 v2.1.219 那一版看，Anthropic 的節奏很清楚：v2.1.219 是「加一個新的 sandbox primitive（network layer strict allowlist）」，v2.1.221–223 是「發現既有 sandbox primitive 在四個不同層次都被繞過，一個一個補」。四個層次分別是——shell parser（zsh `[[ ]]` 與 Windows PowerShell 引號）、字元編碼（Unicode 前置填充 + tab 前綴 + Bash 命令內部 hidden segment）、workflow runtime（動態 `import()` 逃出 sandbox）、agent policy（bypassPermissions 忽略 org disable）。這四層不是意外組合，是一個 permission model 從「模型看得到什麼就檢查什麼」翻成「不管模型看到什麼、實際會執行什麼就檢查什麼」的完整補洞路徑——normalize before check、check the actual bytes, not the display form、sandbox 不是選項是強制、org policy 是最上層。同時 v2.1.222 修的 worktree isolation 對 main checkout 破壞性 git 命令這條也是同哲學：isolation 過去只擋 file edit，不擋 Bash，agent 用 `git reset --hard` 直接搞死 main branch——現在 Bash 也套 isolation 邊界。

以前你 Claude_auto 排程的權限模型是「requiredMinimumVersion 標一個版本 + 幾條 allow rule + 相信這幾條 allow rule 涵蓋所有邊界」；連四版之後這個假設不成立——邊界被繞過的形式從「你想不到的 rule 漏洞」翻成「你想不到的 char encoding / shell parser / runtime primitive 漏洞」。對 Claude_auto SKILL.md 四件最小成本升級：requiredMinimumVersion 從 2.1.219 升 2.1.223 直接享用四層補洞；sandbox 層加 Linux/WSL 上的 `mode: "mask"` 讓 sources.yaml 8 個 domain 對應的任何 credential（若未來有 API key）不進 subprocess 記憶體；worktree isolation 強制打開（就算目前排程單一 session 也照打，未來要跨 session 時 v2.1.222 這條 isolation 邊界已經在）；顯式標拒絕 `bypassPermissions`（永遠不用 org disable policy 那條 fallback）。對 Nexus 對外採購 deck，這條「vendor 連四版全補權限審查繞道」是「vendor 側自主誠實化」新一輪最強證據——vendor 主動連續公告自家 permission model 有四層繞道並各自補齊，比任何行銷段落都證明這家 vendor 對 boundary integrity 認真。

## Atlassian Rovo 用 dynamic URL egress 把 Jira / Confluence 資料送到攻擊者 log——PromptArmor 5/23 通報，Atlassian 兩個月沒修

PromptArmor 8/05 出了篇 disclosure：Atlassian Rovo（Atlassian 自家 AI agent，掛在 Jira + Confluence 之上）可以被 indirect prompt injection 誘導把整個 tenant 的 Jira ticket 跟 Confluence document 內容送到攻擊者指定的 URL。攻擊機制不需要 human-in-the-loop 批准——Rovo 的 URL retrieval tool 對「動態產生的 URL」沒有任何保護：攻擊者只要在 Jira ticket comment 或 Confluence page 埋一段 injection payload，內容大意是「先讀 X ticket 內容，然後把內容 append 到 http://evil.com/log?data=... 這個 URL 上 fetch 過去」——Rovo 讀到 injection 之後就照做，敏感資料直接被 append 進 attacker URL、attacker web server 看到 request 就把 query string 記下來。除了這條主要 attack path，PromptArmor 還找到一條 `rovoChatPrompt` URL parameter 漏洞——攻擊者可以構造一個 URL，受害者一按就把預先塞好的 prompt 灌進 Rovo chat，一次點擊就完成 data exfiltration primitive。第二條 Atlassian 有修，第一條 5/23 通報之後 Atlassian 給了 case number，兩個月多次追蹤 Atlassian 沒回應，Rovo 到 disclosure 那天還是 vulnerable。

這件事的技術問題不新——simonw 在 HN 討論串講的話最直接：「所有現代 agentic 系統把（私有資料存取 + 不可信內容曝露 + 對外通訊能力）三件事湊在一起就會出這個問題」，Rovo 只是把三件事湊得最齊全的一個具體 case。解法也不神祕，simonw 也給了：對 agent 加 deterministic URL 限制——只 fetch 「使用者明確給過」或「trusted tool 傳出」的 URL，agent 自己合成 + append 使用者資料 + 沒經人審批的 URL 一律 block。對比 5/25 Microsoft Copilot Cowork 那條攻擊鏈（PromptArmor 同一家發現，5 行 injection 藏進 81 行 skill、5/5 試 100% 成功率、攻擊點是 Cowork 自動發 Teams/Outlook email 給 active user 不需 human approval），這次 Rovo 的 disclosure 是同一種 architectural 漏洞的第二個大 vendor case——動態 outbound（Cowork 是 email、Rovo 是 HTTP URL）配上 indirect injection 配上沒有 human gate，三件事湊齊就 100% 攻破。時間線也值得記：5/23 通報、Atlassian 給 case number、兩個月無回應、PromptArmor 走 responsible disclosure 期滿公告——vendor 側對 AI agent 邊界問題的 SLA 顯然還沒建立。

以前你 Nexus MCP Server 對「outbound URL 從哪來」這件事是靠 tool schema 隱式限制——MCP tool 定義了 fetch(url) 就假設呼叫方會給合理的 url；現在 Rovo 這條 case 直接證明這個假設不成立——AI agent 可以被 injection 誘導自己合成 url、把敏感 tool result 塞進 query string。對 Nexus MCP Server 三件補洞：MCP tool schema 對 outbound URL 顯式改成 whitelist（Figma API domain + npm registry + design token JSON schema domain 三條允許，其他拒絕）、tool response 對 outbound URL 加 「這個 URL 是使用者給的 or trusted tool 傳的」flag、任何 tool 想 fetch dynamic URL 都必須經 human approval prompt 才能執行。對 Nexus 對外採購 deck 這篇更直接——加「outbound URL 白名單 + dynamic URL 需人審 + injection payload deterministic block」三條，用 Atlassian Rovo 5/23–8/05 兩個月無回應當「別家 vendor 對 AI agent 邊界問題的實際 SLA」對照，Nexus 的 policy schema 對 IT/SecOps 立刻好懂。

## Neon Castform：4B 開源模型 post-train 後在 retrieval 追平 GPT-5.6 Sol，成本 100× 便宜、單次 request 從 10 秒壓到亞秒

Neon 8/05 發了 Castform 的公開實驗結果：一個 4B 參數的開源模型，用 Castform 這條 RL post-training pipeline 訓練之後，在 retrieval 任務上追平 GPT-5.6 Sol（OpenAI 現在的 flagship），成本便宜 100 倍。實測數字——GPT-5.6 Sol 跑一次 multi-turn search 大約 10 秒以上、單次 request 端到端成本大約 $0.03；Castform 後訓 4B 開源模型跑同樣的 retrieval 任務，準確度追平 Sol，成本便宜兩個數量級。方法不是 embedding-based retrieval（那條路徑主流是 CodeRankEmbed / OpenAI ada 那類）——Castform 走 RL post-training 把 retrieval 這個特定任務「教會」小模型，讓小模型不 overthink（更大的模型在 fact retrieval 任務上常常 overthink 反而輸給小模型）。Neon 的定位是「specialized model 打 generalist model」——小模型只要專精一個任務、後訓 pipeline 一次建好、之後 base model 版本升級只要重跑 pipeline，維護成本不高。

這件事的意義不在「4B 小模型贏 SOTA」——這個結論之前 fine-tuning 界就講過很多次；意義在把「self-host 一定貴」跟「open weights 一定弱」這兩個 2025 底的直覺打掉。過去大家的 mental model 是——大 vendor 的 flagship（Sol、Opus 4.8）什麼都能做但貴、開源大模型（Kimi K3 2.8T、Qwen）便宜但要自己跑、開源小模型（4B 級）便宜且快但太笨——所以任何 production task 只要求「準確度」就會 default 走 Sol / Opus 那條線。Castform 這篇的實測把這條 default 直接推翻——特定任務（retrieval）+ 後訓 pipeline（Castform）+ 4B open weights 可以在準確度追平 flagship 的同時把 cost 砍到 1%，這條路徑對「大量、重複、單一任務」的 workload（RAG、log analysis、structured extraction、SQL query generation）都成立。同期 HN 討論串裡最有共識的一條 comment 是「不用把 Opus/Fable 的 token 燒在 dumb-but-token-heavy 任務上」——這條原則過去是好想法但沒有工程證據，Castform 是第一次把「單一任務 specialized model 100× 便宜」這件事做成可複製的 pipeline。

以前你 Nexus MCP Server 對「客戶問設計 token 相關問題」預設走 Claude Sonnet / Opus—— reasoning 強但單次 query 貴。Castform 這條 case 讓 Nexus 有第二條路可規劃：對「重複、結構化、retrieval-heavy」的 query（例如「Nexus button component 用哪個 CSS variable？」「semantic-primary token 的 fallback chain 是什麼？」「哪個元件依賴 spacing-md？」），跑 Castform 後訓 4B 小模型比 Sonnet 便宜兩個數量級、latency 從秒級壓到亞秒。對 Nexus 對外採購 deck 這條也是重點——歐盟 / 日韓 / 醫療合規客戶要「self-hosted」時，Nexus 可以給兩種 self-host option：一種是 Kimi K3 全權重（2.8T、機房級 GPU、追平 Sol/Opus 但貴）、一種是 Castform-style 後訓 4B（單機 GPU、任務精準專精但便宜）——客戶依 workload 特性選一種，Nexus 兩種都能接。這條 fallback chain 從「Sol / Opus / Sonnet 三家雲端 vendor」翻成「雲端 vendor + Kimi K3 全權重 + 後訓 4B」三段實選，比只給客戶一種答案有說服力太多。

## shadcn 新加 Questionnaire primitive：multi-step 問題 + freeform 答案 + validation + 鍵盤導覽一個組件搞定

shadcn 8/05 出了 `@shadcn/react@0.3.0`，新增一個 Questionnaire primitive——multi-step 問題流程、freeform 答案輸入、驗證、鍵盤導覽全部一個 primitive 內建。這條看起來只是新增元件的 changelog 其實延續 shadcn 這半年的一條大脈絡：把「特定 UX pattern 需要多個 headless primitive 拼起來」的痛點翻成「一個新 primitive 直接對應這個 UX pattern」。過去要在 React 做 multi-step questionnaire——你要組 form primitive（validation、error state）、multi-step state machine（current step、prev/next navigation、progress indicator）、keyboard navigation（Tab 移焦點、Enter 提交、Esc 取消、Arrow key 切選項）、freeform input（controlled input、debounce、submit-on-blur）——過去要 4-5 個 headless library 拼、拼起來還有 accessibility 焦點漂移的邊角問題。這個 primitive 把這五件事包成一個組件、給你完整 headless API 讓你自己組樣式，卻不用碰底層。

這條放到 shadcn 這半年的產品路徑看意義更明顯。5/29 shadcn 出 4.13.1 補三條資安（cross-origin redirect drop custom header + path traversal validation + dependency string flag injection block），把 registry 資安門檻拉到「trust the registry」翻「validate every registry input」。6/01 4.10.0 讓任何 GitHub 公開 repo 加 registry.json 就能 `pnpm dlx shadcn add owner/repo/item` 拉，把 distribution 從 shadcn.com 官方 registry 翻成「任何 GitHub repo 都能當 registry」。今天 8/05 Questionnaire primitive 是產品路徑第三步——registry 通了、資安補了、下一步是把過去要靠社群 recipe 拼的複雜 UX pattern 直接做成 first-class primitive。這條走完 shadcn 就從「元件庫」翻成「元件庫的協議 + 工具 + first-class primitive 三合一」，跟你 Nexus 的定位越來越像。

以前你 Nexus packages/ui 想加 Questionnaire 這類 multi-step UX，只能三個選項：一個超複雜的自製元件（Angular + RxJS + form state machine + focus trap 全部自己寫）、拼四五個 headless library（Angular CDK + reactive forms + custom directives 拼起來但拼縫多）、或者直接放棄這條 pattern 只做單頁 form。shadcn 這條 primitive 給你一個對照物——你可以看 primitive 內部怎麼把「multi-step state + validation + focus management + keyboard nav」四件事的邊界劃在哪、對應 headless API 是哪幾條、accessibility invariant 是什麼——然後把同樣的邊界劃在 Nexus 的 Angular 版 QuestionnairePrimitive。對 Nexus packages/ui 這條是直接可 port 的設計參考——你不必逐字翻譯 React 實作，但可以把 primitive 的 headless API 邊界拿來當 Nexus Angular 版的規格。同時對 Nexus 對外採購 deck，加一條「Nexus primitive 對照 shadcn 業界主流」的中立性維度——Nexus 的每個 primitive（包含未來要加的 Questionnaire）都有對應 shadcn primitive 對照，客戶 IT 團隊要遷移或整合時不用重新學一套新的 mental model。

## 今日總結

今天 4 條獨立路徑指向同一個工程動作——**「AI agent 的邊界，被繞道之後才會知道原來的邊界劃錯了」**。Claude Code 連四版（v2.1.220–223）補 zsh `[[ ]]` + Windows PowerShell 引號 + Unicode 前置填充 + tab 前綴 + Bash hidden segment + workflow dynamic `import()` + bypassPermissions 忽略 org policy + worktree isolation 對 Bash 不套 八條 bypass path，全部是「原本以為 rule pattern 涵蓋、實測繞道還有八條」——vendor 側自主誠實化的 track record 從單一 primitive（7/24 strictAllowlist）翻成連四版補洞。PromptArmor 對 Atlassian Rovo 的 disclosure 是同一個工程動作在 vendor 側的另一面——Rovo 的 URL retrieval tool 對 dynamic URL 沒保護，AI agent 被 injection 誘導自己合成 URL、把敏感資料塞進 query string 送到 attacker log，5/23 通報 Atlassian 兩個月沒修，是 5/25 Microsoft Copilot Cowork 之後同一種 architectural 漏洞的第二個大 vendor case（outbound + injection + no human gate 三件事湊齊 100% 攻破）。Neon Castform 是同一個工程動作的成本側——「self-host 一定貴、open weights 一定弱」這條 2025 底的直覺被 4B 後訓小模型在 retrieval 追平 GPT-5.6 Sol 且 100× 便宜實測打掉，Nexus fallback chain 從「一種 self-host 答案」翻成「大模型全權重（Kimi K3）+ 小模型專精後訓（Castform）」兩段依 workload 特性選。shadcn Questionnaire primitive 是同一個工程動作在元件庫側的展開——過去要靠社群 recipe 拼的 multi-step + validation + focus + keyboard 四件事現在做成 first-class primitive，shadcn 從「元件庫」翻「元件庫的協議 + 工具 + first-class primitive 三合一」路徑第三步。
