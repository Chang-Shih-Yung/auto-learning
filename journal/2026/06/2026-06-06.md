## 1. Microsoft pg_durable：在 Postgres 裡跑 crash-safe workflow，外部 worker 全砍

Microsoft 開源 **pg_durable**（GitHub 650 stars，PostgreSQL License），讓你**在 SQL 裡寫 long-running workflow，由 Postgres 自己做 checkpoint，crash / restart / failed step 都能 resume**。你開一段 SQL 寫進去，每一步狀態自動 persist 到 Postgres、survive 主機重啟、survive failover，**完全不需要外部 worker、不需要 Redis、不需要 Temporal、不需要 BullMQ**——Postgres 本身就是 runtime。對你現在正在學 SQL 的階段直接受用：vector embedding pipeline（chunk → call API → upsert pgvector）、ingest pipeline（stage → dedupe → transform）、定時維護任務、fan-out 平行查詢、外部 API enrichment——這些以前要拆三個服務寫的東西，現在一段 SQL 解決。

技術機制：pg_durable 是 PostgreSQL extension，用 Rust 寫（codebase 50.4% Rust），把 workflow 拆成 composable SQL operators，每個 step 完成後 commit transaction 寫進 metadata table；crash 後 Postgres 重啟，extension 讀 metadata 找出未完成的 step 從上次 commit 點接著跑。內建排程、條件分支、平行執行三個 primitive——以前要靠 Airflow、Temporal、Step Functions 才有的 DAG 編排，現在跟你的 application table 共用同一個 transaction、同一個 backup、同一個 monitoring。範例語法：

```sql
SELECT df.start(
    'SELECT id FROM documents WHERE processed = false LIMIT 100' |\=> 'batch'
    ~> 'UPDATE documents SET processed = true WHERE id = ANY($batch)'
);
```

以前做企業專案——你在東元 MES 跑生產數據推送，背後要 SignalR + 應用層 retry + 資料庫狀態欄位三件事拼出「掉線重連繼續處理」；如果那時有 pg_durable，整段 workflow（拉訂單 → 拆 BOM → 推 WO 給每條產線 → 等回報 → 寫進 dashboard table）會收成 SQL 三段，狀態就在 Postgres 本身，restart 不需要重設記憶體狀態。對 Henry 在 Nexus 推給企業客戶的延伸——packages/cli 可以加一個 `nexus deploy --workflow=pg_durable` 模式，把 design token sync、a11y check、bundle analysis 變成 pg_durable workflow，客戶 IT 部門看的是「我們 workflow 跟 application 在同一個 Postgres、同一個 backup policy、同一個 audit log」這種「複雜度收進去」的賣點。對應 5/26「複雜度不消失，只是移到最合適的位置」這條主線——把 workflow execution 推回到資料庫端，跟你已會的 application-level cache 推到 service edge 是同一條哲學。

## 2. Google Gemma 4 QAT：Gemma 4 E2B 壓進 1GB 記憶體，手機跑 frontier-level open weight

Google 釋出 **Gemma 4 QAT 版本**（quantization-aware training）：**Gemma 4 E2B 的記憶體需求從原本好幾 GB 壓到 1GB**，意味著你手上中階手機就能跑這個級別的開源模型，桌機隨便一台 8GB MacBook 跑更大版本綽綽有餘。關鍵差異是 QAT 把量化過程**整合進訓練本身**而非訓練完才壓——以前 post-training quantization 把 16-bit 模型砍成 4-bit 會掉精度，QAT 在每步 training 都用「量化後的權重」算 loss，模型學會適應量化的數值表現，所以 Q4_0 + 行動專用 2-bit 混合方案下精度幾乎不掉。

技術組成有四個 mobile 專用設計：(1) **static activations**（預先算好 scaling 因子，inference 時直接套）、(2) **channel-wise quantization**（依硬體 accelerator 結構切 channel）、(3) **targeted 2-bit quantization**（只把 token-generation 層壓 2-bit，其他保留 4-bit）、(4) **embedding + KV cache 優化**（把長對話的記憶體開銷砍下來）。整套 weights 已上 Hugging Face（GGUF + compressed tensor 兩種格式），llama.cpp / Ollama / LM Studio 桌機可直接跑、LiteRT-LM runtime 與 Transformers.js 給手機與 web、vLLM / SGLang / MLX / Unsloth 給開發者 fine-tune。

以前要在手機或瀏覽器跑 LLM，你只能選兩條路：(a) 跑很小的模型（< 1B 參數）能力有限、(b) call 雲端 API 但每次都付錢且把使用者資料外送。Gemma 4 QAT 把這條路第三選項打開：**E2B 等級的模型直接跑在使用者裝置上**，沒有 API key、沒有 round-trip latency、沒有訂閱、沒有資料離開設備。對 Henry 在 Nexus 做 design tooling 的延伸：packages/ui 元件庫之後可以內建一個「設計師現場問 Claude 為什麼這個 padding 不一致」的對話框，跑在使用者瀏覽器本地的 Transformers.js + Gemma 4 E2B；packages/cli 的 design token sync 可以加一個本地版「分析這份 Figma JSON 是否符合 token system」不必送雲端。對應 5/30 〈Liquid LFM2.5-8B-A1B〉同一條主線——on-device 不再是「玩具版」，是「夠用版」。

## 3. Claude Code v2.1.166：fallbackModel 三層、cross-session message 不再帶使用者授權

Claude Code v2.1.166（6/6 凌晨 release）三個結構性變動全部直接打中你 Claude_auto 排程任務的可靠度與安全模型：

**`fallbackModel` 設定升格為一級**——可以宣告**最多三個 fallback model 依序嘗試**，主模型 overloaded 或 unavailable 時自動接，`--fallback-model` CLI 旗標現在也適用 interactive sessions。意思是你 SKILL.md frontmatter 可以寫 `model: claude-opus-4-8` + `fallbackModel: [claude-sonnet-4-6, claude-haiku-4-5]`，今晚 Anthropic API 一段時間 503，你的排程任務不會 hang，自動降一階繼續跑、跑完通知你今天降階執行（這對 6/5 的「跑得久要被量化」主線的可靠度補強）。對應 v2.1.166 還新增的「Claude Code 遇到 API non-retryable error 會在 fallback model 上 retry 一次」——auth / rate-limit / request-size / transport 錯誤仍然立即冒上來，但 unknown 500 之類的錯誤現在自動切備援，不再需要外部 cron 重試。

**Cross-session messaging 的信任邊界硬切**——這是今天最重要的一條 security 結構變動：**從別的 Claude session 經由 `SendMessage` 轉送過來的訊息，不再帶使用者授權**。receiver session 會拒絕轉送過來的 permission request，auto mode 直接 block。背景：v2.1.157 推出 Dynamic workflows（DAG fan-out）後，一個 parent agent 可以 spawn 數十個 child agent；如果 child agent 中招 prompt injection 後 SendMessage 給 sibling agent，原本 sibling 會以為「這是 Henry 同意的」——v2.1.166 把這條信任傳遞鏈砍掉，sibling 必須自己重新跟 Henry 確認。對應 6/5 Anthropic 白皮書「user misuse / model misbehavior / external attackers」三類風險中 model misbehavior 的補丁，把「session 內 trust」跟「session 間 trust」分開。

**glob pattern 在 deny rule 的 tool-name 位置可用**——`"*"` 等於 deny 所有 tools；allow rule 反而拒絕非 MCP 的 glob（避免你不小心開太大的洞）；deny rule 用了未知 tool name 會在 startup warn。這條對企業 IT 寫 managed settings 強約束很實用——可以宣告「這個 user 只能用 Read + Edit + 我們自己的 MCP server，其他全 deny」一行寫完。

其他補丁：JetBrains 2026.1+ terminal flicker 修（synchronized output）、PowerShell 命令驗證在 killed process 的 children 持有 output pipe 時 hang 修、`claude --bg-pty-host` orphan 在 daemon 死後 100% CPU 修、Windows worktree 背景 agent 重開 crash-loop 修、managed settings 一個無效 entry 不再 silently disable 整段 policy。對 Claude_auto 的立即動作：(1) SKILL.md frontmatter 加 `fallbackModel: [...]` 把可靠度從 cron 重試上移到 CC 自己決定、(2) Dynamic workflows 內各 sub-agent 之間的 SendMessage 設計現在可以放心做 fan-out，不必擔心 child 中招會擴散到 sibling、(3) deny rule 用 glob `"*"` 配 explicit allowlist 做「最小授權」設定（例如 Claude_auto 排程只允許 Read / Write / Bash 三類 + 你的 WebFetch domain allowlist）。

## 4. Stop Using Conventional Commits：scope 才是第一順位，type 是冗餘的

Sumner Evans（Can/Am Technologies Tech Lead）6/2 寫一篇〈Conventional Commits encourages focus on the wrong things〉在 HN 拿到 268 點，核心論點：Conventional Commits 把 `fix(compiler): prevent namespaced SVG elements from being stripped` 這種 commit 變成「**type 強制（fix/feat/chore）+ scope 選用**」，這是順序反了——「fix」這個字從描述本身一看就知道了，**真正在 incident 時你 scan git log 想找的是「哪個模組」（compiler、auth、token-sync），不是「這是不是 bug」**。Linux kernel、Go、Git 早就用 `subsystem: description` / `package: description` / `area: description` 這條 scope-first pattern 跑了幾十年，Evans 直接架了 [scopedcommits.com](https://scopedcommits.com) 推這個替代規格。

他對 Conventional Commits 三個承諾的拆解：(1) **自動 changelog** 把 developer 跟 user 兩種讀者混在一起——使用者不在乎你 refactor 哪個 internal helper，但 Conventional Commits 強制每筆 commit 都標 type、結果 changelog 灌水；(2) **semver 自動 bump** 在 revert 與意外 breaking change 下會失準——一個 `fix:` 其實 break 了 public API，自動化 tool 不會抓到；(3) **用 commit type 觸發 build** 是 security 漏洞——攻擊者只要 PR 寫 `chore:` 就能跳過 release pipeline。

以前你在企業專案 git log 找「上週是誰改了 token sync」這件事，commit message 寫 `feat(tokens): ...` 跟 `feat: tokens add OKLCH support` 差別不大；但 Evans 的論點推到極限的場景是 monorepo——當你 Nexus 有 packages/ui、packages/cli、apps/demo、apps/www 四個 workspace 同時演進，**scope 是「我這次到底動了哪個 package」這個結構資訊**比「這是 fix 還是 feat」重要十倍。對 Henry 立即動作：(1) 把 Nexus 的 commit convention 從 `feat(...)` 改 `packageName: description`（例如 `packages/ui: add OKLCH token resolver` / `packages/cli: support --dry-run flag` / `apps/www: fix dark mode flicker on first render`），(2) Claude_auto 自己的 commit message 已經是 `daily: YYYY-MM-DD AI tech digest` 這種 scope-first 結構（巧合走在這條方向），(3) 對 Nexus 客戶推一份 commit convention guide 把 scope-first 寫成內部規範。

對應 6/5「containment 一級基礎設施化」延伸——commit message 是 codebase 對「未來自己」的 contract，把 contract 的「最重要欄位」（scope）放第一位是同一條哲學：**重要的資訊不該是選用，不重要的不該是強制**。

## 5. Inference Theft：你的 AI endpoint 是別人的免費模型，5 層防禦

Morgan Willis（dev.to 6/5）把一個新攻擊類型工程化：**Inference theft**——攻擊者發現你的 AI endpoint 後，把它包裝成標準 model API 用 5-10% 的官方價錢轉售，**你付完整 inference 費，攻擊者賺中間價差**。實際案例：某速食連鎖的客服 chatbot 被一群人發現可以拿來當免費 coding assistant 用，整段對話被 reroute 進另一個白牌服務。經濟學支點是「**AI 請求的成本可以比一般 HTTP 請求貴一百萬倍**」——傳統 API call 一次幾分之一分錢，一次 agentic request 可能 $1+。攻擊者的工程一次性成本被你長期未封頂的 inference 帳單 amortize 掉。

具體燃燒速度：一個 user rate-limit 設 90 requests/minute、每次 $0.30，**等於 $39,000/天**——這還是 well-behaved 的 rate；沒設 rate-limit 的話一個 botnet 一夜燒掉一輪 Series A。Willis 提的 5 層防禦：

1. **Bot Detection**（per-request human verification，抓 botnet 抓不到正當帳號 abuse）
2. **Guardrails**（AWS Bedrock Guardrails 或同類做 input/output 內容過濾，擋「請幫我寫一段 Python」這種偏題請求）
3. **Cost-Aware Routing**（intent classifier 把簡單請求送 cheap model、複雜的才送 frontier model——對應 6/5 Copilot AI Credits 同一條主線）
4. **Budget Controls**（per-user token/cost limit，超過 graceful degrade 而非直接全停）
5. **Observability**（real-time spend monitoring + alerting，cost 50/75/90 告警，對應 5/26 Veso AI agentic patterns）

以前做企業前端 API 你擔心的是 DDoS（炸頻寬 / 服務不可用），現在多一條「**denial-of-wallet**」——服務照常可用，**你帳單爆掉**。對 Henry Nexus 推給企業客戶的 AI feature：未來 packages/cli 內任何「上傳 design 給 LLM 分析」的 API 都必須在 client 端先做（a）per-user budget cap、（b）request fingerprint 比對偵測「這個 user 在某個 minute 突然 100× 平均量」、（c）cost log 寫進 audit DB 客戶 IT 看得到。對 Claude_auto 個人專案：因為走的是你自己的 API key 跟 token 預算，今天還不會被攻擊，但**今天就該把每天 token cost 寫進一個 trend dashboard**（呼應 6/5 OTEL_RESOURCE_ATTRIBUTES + Vercel KV 14 天 trend 的延伸），等你之後把 packages/cli 開放給外部用就有現成的觀測基礎建設。

## 6. Neo + Claude Code：「主 agent 退一步、子 agent 做完報告」省 62% token 的設計選擇

Gaurav Vij（dev.to 6/5）量化 Claude Code + 外掛子 agent 跑同一個 speech-to-text evaluation task 的成本對照：

| 跑法 | 成本 | 字錯誤率（WER） | RTF（即時倍率）|
|------|------|----------------|---------------|
| Claude Code 單獨 | $1.96 | 20.9% | 0.519 |
| Claude Code + 子 agent | $0.74 | 4.65% | 0.328（快 37%）|

省 62% 成本同時把 WER 從 20.9% 砍到 4.65%——這不是「省錢但變差」的 trade-off，是「省錢同時更好」。設計差異是子 agent 進場前**先花 2 分鐘專門查 benchmark + 文件**寫一份線性 plan，然後一步一步執行加自我驗證；Claude Code 主 agent 退到只負責 dispatch + review，**不再 turn by turn 跟使用者 ping-pong 燒 token**。

技術機制是 **MCP server 模式**——子 agent 跑在本地（沒有資料外送），透過 MCP 協議跟主 Claude Code 對話。設定上是 Claude Desktop config 加一段 mcpServers entry 指向 `@heyneo/mcp` 套件、用 npx 啟動。Vij 強調的關鍵是「**research before code**」這個 prompt pattern——以前直接寫 code 模型每幾輪會迷路（context 累積、misalignment），改成「先讀文件、產 plan、再執行、每步 self-verify」之後 context 消耗反而少。

> ⚠️ 文章引用的 `@heyneo/mcp` 套件 GitHub stars / npm weekly downloads 在公開頁面無法驗證，新工具，使用前請自行確認安全性、不要直接照貼設定上 production。

## 今日總結

三條獨立路徑同一個工程動作：**邊界焊好之後，「state 跟 execution 的承載基板（substrate）」全面被重選**。

- **Microsoft pg_durable** 把 durable workflow 的 substrate 從「Temporal / Airflow / 外部 worker」推回 **Postgres 本身**——你的 application table、workflow state、checkpoint 共用同一個 transaction、同一份 backup、同一個 audit log。複雜度收進 PG extension，使用者層只剩 SQL operator。
- **Google Gemma 4 QAT** 把 LLM 推理 substrate 從「雲端 API」推進 **使用者手機/瀏覽器的 1GB 記憶體**——Q4_0 + 行動專用 2-bit + static activations + channel-wise quantization 四件事讓 E2B 級模型零 API 跑在本機。資料不外送、無 latency、無訂閱。
- **Claude Code v2.1.166** 把 cross-session message 的信任 substrate 從「session 內 trust 一路傳遞」**斷成 per-session 重新確認**——SendMessage 轉送過來的訊息不再帶使用者授權，auto mode 直接 block 轉送來的 permission request。Trust 不再隨 message body 一起在 sibling agent 間流通。
- **Sumner Evans / Conventional Commits 替代提案** 把 commit message 的「重要資訊位置」substrate 從「type 強制 / scope 選用」翻成「**scope 強制 / type 隱含於描述**」——對應 Linux/Go/Git 幾十年實踐，對 monorepo（你 Nexus 的場景）尤其關鍵。
- **Morgan Willis / Inference theft** 把 LLM endpoint 的安全 substrate 從「擋 DDoS（服務不可用）」擴成「擋 **denial-of-wallet**（帳單爆炸）」——5 層防禦：bot detection / guardrails / cost-aware routing / budget controls / observability，攻擊者用你的 endpoint 賣轉售你付錢。
- **Gaurav Vij / Neo + Claude Code** 把 multi-agent 的成本敘事從「分工讓速度變快」翻成「**dispatch + review 比全程陪跑省 62% 同時 WER 改善 4.5×**」——主 agent 退一步、子 agent plan-then-execute self-verify，substrate 從「同一個 context window 滾雪球」推進「明確 role 分割 + MCP 介面隔離」。

延續這條主線可以追蹤的下一檔次：

1. **「Substrate 多樣化下，跨 substrate 的 portability 是不是會卡」**——你寫的 pg_durable workflow 能不能換成 Temporal / Step Functions？Gemma 4 QAT 跑在 Transformers.js 跟 LiteRT-LM 行為一致嗎？跨 substrate 的「相同行為保證」會不會跟 6/5 的「邊界宣告語言標準化」收斂成同一個議題？
2. **「Substrate 重選之後，cost / latency / sovereignty 的三維 SLA」**——pg_durable 把 workflow 放 PG → 你 PG 也是 cost / 也有 disk IO bottleneck；Gemma 4 在本機跑 → 換成電池消耗 / 熱問題；inference theft 防禦的 budget cap → degrade gracefully 的 UX 怎麼設計。每個 substrate 都帶來新的 trade-off 維度。
3. **「Substrate 跟 contract 的對應關係」**——pg_durable 跟 SQL contract / Gemma 4 跟 Hugging Face GGUF format contract / Claude Code v2.1.166 跟 SendMessage trust contract / scope-first commit 跟 git log contract——每個 substrate 重選都附帶一個 contract 升格動作，這條對應呼應 5/27「契約 first-class 物件本身的『屬性』也要 first-class 化」推到下一層「substrate 屬性」。
