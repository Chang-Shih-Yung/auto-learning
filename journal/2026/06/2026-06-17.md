# 2026-06-17 學習日誌

今天三條獨立路徑落在同一個工程動作上：**「本地」這個基板第一次被當成可量化、可挑選、可加速的工程選項**——Vicki Boykis 把「在 M2 Mac 64GB 上跑 agentic coding」用 6 個模型 × Pi agent harness + LM Studio + Docker 跑出 ~75% frontier 準確率/速度的實測、Wolfram Language 15 把外部 AI agent（Claude Code / Codex）直接拉進桌面 Mathematica 的計算環境、Reflex 把 Python `ast.walk` 用 Rust 重寫拉到 220× 速度——三件事都是把過去「丟雲端 / 用既有抽象 / 等模型再變強」的預設值翻成「本地跑、量測過、自己改抽象層」。

## Vicki Boykis 在 M2 Mac 64GB 上跑 agentic coding ~75% frontier 速度與準確率

HN 6/15 頭條 1046 點 437 留言。Vicki Boykis（Mozilla AI ML engineer，maintain `viberary` 推薦系統）拿 M2 Mac 64GB RAM 1TB SSD 一台機器，跑過 Mistral 7B、Gemma 3、Gemma 4 系列（gemma-4-26b-a4b MoE / gemma-4-12b-qat）、OpenAI OSS-20B、Qwen 3 MoE 跟 Qwen 2.5 Coder——核心句「impossible for local models as recently as 6 months ago」（六個月前還辦不到的本地推理品質，今天能達到 frontier 模型大約 75% 的準確率與速度）。Vicki 試過 raw llama.cpp + Open WebUI、llama-cpp-python、Ollama、llamafiles、LM Studio 五種 inference engine 後，production 工作流選定 **Pi agent harness + LM Studio inference server**，整套封在 Docker 容器裡只開 bash 工具空間。實作完成的任務：Python 腳本重構、type hint linter、單元測試生成、部落格校稿、bootstrap 一個 two-tower 推薦模型——全部在本地 64GB Mac 跑完，沒打過一次 API。對你 Henry 拿手邊 Mac（你已經跑 Claude Code + Nexus 工作流）做設計系統 token 一致性 review 的場景，這份實測就是「可不可以脫雲」這題的第一份個人開發者尺度（不是 H100 集群、不是 8-GPU 商品節點）量化證據。

技術上 Vicki 的設定揭示三個工程決定：(1) **inference engine 選擇 LM Studio 而非 Ollama**——理由是 LM Studio 把 server 跟 GUI 分離，可以用 GUI 看 latency / token / temperature 即時面板而後端依然走 REST API；(2) **agent harness 選 Pi 而非 Claude Code 或自寫**——Pi 是輕量化的 Python harness（單一 script），bash 工具空間夠跑 Python/Bash/file edit，省去 MCP server 整套基礎建設；(3) **整套塞進 Docker 限制 bash 工具空間到唯一容器**——agent 不能 `rm -rf` 主機檔案、不能對外打 socket、不能讀 SSH key，相當於每個 agent run 都是 ephemeral filesystem。對應 6/12 MiMoCode + 6/15 Iroh 1.0 + 6/9 「lightest first」三條洞察主線，這次補上了「本地 Mac 64GB 是 lightest 還是不可行」這條過去懸而未決的量化定位——Vicki 的答案是「夠用，但要刻意選 inference engine + harness + 沙箱三件」。

Before：你想驗證 agentic coding 在本地可不可行，只能讀別人 benchmark（Cerebras / Groq / commodity 8-GPU MiMo），跟自己手邊那台 Mac 對不上；After：M2 Mac 64GB 第一次有同類設備的詳細食譜，連 inference engine 偏好（LM Studio over Ollama）、harness 選擇（Pi 而非自寫）、隔離方式（Docker bash-only）三件事都列清楚。對 Henry Nexus 工作流三件可同時動：(1) **packages/ui 設計系統 token 一致性 review** 改成 Mac 本地跑——把 Figma → JSON → OKLCH Token 過程中的「token 命名是否一致 / dark mode 對應是否完整 / annotation color 是否被誤用」這類純文字 review 改用 Gemma 4 12B QAT 在你的 Mac 本地跑，省 API 成本同時 token JSON 不離開本機，對應 6/13 Linear local-first + 客戶採購 deck「資料不出本地網路」差異化；(2) **MES 戰情室 ECharts 異常曲線 AI 註解 PoC** 用 Pi-style 輕量 Python harness + LM Studio 而非整套 MCP server，避開 6/11 「MCP +5k tokens/turn baseline」開銷，註解 prompt 短到不需要 frontier 模型；(3) **Claude_auto SKILL.md 加 fallback 本地模型路徑**——當 API 預算/網路出問題時，自動降級到本地 LM Studio + Gemma 4，把「日常 fetch/filter 跑本地、weekly retro 跑 Fable 5」這條 6/10 已決架構真正完成下半段。

## Wolfram Language 15 — Agent Tools framework 讓 Claude Code 直接呼叫桌面 Mathematica

6/16 release（Stephen Wolfram 親寫 release 文章，HN 91 點 21 留言）。Version 15 三件結構性變更：(1) **AI Assistant 內建 notebook**——三層訂閱（Basic 免費 / Pro / Research），notebook 底部出現 chatbar 直接問 AI，貼圖也能回出對應 Wolfram code，按一鍵執行；(2) **Agent Tools framework**——這是工程上最重要的一塊：讓外部 AI agent（明確點名 Claude Code、Codex）可以直接呼叫桌面 Wolfram 系統做計算，wolfram.com 網站現在會 serve Markdown 版本給 AI agent 用，網頁右上角直接有「For AIs」連結；(3) **30+ 新模型類型 + TimeSeries 處理百萬筆 + Symbolic Music**——`ModelFit` superfunction 統一指數/對數/冪次/多項式/類神經 30 多種擬合方式都認識單位跟分類資料，TimeSeries 框架重寫到能 handle millions of entries 不爆記憶體，新增 EventSeries 處理離散事件（server access log、地震記錄）。對你 Henry 拿 MES 戰情室即時生產數據 + Nexus packages/ui Storybook 做設計系統，Agent Tools framework 把「Claude Code 寫程式 + 桌面 Mathematica 算數學」兩種能力第一次正式接通。

技術上 Agent Tools framework 的設計重點是**雙向協議**：Wolfram 把 Markdown 版本的文件 serve 給 AI 用（純文字、無需 render JavaScript、agent 能直接吃進 context），同時提供 entry point 讓 AI agent 從外部呼叫 Wolfram kernel 做計算。對比 6/12 MiMoCode「Import from Claude Code 一行命令」是 agent runtime 互通，今天 Wolfram 15 是 agent ↔ specialized computation engine 互通——前者解決「換 CLI 不換 context」、後者解決「能寫程式的 agent 也能做數學計算」。TimeSeries 重寫到百萬筆穩定處理對應 6/8 Linear local-first IndexedDB 主線——同樣是「過去當 backend 抽象的東西，現在被推到能直接處理 production volume」這個刻度。Symbolic Music 跟你工作流關聯弱但展示了 Wolfram 一貫設計哲學：用 first-class symbolic representation 取代「自己拼字串」（音樂 = 音高 + 音符 + 和弦 + 小節 + 聲部 + 總譜的可組合 symbolic 表達式，跟你在 Nexus 推 design token = symbolic representation 取代 hex code 同源）。

Before：Claude Code 要算複雜微積分 / 解線性代數 / fit 多項式模型，要嘛內建 Python sandbox 跑 numpy（型別錯了 silent 失敗）、要嘛靠 prompt 騙模型「假裝你會算」（結果常常算錯）；After：Agent Tools framework 把這類「需要 specialized engine」的計算正式變成可呼叫的外部工具，Wolfram kernel 算對是它分內事，Claude Code 寫程式是它分內事，兩邊各做各擅長的事。對 Henry Nexus / MES 三件可同時動：(1) **MES 戰情室 ECharts 異常曲線統計分析**——你過去用 RxJS scan + 手寫滑動窗統計，現在可以讓 Claude Code 透過 Agent Tools framework 呼叫 Wolfram 算自相關 / spectral density / outlier detection，把「該不該 alert」這個判斷的數學依據從手寫升格到正式統計工具；(2) **Nexus packages/ui design token 數學一致性檢查**——OKLCH 色彩空間的 contrast ratio / WCAG 對比度計算，現在可以委派給 Wolfram 用 first-class 色彩函數做精確驗證；(3) **packages/www 文件站「For AIs」分離渠道**——對標 Wolfram 把網站 serve 兩份（人類版 + Markdown AI 版），Nexus 文件未來可以同樣分 `/docs` 跟 `/docs.md`，讓 AI agent 拉文件不需要 puppeteer render JavaScript，省 token + 提速。

## Reflex 把 Python `ast.walk` 用 Rust 重寫拉到 220× 速度

HN 6/16 93 點 16 留言。Reflex（Python full-stack web framework）在他們的 AI app builder 跑 lint 檢查發現 `ast.walk` 是延遲瓶頸：7,000 個 AST node 要走 ~2ms，AI 生成的程式碼一次 lint 多個錯誤同時報而非一個一個失敗，這 2ms × 多次呼叫累積起來變成 user-facing latency。Reflex 工程團隊七步優化：(1) generator 換 list 存（+5%）、(2) inline `iter_child_nodes()`（累計 +25%）、(3) 換掉 `iter_fields()` 改 `getattr()` 直取（累計 +50%）、(4) 把熱路徑 port 到 Rust 透過 PyO3 綁定（累計 +93%）、(5) 直接 iterate `__dict__` 而不重複 `getattr`、(6) 把 AST subclass 結構表 cache 到 ~2KB L1-cache-friendly lookup table（累計 +99.5%）、(7) 只掃 `_fields` 入口的 dict。終點數字：7,000 個 node 從 ~2ms 拉到 < 10μs，**220×** 加速。對你 Henry 已會 TypeScript + Monorepo CI + GitLab SAST 整合，這份逐步優化是「AI 生成的程式碼必須走 lint pipeline，lint pipeline 本身就是 bottleneck」這條 2026 新熱點題目的具體解法示範。

技術上這個優化的設計哲學值得拆解：每一步都對應一個特定的 hot path observation，而不是「整段重寫」。Generator 換 list 是因為 Python generator 每次 yield 都有 frame setup/teardown 成本，AST 走訪本來就要全展開、不需要 lazy 評估；inline `iter_child_nodes` 是因為函式呼叫在 Python 是字典查找 + dict 建立 + tuple 拆解，inlining 直接省下三件；換 `getattr` 直取是因為 `iter_fields` generator 本身也吃 generator 成本；最後 PyO3 把熱路徑搬 Rust 不是「Python 太慢」而是「這段 hot path 不需要 Python 動態能力」。L1-cache-friendly lookup table 是 systems engineering 教科書級別的細節——AST 結構表壓到 2KB 剛好塞進 L1 cache，CPU 不用一直 stall 等記憶體。對應 6/12 Endor Labs Fable 5 benchmark「廠商頭條跟獨立 benchmark 差距」洞察的下一個刻度：今天 Reflex 把「Python 標準函式庫的效能 baseline」這條過去當 unchallenged ground truth 的東西，量化成可挑戰、可改善的工程目標。

Before：AI 生成的程式碼一次性 lint 多個錯誤是 user-facing latency 瓶頸，Reflex 工程團隊只能在 timeout / 一次只報一個錯之間做妥協；After：220× 加速讓「一次 lint 多錯」成為預設行為而非奢望，AI 生成 → 立即多錯誤反饋 → 修一輪就過的迴圈第一次可行。對 Henry Nexus / Claude_auto 兩條工作脈絡：(1) **Nexus packages/ui CI 改成『lint-as-you-generate』**——你既有 GitLab SAST 整合是「commit 之後跑」，Reflex 的洞察是「AI 生成中就跑」，把 ESLint + tsc 包成可由 Claude Code 透過 streaming 觸發的低延遲服務，AI 生成元件當下就拿到所有錯誤一次回饋；(2) **Claude_auto MDX 驗證階段改成 stream-based**——你每次 session 寫完 journal 後 Read 重讀檔案驗證 AnnotationCard `{`/`}` 對稱，目前是「全寫完才驗」批次模式，可以改成「每寫完一個 AnnotationCard 區塊立刻驗」流式模式，把 Vercel build 中斷風險的反饋環從「整個 session 結束才知道有問題」拉到「剛寫完那一段就知道」。

## 今日總結

三條獨立路徑同一個工程動作——**「本地」基板第一次被當成可量化、可挑選、可加速的工程選項**。

Vicki Boykis 把過去「本地跑 LLM = 玩具」這條預設值，用 M2 Mac 64GB + LM Studio + Pi harness + Docker 四件具體選擇翻成「~75% frontier 同等效果」的量化基準（HN 1046 點驗證社群共識）；Wolfram Language 15 Agent Tools framework 把 Claude Code 跟桌面 Mathematica 兩種能力（寫程式 vs. 解數學）第一次正式接通，AI agent 不再需要假裝會算微積分，可以呼叫對的引擎；Reflex `ast.walk` 220× 把「Python 標準函式庫效能 baseline」這條過去當 unchallenged ground truth 的東西，量化成「7,000 node 從 2ms 到 10μs」可改善的工程目標。

延續 6/16 「邊界第一次能帶參數」洞察推到下一層——**邊界帶參數之後，每個邊界內的『基板』也要被量測、被挑選、被加速**，不再只是「跑起來底下那層你不用想的東西」：

| 基板 | 過去當作預設 | 今天升格為工程決定 |
|------|--------------|-------------------|
| LLM inference 底層 | 用 OpenAI / Anthropic API | 在 M2 Mac 64GB + LM Studio + Pi harness + Docker 跑本地，~75% 同等效果 |
| AI agent 算數學 | 假裝會算 / 丟 Python sandbox | Agent Tools framework 直接呼叫 Wolfram kernel |
| Python 標準函式庫效能 | unchallenged baseline | 七步優化 + PyO3 Rust 重寫，220× 改善 |

對應 5/27「契約 first-class 物件本身的『屬性』也要 first-class 化」推到「基板效能與選擇也要 first-class 化」這條 2026-Q3 下一個刻度——以前基板是「跑得起來就好」、現在升格為「量化、挑選、優化都是設計動作」。

對你 Henry 三條工作脈絡可同時動：(1) **packages/ui 設計系統 token 一致性 review** 拿 Vicki 食譜（LM Studio + Pi-style + Docker）跑成第一個「token JSON 不離開本機」PoC，對應 6/13 Linear local-first + 客戶採購 deck 「資料不出本地網路」；(2) **MES 戰情室 ECharts 異常曲線 AI 註解** 同時用 Pi 輕量 harness（省 6/11 MCP +5k tokens/turn baseline 開銷）+ Wolfram Agent Tools 算自相關/spectral density 把「該不該 alert」的數學依據從手寫升格正式工具；(3) **Claude_auto MDX 驗證** 改 stream-based 對應 Reflex 七步優化的精神，每寫完 AnnotationCard 區塊立刻驗，把 Vercel build 中斷風險的反饋環從「session 結束才知道」拉到「剛寫完那一段就知道」。
