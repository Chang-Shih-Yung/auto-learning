# 2026-06-05 學習日誌

> 今天的主軸：「containment（圈圍）」從邊界補丁升格為一級基礎設施。Anthropic 把它寫成工程白皮書、Microsoft 把它焊進 Windows、Cloudflare 把整套 JS 工具鏈收進來但保 vendor-agnostic、GitHub Copilot 用 token-based 計費把模型選擇變成最大成本變數、Kasra 花 $1,500 真的拿 9 個 LLM 去打一個 broken access control 漏洞——五條獨立路徑同一個工程動作：**把「邊界在哪、誰負責、能不能逃出去」從約定俗成升格為可宣告、可量測、可 enforce 的一級基礎設施**。

## 1. VoidZero 加入 Cloudflare：Vite/Vitest/Rolldown/Oxc 同一個 owner，$1M ecosystem fund 保中立

如果你正在用 Angular 17+（Vite-based）、Vue 3 + Vite、SvelteKit、Nuxt、Astro、Solid、Qwik、React Router、TanStack Start，甚至 Next.js 16 的 `vinext` 實驗分支，今天起你的整條建構工具鏈背後同一家公司在維護：Cloudflare。Evan You 帶著 VoidZero 全員加入 Cloudflare，Vite/Vitest/Rolldown/Oxc/Vite+ 五個專案的維護權繼續由原團隊主導，但加上 Cloudflare 注入的工程資源與一筆 **$1,000,000 Vite 生態系基金**，由 Vite core team 管理用來付給外部 maintainer 與 contributor。Vite Environment API（2024 開始 Cloudflare 與 Vite 共同設計）讓你跑 `vite dev` 時 server code 可以跑在 `workerd`——也就是 production Cloudflare Workers 那顆 runtime——意思是本地 dev 就能拿到跟正式環境一樣的 Durable Objects、D1、KV、R2、Workflows、Workers AI、Agents、Service Bindings 的行為，不需要再 mock。

這次收購跟過去 framework 公司被收編最大的差別是 Cloudflare 在公告裡明寫四件事：MIT 授權不動、Vendor-agnostic 不動（Vite 跑在哪個雲都可以）、roadmap 繼續由 Vite team 與社群決定、Evan 跟團隊繼續主導五個專案。Cloudflare 把這次操作對標今年初收編 Astro：「Astro 還是 open source，還是可以 deploy 到任何地方，roadmap 還是原本那條」。背後設計支點是 Vite Environment API——這是一個「generic mechanism in Vite + provider-specific implementations」的協議，任何 runtime（不只 workerd）都可以接，所以 Cloudflare 投資 Vite 不會等於 lock-in，因為 Bun / Deno / Node 也可以用同一個 API 接進來。

以前一個 framework 被收編，社群會擔心兩件事：roadmap 會不會被綁去服務母公司商業目標、其他 runtime 接入 API 會不會被 deprecate。VoidZero 這次的設計選擇是兩件事都用結構保住——前者用「Vite core team 管理 $1M 外部基金」確保社群還拿到實質好處而非象徵性、後者用「Environment API 本來就是 provider-agnostic protocol」確保 workerd 不會成為 Vite 的特權 runtime。對 Henry 在 Nexus 推 Monorepo（PNPM Workspace + packages/ui + packages/cli + apps/demo + apps/www）的決定：Vite + Vitest 在企業選型題上的「長期歸屬」這個風險今天被結構性壓低，packages/ui 元件測試框架選 Vitest 不會在 18 個月後變成被棄養的孤兒。

## 2. Anthropic 工程白皮書：How we contain Claude — supervision fatigue 93%，OS sandbox 後 prompt 降 84%

Anthropic 工程部門公開三套 agent 產品（claude.ai、Claude Code、Cowork）的「圈圍」（containment）架構演化。最關鍵的兩個數字：Claude Code 早期讓使用者每一步都按「允許」結果**使用者 93% 都按了允許**——「approval prompt 越多，每次注意力越少」這個直覺被 telemetry 證實，過度依賴 human-in-the-loop 就變 supervision fatigue；後來他們在 macOS 用 Seatbelt、Linux 用 bubblewrap 加上 OS-level sandbox（reads 允許、workspace 內 writes 允許、network 預設 deny），**permission prompt 數量直接降 84%**，runtime 也開源讓邊界可審計。Auto mode 在那之上又加一層 model-layer 守衛——在 Gray Swan Agent Red Teaming benchmark 上 Claude Opus 4.7 的單次 prompt injection 攻擊成功率 0.1%、100 次 adaptive attempt 後 5–6%、Auto mode 在 execution 前抓到約 83% 的「過度熱心」行為。

文章核心框架：把風險拆三類（user misuse / model misbehavior / external attackers），對應三層防禦（the model / the environment / external content the agent can reach）。三個產品各有不同的 isolation pattern：claude.ai 用 ephemeral gVisor container 完全 server-side、Claude Code 用 OS sandbox + 人類審 + Auto mode model-layer 三層、Cowork 用 VM + egress control + identity boundary。文中還誠實列出設計失誤：2025 中–2026 一月有人回報三個漏洞利用「使用者按下 trust 對話框之前就能執行的程式碼」——例如 clone 別人的 repo 看 PR 時，repo 內 `.claude/settings.json` 定義的 hook 在「Do you trust this folder?」prompt 顯示**之前**就被讀取執行；以及自家寫的 custom proxy 是最大事故來源（驗證了「最弱的一層永遠是你自己寫的那層」）。

以前討論 agent 安全停在「我們有 prompt injection 防護」這層宣稱；現在 Anthropic 直接把 supervision/containment/external content 三層拆開、把 telemetry 量化（93% / 84% / 0.1% / 83%）公開、把 trust dialog 之前的攻擊面當設計疏失承認。對 Henry 的 Claude_auto 排程任務：第一手收到的 SKILL.md 也是「在 trust 對話框之前就會被讀」的設定檔，意思是 `.claude/skills/auto-learning/SKILL.md` 內的內容必須假設潛在攻擊者能寫進去（雖然你自己的機器、自己的檔案，但這個威脅模型今天起被 Anthropic 認證為一級設計考量）；對 Nexus 推給企業客戶的設計工作流：把「Claude 跑在哪個 sandbox / 能否寫 disk / 能否 network call」變成你採購對話中的一級欄位，而不是「我們有用 best practice」這種模糊宣稱。

## 3. Microsoft MXC：把 Windows 變 agent 的 OS-level 圈圍層

Build 2026 微軟把 Windows 路線從「AI dev 不重要」翻成「agent containment 要 enforce 在 OS 層」。**Microsoft Execution Containers（MXC）**是一個跨平台、policy-driven 的執行層，內建在 Windows 與 WSL，讓你**在 agent 定義時宣告它能存取什麼（檔案 / 網路 / 剪貼簿 / UI 輸入裝置），執行時由 OS enforce**。架構是 composable spectrum：Process isolation 把 agent 跟使用者桌面 session 分開並綁定強身份（直接擋 UI spoofing 與 input injection）→ Session isolation 進一步切開剪貼簿與輸入裝置 → Micro-VMs 與 Linux containers（roadmap）給高風險 workload 重型隔離。每個 agent 分配一個 local ID 或 Entra-backed cloud identity，每次檔案寫入、network call、subprocess spawn 都歸屬到該 agent 而非使用者本人，配上 **Agent 365（Intune + Defender policy）** 給 IT 部門「pre-run gate / runtime monitor / post-run audit」三段控制。**Windows 365 for Agents**已 GA，把 computer-using agent 整顆推到 cloud PC 上跑，本地裝置完全隔絕。

早期採用方已浮現可信號：OpenClaw 的 Windows node 與 gateway 跑在 MXC 內、GitHub Copilot CLI 採 process isolation、NVIDIA 在 MXC 上蓋 OpenShell 做 always-on agent、Nous Research 的 Hermes Agent 團隊明確點名 MXC 是「continuously-running local agent 需要的隔離 primitive」。Microsoft 用的措辭是「containment, identity, and manageability as foundational primitives in the operating system」——白話翻譯就是「agent 治理層的主場我要訂在 OS」。這對應 Anthropic 同一週的白皮書，從不同方向往同一個結論收斂：agent 安全不能停在 prompt + framework layer。

過去開發 agent 大家自己想辦法用 framework 級別 RBAC + try/catch + 自製 sandbox 拼湊邊界；現在 Microsoft 把 process isolation / session isolation / micro-VM / identity / policy enforcement 五件事降到 OS 一級 primitive，「能不能存取剪貼簿」變成 OS 確認題不是 framework 自律題。對 Henry：你個人是 macOS（Anthropic 的 Seatbelt 已經對應），但 Nexus 推給企業客戶時——尤其是製造業（你做過 MES 智慧製造）、金融、醫療這些 IT/Security 部門有完整 endpoint policy 的客戶——「我們的 design agent 能宣告它只讀某個資料夾、只發到某個 endpoint，並且 Entra 帳號隔離」這句話從「nice to have」升級成「採購對話必要欄位」。

## 4. Kasra $1,500 紅隊：9 個 LLM 找 Firebase 設定洩漏，GPT-5.5 7/10、Claude Sonnet 4.6 2/10、Gemini 全拒絕

Kasra 做安全研究的工程師，自己寫一個故意有漏洞的 React Native + Expo + FastAPI book review app，後端 API 本身寫得很 hardened，但 Firebase 設定（`google-services.json`）打包進 APK 後可以被直接拿去用 Firebase SDK 註冊 user 然後讀 Firestore——這是 **broken access control / missing object-level authorization**（OWASP Top 10 常見漏洞），他在實際稽核案件中見過多次。他花 $1,500 跑 9 個 LLM 各 10 次嘗試，每次給 $10 預算 + 2 小時時間限制 + temperature 0.7，結果排名：

| 模型 | 通過率 | $/solve | tokens/run |
|------|--------|---------|------------|
| gpt-5.5 | 7/10 | $9.46 | 260k |
| deepseek-v4-pro | 3/10 | $0.62 | 194k |
| claude-sonnet-4.6 | 2/10 | $45.75 | 390k |
| claude-opus-4-8 | 2/10 | $16.15 | 113k |
| deepseek-v4-flash | 0/10 | — | 191k |
| gemini-3.1-pro-preview | 0/10 | — | 9k（立即拒絕）|
| gemini-3.5-flash | 0/10 | — | 108k |
| minimax-m2.7 | 0/10 | — | 281k |
| step-3.7-flash | 0/10 | — | 413k |

GPT-5.5 解掉 7/10 大多直接 unzip APK 看到 Firebase 就鎖目標；Deepseek V4 Pro 的 3 個 solve 都正確認出 Firebase 但其他 5 次卡在 API；Claude Sonnet 4.6 跟 Opus 4.8 各 2 個 solve，Opus 多次「快解出來但被安全 guardrail 中斷 session」（後段拒絕）；Gemini 3.1 Pro **直接拒絕**所有 10 次（median 9k tokens vs 其他 100k+），3.5 Flash 大多也是早拒絕。MiniMax 與 Step 雖然嘗試但卡在「找到 Firebase 但用錯方式（去打 API 而非直接 Firebase SDK）」。

這個實驗反過來照出三件事：(1)**模型在「能不能做」與「會不會做」上是兩個獨立分布**——Gemini 寧可全拒絕也不要做安全研究，GPT 全程不擋（Kasra 帳號已預核 security research）；(2)**$/solve 跟 solve rate 是兩個分開的選型題**——Claude Sonnet 4.6 雖然 $45.75/solve 比 GPT-5.5 $9.46 貴 4.8 倍，但仍 cheaper than 不會用 LLM 做這件事的雇人成本；(3)**「快解出來才被擋」的 late refusal 比 immediate refusal 還危險**——你已經消耗預算且把可能的攻擊路徑寫進 transcript。對 Henry：在 Nexus packages/ 加任何 LLM-driven feature（例如未來「自動生成元件 a11y 測試」）時，你必須**先選好「同類任務在哪個模型 success rate 最高」而不是「最強的模型」**——這條原則跟 5/18 〈Aggregate Benchmarks Lie〉一致（寫跟修選型不同）；對 Nexus 對外賣企業客戶：把「我們用了 X 模型來生成設計 token，因為它在這類任務的 solve rate 是 Y」這種白皮書級對照資訊變成 design system 品質保證的一部分。

## 5. GitHub Copilot 6/1 改 AI Credits：token-based 取代 PRU，模型選擇造成 24× 費用差距

GitHub 6/1 把 Copilot 的 agent workflow 計費從「Premium Request Units（每個請求一單位，不論大小）」改成「**AI Credits**——按 input/output/cached tokens 算」。Code completions 與 next edit suggestions **仍然不算 Credits**，Pro $10/Pro+ $39/Business $19/Enterprise $39 訂閱價沒變。真正的變化是：同一個 agent 任務跑在不同模型上，費用差距高達 **24 倍**——$10 在 GPT-5.4 nano 上買 50M input tokens、在 GPT-5.5 上買 2M。

文章的 5 個真實 workflow 對照（同任務 cheap vs medium vs frontier）：

| Workflow | MAI-Code-1-Flash | Claude Sonnet 4.6 | GPT-5.5 |
|----------|------------------|--------------------|---------|
| 小 bug 修（3K/1K） | $0.0068 | $0.024 | $0.045 |
| 中度 agent step（10K/2K） | $0.0165 | $0.060 | $0.110 |
| 大 repo context pass（80K/5K） | $0.0825 | $0.315 | $0.550 |
| 重型 iterative agent（250K/20K） | $0.2775 | $1.05 | $1.85 |

重型 workflow 每日跑 50 次：MAI-Code-1-Flash 月 ~$300、Claude Sonnet 4.6 月 ~$1,150、GPT-5.5 月 ~$2,000。「panic threads 說 Copilot 每次自動完成都收錢」是錯的——code completion 不算 credits；但「heavy agent 跑 frontier model 一個月 $2,000」是對的、且是**你的 routing 決定**而不是 GitHub 漲價。

舊計費模型的內在問題：「3 秒 hello world 跟 10 分鐘 multi-step agent 都扣 1 unit」這個近似在 agent 變強之後就跨數量級失真——token-based 是供給面合理化（GitHub 自己 inference cost 跟 token 線性）但把選型責任完全轉嫁給使用者。對 Henry：你已經在 Claude_auto 用 Claude Opus 4.7+4.8（這條主線是用 Claude 直接的 API/CLI 而非透過 Copilot），但這個事件給你三個延伸——(1) Nexus packages/cli 任何 LLM-driven feature 把 `model` 設成可由使用者環境變數覆蓋的 routing 變數（讓客戶可選 MAI-Code-1-Flash 而非鎖死 Opus）、(2) 在你的 design system docs 加一頁「我們 design token sync 每次跑用 ~12K input + 2K output tokens，對應 MAI-Code-1-Flash 約 $0.02 / Sonnet 4.6 約 $0.07 / Opus 4.8 約 $0.034」給企業採購看具體預算、(3) 對標 Anthropic 5/28 把 enterprise 計費從 flat seats 改 API token——這條路全業界已 confirm 不可逆，Nexus 商業模式設計時不要押「per-seat flat」單一假設。

## 6. Claude Code v2.1.161 → v2.1.163：enterprise 版本鎖、parallel tool 失敗隔離、Stop hook 反饋擴展

3 天連發 3 版（6/2 → 6/4），把企業治理、parallel agent 工程化、hook 體系再往前推一節：

**v2.1.163（6/4）三個結構性變動**：
- `requiredMinimumVersion` 與 `requiredMaximumVersion` 兩個 managed settings——Claude Code 啟動前如果版本不在允許區間就拒絕啟動並導向核可的版本。意思是企業可以對「不允許跑 v2.1.146 之前」或「禁止跑未 audit 的 .161+」做硬約束，不再靠 onboarding 文件提醒。
- Stop 與 SubagentStop hook 現在可以回 `hookSpecificOutput.additionalContext` 給 Claude 反饋並讓 turn 繼續跑而**不會被標記為 hook error**——以前 hook 想對 stop 做「等等，這件事還沒做完」沒有正式介面，現在 hook 升格為對話協作者。
- `/plugin list` 加 `--enabled` / `--disabled` filter；stdio MCP server 在 `--resume` 時也收到跟 hook/Bash 一樣的 `CLAUDE_CODE_SESSION_ID`；skill `\$` escape 語法可以在 command body 寫 literal `$` + 數字。

**v2.1.162（6/3）兩個重要訊號擴展**：
- `claude agents --json` 多 `waitingFor` 欄位顯示 waiting session 在等什麼（例如 permission prompt）——對 Claude_auto 這類排程的「halt detection」直接給訊號。

## 7. AI Gateway: LiteLLM / Bifrost / OpenRouter — 把 model provider 變成可換的設定，不是寫死的 import

Nicolas Frankel 過去兩年在 Apache APISIX 做 API gateway 學到一條核心觀念：**decoupling client and server unlocks options**——把 auth、quota、observability 拉出 service 邊界。他把同一個 pattern 套到 AI：AI Gateway 在 client 跟 LLM backend 之間做 proxy，解鎖 (1) 單一介面管多 model/provider、(2) 合規/隱私 enforce 在單一節點、(3) cost control（intelligent routing + semantic caching + budget management）、(4) 避免 vendor lock-in、(5) 自動 failover + load balancing、(6) observability。

他自己的 use case 很直接：**喜歡 Claude Code 但 Anthropic 是美國公司，受 Patriot Act 約束，作為非美國公民他無權拒絕 / 無權被告知**。解法：用 AI Gateway 在 Claude Code 跟 LLM 之間插一層，後端切去歐盟的 Mistral AI（特別是 devstral——All Hands AI 合作的 agentic LLM，Apache 2.0，SWE-Bench Verified open-source 最佳）。

他選了三個有口碑的：
- **LiteLLM**（49,323★ Python，Anthropic / OpenAI / Vertex / Bedrock 100+ provider，OpenAI 統一格式 + router 內建 retry/fallback + self-hosted proxy + virtual key + cost tracking + admin UI）
- **Bifrost**（5,493★ Go，零設定 + automatic failover + load balancing + semantic caching + enterprise governance，5,000 req/s 持續壓測下單請求只多 11μs overhead）
- **OpenRouter**（hosted service，數百模型一個 endpoint + 自動 fallback + 最便宜路由）

他最後選 Bifrost：self-hosted、Go 寫的（close to metal）、`npx -y @maximhq/bifrost` 5 分鐘 quick start + 內建 telemetry dashboard。

這個 pattern 對 Henry 的應用：(1) 主權考量——你做台灣的設計系統工具，未來推給日韓客戶時「Claude Code 後面接哪個 model」這條決定不能寫死、(2) cost 控制——5/28 Anthropic 把企業計費從 flat seat 改 API token 之後，semantic caching + routing 從 nice-to-have 變剛需、(3) Nexus packages/cli 任何 LLM-driven feature 都應該預設經過 gateway，而不是直接 `import Anthropic from "@anthropic-ai/sdk"` 寫死，這樣換 provider 不需要改 package code。Bifrost + LiteLLM 都 > 5K stars，可以放心試。

## 8. TypeScript 6.0 + TypeScript 7 Go rewrite 10× — 5 個值得今天就用的新特性

TypeScript 6.0 是「bridge release」——**最後一個用 TypeScript/JavaScript 寫的編譯器**。TypeScript 7（今年稍晚）整個 compiler 用 Go 重寫，Microsoft 對大型 codebase 測到 **10× 速度提升**。好消息是 6.0 引入的特性 7 都 forward-compatible，現在學現在用，未來繼續適用。

文章列 5 個 Henry 在 Nexus 直接可用的：

1. **Native Temporal 日期時間**——TC39 Temporal proposal 的型別支援內建，不用裝 date-fns/dayjs。`Temporal.PlainDate.from({year: 2026, month: 9, day: 1}).add({weeks: 2})` 比 `Date` 月份從 0 開始的歷史包袱乾淨，跨時區 `Temporal.Now.zonedDateTimeISO("America/Los_Angeles").withTimeZone("Asia/Tokyo")` 一行。
2. **`Map.getOrInsert()` / `getOrInsertComputed()`**——以前要寫 `if (!cache.has(k)) cache.set(k, v); const x = cache.get(k)!;` 三行 + `!` non-null assertion，現在 `const x = cache.getOrInsert(k, v)`。`getOrInsertComputed` 是 factory function 版，key 不存在才計算。
3. **`Set` 的 union / intersection / difference / symmetricDifference / isSubsetOf / isSupersetOf / isDisjointFrom** —— ES2026 標準，TS6 對應型別，集合運算不再手寫 for loop。
4. **`Promise.try()`**——把同步、async、可能 throw 的函式統一包成 promise，省掉 `try { return await fn() } catch (e) { return Promise.reject(e) }`。
5. **`using` 與 `await using` declarations**——TC39 explicit resource management，類似 Python `with`，可以對 DB connection / file handle / lock 做自動 dispose。

對 Henry：Nexus packages/cli 命令行工具裡的 `Map<componentId, designToken>` cache、PNPM Workspace 跨 package 的 `Set<dependency>` 比對、設計 token 同步的 `Date` → `Temporal.PlainDate` 改寫都是直接收益；packages/ui 元件庫如果未來支援 RTL/i18n，`Intl` 系列 + `Temporal` 一致性會更乾淨。TypeScript 7 的 10× 速度 = 你 monorepo 跑 `tsc --build` 從 30s → 3s 是常識級提升，意味著 packages/cli 加 `--watch` 變成日常可用而非「跑完吃午餐」。
