## Ornith-1.0 547★ MIT——RL 同時學「方案」跟「跑出方案的鷹架」，397B MoE 在 Terminal-Bench 2.1 跑 77.5%

你跑 agentic coding task（close 一張 ticket、跨檔 refactor、補 missing test）想換掉 frontier API，DeepReinforce 釋出 **Ornith-1.0 MIT 開源四尺寸（9B-Dense / 31B-Dense / 35B-MoE / 397B-MoE）**，基底 Gemma 4 + Qwen 3.5。Benchmark：**397B MoE 版 Terminal-Bench 2.1 77.5%、SWE-bench Verified 82.4%、NL2Repo 48.2%**；**35B MoE Terminal-Bench 64.2%、SWE-bench Verified 75.6%**。整合 OpenHands / Hermes Agent / OpenCode / OpenClaw / llama.cpp / Ollama 全 OpenAI-compatible 端點。HN 6/30 156 點 32 留言。

設計核心翻轉：**RL 不只學「答案」，同時學「跑出答案的鷹架」**。論文原話 "RL to learn to generate not only solution rollouts, but also the scaffold that drive those rollouts"——傳統 SFT 學從 prompt → solution 一段映射，Ornith 學從 prompt → (scaffold, solution) 兩件事一起最佳化。Scaffold = agent 跑 tool call 的順序、retry 策略、cross-file context 管理、failure recovery 模式。把兩件事縫成同一個 RL 目標函數，base model 自己知道「這個 task 該先 grep 再 read 還是該先 read 再 grep」「retry 時要不要切 model」「subagent fan-out 該幾條 path」，不靠工程師手寫 harness 規則。對標 6/29 Semgrep IDOR benchmark「harness 設計（cross-file index + multi-pass + RAG）才是真正槓桿、base model 差距會被吸收」洞察——Ornith 把那條洞察推到下一層，**harness 結構本身變 RL 學習對象**，過去 base model 跟 harness 是兩個 team 兩個產品，今天起 base model weights 內含「自帶 scaffold 智能」。

以前 Henry 寫 Nexus packages/cli `add/sync/migrate` 三命令是純 imperative bash + TS，AI 生成的 migration code 失敗時要 Henry 自己寫 retry / dry-run / git stash 順序——今天 Ornith 證明「scaffold 跟 solution 一起學」可行，意味未來 packages/cli migrate 命令的 retry 策略不必工程師手寫 if-else，可以從 base model 直接吐出「先 storybook diff 再 git stash 再跑 migration」的順序。對應 6/26 Scorer vs Decider「LLM 不做決策只打 4 軸分數 + 60 行 TypeScript decider」設計——今天 Ornith 把 decider 的「跑哪個 scaffold」這條決策也搬進 RL，過去 scaffold 是 decider 寫死的 procedure，現在 scaffold 變成 model 自己生成的 first-class output。Nexus packages/ui PR review 過去手寫 reviewer + arbitrator 兩 subagent（6/29 antoine MRI 條目）能不能用 Ornith 35B MoE 一個 model 自己跑出「分兩 subagent 互審」的 scaffold，是 2026-Q3 值得 PoC 的方向。

## Claude Code v2.1.196——streaming watchdog default-on / .mcp.json untrusted 不再 self-approve / /code-review 砍 25% tokens

你 Claude_auto 排程任務跑跨晚 fetch + journal 寫入，過去 streaming 卡死要等到下次手動進來才補刀，**今天 v2.1.196（6/29 23:27 UTC release）把 streaming idle watchdog 設預設開啟**——response stream 5 分鐘內沒任何事件自動 abort + retry，環境變數 `CLAUDE_ENABLE_STREAM_WATCHDOG=0` 才能關掉。同時 `/code-review` workflow 把 5 個 cleanup finder（trailing whitespace、unused import、commented dead code、TODO without ticket、duplicate string literal）合併成單一 prompt 一輪過，token 用量降 **~25%**。安全面三件 enforce：**`.mcp.json` sandbox 強化**——`claude mcp list`/`get` 不再 spawn 被 repo 自我審核（committed `.claude/settings.json` approving 自己的 `.mcp.json`）的 server；**Untrusted workspaces** 顯示 `⏠ Pending approval` 狀態；**Remote Control 在 ANTHROPIC_BASE_URL 指向非 Anthropic host 時 disabled**（跟 `CLAUDE_CODE_USE_BEDROCK` / `_VERTEX` / `_FOUNDRY` 既有行為對齊）。其他 polish：background job 跨 wake 不再掉 transcript file、background session 長任務跨 process restart / Windows handed-off shell 撐得住、`/deep-research` verifier failure 不再誤報「all claims refuted」改報 `unverified`。

## vLLM Micro-Agent——multi-agent collaboration 從應用層搬到 serving layer，5 loopers 在單一 API call 內跑

你過去寫 multi-agent collaboration 要在應用層手寫 fan-out / 投票 / 重試 / synthesis 全部邏輯（RxJS forkJoin + Promise.all + 自寫 quorum 判斷），**vLLM Semantic Router team + AMD 釋出 Micro-Agent 把整層搬到 serving layer**——使用者 call `vllm-sr/auto` 一個 endpoint，背後 router 自動「fan out 到 workers / 收 quorum / 驗 disagreement / synthesize 最終答案 / 修 output contract / 回一個 OpenAI-compatible response」。**5 種 looper pattern**：**Confidence**（sequential 升級配信心 threshold）/ **Ratings**（parallel 跑帶 concurrency cap）/ **ReMoM**（fan-out + synthesis + fallback）/ **Fusion**（panel 答案讓 judge 分析）/ **Workflows**（bounded multi-step agent）。Benchmark：**LiveCodeBench 92.6**（vs Fugu Ultra 92.0）/ **GPQA-Diamond 96.0**（vs 95.5）/ **Humanity's Last Exam 50.0**（同 Fugu Ultra）。HN 6/30 53 點 18 留言。

設計核心翻轉：「multi-agent collaboration 設計責任」走到第三格。**第一格**「應用層手寫」（你寫 Promise.all + 自寫投票邏輯）→ **第二格**「SDK 抽象」（Claude Agent SDK / OpenAI Agents SDK 封裝 spawn / await / aggregate）→ **第三格**「serving layer 內建」（vllm-sr/auto endpoint 一個 call 解決所有 multi-agent 機制對使用者透明）。客戶端只看到 standard OpenAI chat completion API、回的也是普通 response，內部 fan-out 多 model / 跨 model 投票 / 失敗重試 / 結果 synthesize 全部對 application code 不可見。這跟 6/29 antoine MRI multi-subagent arbitration 是同樣 collaboration 設計 idea 但實作搬到不同層——antoine 的是「application 端跑 Claude Code subagent 平行打 raw 判斷」、今天 Micro-Agent 是「同樣 panel + judge 思路在 serving layer 內建一個 endpoint 解」。

以前 Henry 規劃 Nexus packages/ui PR review pipeline 要拆 reviewer + arbitrator 兩階段 Claude Code subagent（6/29 條目）+ MES 戰情室 ECharts 異常 alert 要用 RxJS forkJoin 並行打多個 model 取共識——今天 Micro-Agent 證明這兩件事都可以塌成「choose looper + call vllm-sr/auto」：PR review 接 Fusion looper（panel + judge）、alert pipeline 接 Confidence looper（低信心自動升級到 frontier）、Claude_auto Step 2a Scorer/Decider 接 Ratings looper（並行打分帶 concurrency cap）。架構選擇從「自己拼 collaboration」翻「廠商 endpoint 拼好給你」，省掉 RxJS forkJoin + Promise.all + 自寫投票邏輯三層 application code。對應 6/26「黑盒判斷被翻可審計合約」+ 6/29「verdict / decision 跨 context 顯式可審計」兩條洞察今天加第二維——**collaboration 設計也要 first-class 化跨層**，過去 collaboration 是「應用層責任」現在升格「serving layer 可選 endpoint」可量化工程選擇而非單一實作模式。
