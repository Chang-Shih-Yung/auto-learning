## 1. Recall — Claude Code 本地專案記憶外掛

第一段：你能做什麼

你跑 Claude_auto SKILL.md 跑了一週後，每次 session 開頭要花 1-2 分鐘從零交代「我這個 repo 在做什麼、上次跑到哪、要避免哪些坑」。Recall 接到 Claude Code 後，每個 session 自動把你的 prompt、Claude 回應、改動的檔案、跑過的命令寫進專案目錄底下的 history log，session 結束用本地 TF-IDF + TextRank 把整段 transcript 壓成 1-2K tokens 的 context 摘要。下一次 session 啟動，Claude 自動讀摘要問你「上次到這裡，要繼續嗎？」整個壓縮過程不打 API、不上雲、全在你 M2 Mac 上跑。

第二段：背後怎麼運作

關鍵是「extractive 而不是 generative summarization」。TF-IDF 算每個句子在當前 transcript 跟整體語料的詞頻反差，TextRank 把所有句子當圖節點互相投票排重要性。兩個演算法都不需要 LLM 推理，純算術——所以零 API 成本、零等待。Recall 還做了三層安全：secrets redaction（API key 自動去掉）、git execution hardening（不亂跑 git push --force）、confined writes（只寫專案目錄）。整個外掛是 Pure Python，NumPy 是可選的加速器，不裝也能跑。

第三段：這改變了什麼

以前你想讓 AI agent 跨 session 記憶有兩條路：(1) 開 Anthropic API 跑 Claude 自己壓縮 conversation history 每次 session 燒 5-10K tokens、(2) 自己寫 prompt「上次我們做了 X、要繼續 Y」手動 maintain。現在 Recall 把第三條路打開：本地、零成本、自動。對應 6/18 rapls「agent got dumber mid-session」量化 conversation history 占 ~20% context 浪費——Recall 是這個觀察的直接工程化解法。

## 3. Claude Code Agent Loop 1,400 行的工程拆解

第一段：你能做什麼

你寫 Claude_auto SKILL.md 寫了三個月，知道一個 agent loop 表面上很簡單：呼叫 LLM → 執行 tool → 重複到完成。Laxmena 把 Claude Code 的 agent loop 反編譯，發現 production-grade 寫到 1,400+ 行，原因是九個失敗模式：network timeout（指數退避 10 次）、incomplete response（撞 output token 上限）、context warning（注入預算警告）、proactive compaction（四種策略主動壓縮）、reactive compaction（413 緊急回退）、sub-agent completion（父迴圈接續子 agent）、stop hook override（治理層強制續跑）、blocked tool calls（denial hook 注入結果），加上正常的 tool execution。

第二段：背後怎麼運作

最關鍵是 single-threaded design——Claude Code 刻意不平行跑 tool 換取決定性正確，沒有競態條件但 bash 卡住會凍住整個 terminal。第二個關鍵是 async generator pattern——loop 把 token、tool call、result 即時 yield 到終端，配合 prompt caching 達成「逐字渲染但底層用 cache 不重算」。第三個觀察是 context cost——session 還沒打字就吃 8,000-12,000 tokens（system prompt + tool definitions + CLAUDE.md），在 32K context window 上等於 25-37% 已被吃掉。Compaction pipeline 順序明確：先跑便宜的 truncation/deletion，最後才跑昂貴的 model-based summarization。

第三段：這改變了什麼

以前你看 Claude_auto SKILL.md 的「Step 1-7」覺得它是 procedure；現在看完這篇你會知道每個 Step 背後其實有九個 failure mode 在暗中保護你。對應 6/11 CLI-over-MCP 的「MCP tool definitions +5k tokens/turn baseline」+ 今天的「8-12K tokens 開機成本」——你的 Claude_auto 在 200K context window 上開機成本佔比約 6%，比 32K window 上 37% 健康得多，但 session-log 隨累積會推升占比。直接行動：把 SKILL.md frontmatter 加上 `context-budget-warn: 30%` 觸發 Recall 風格的 extractive compaction。

## 5. Sandi Metz「Prefer duplication over the wrong abstraction」LLM 時代重讀

第一段：你能做什麼

你 Nexus packages/ui 60% 元件由 Claude 生成，AI 寫程式速度快，但「找出重複 pattern → 抽出共用元件」這個動作 LLM 也快——快到容易在第二次相似請求就立刻抽象。Sandi Metz 2016 年的文章今天在 HN 衝到 428 點 294 留言重新爆紅，核心警語：「duplication is far cheaper than the wrong abstraction」。她描述四段失敗序列：(1) Programmer A 看到重複抽出 abstraction、(2) Programmer B 遇到 90% 相似但不完全 fit 的需求加 parameter + conditional、(3) Programmer X 重複 B 的動作層層疊 conditional、(4) 你接手一團亂麻。

第二段：背後怎麼運作

Metz 的觀察是 sunk cost fallacy 在程式設計裡的具體形式：一旦 abstraction 存在，下個開發者本能保留它（不想浪費前人努力），用 parameter + if/else 強制塞新需求。她的反向處方是：「當你看到 parameter + conditional 開始累積，就 inline 回去」——把 abstracted code 拆回各個 caller、刪掉跟那個 caller 無關的部分、從乾淨結果重新提取真正簡單的 abstraction。核心句：「When the abstraction is wrong, the fastest way forward is back.」

第三段：這改變了什麼

以前這篇是 OOP 時代的設計建議；今天在 LLM 時代意義升級。當 Claude 一晚可以寫 10 個 Button 變體，「看到第二個就抽 BaseButton」這個本能會在 AI 速度下放大成災。對應你 Nexus packages/ui Button + AnnotationCard + Card 等 60% AI 生成元件——直接行動：在 SKILL.md 加一條「LLM 生成的相似 pattern 連續出現 3 次以下，不要立即抽象；先 inline 跑兩週累積真實 variance signal 再決定」。把 wrong abstraction 的成本（重構難度高、conditional 爆炸）寫進 design system 設計原則，比抽象本身更重要。
