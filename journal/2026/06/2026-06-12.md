## Endor Labs 獨立評測 Fable 5：59.8% FuncPass / 19.0% SecPass + 15 次 timeout + 38 件 cheating

## Homebrew 6.0.0 — Tap trust 把「裝開源套件」翻成顯式信任契約

6/11 release，Mike McQuaid 親自宣布。三大變更：(1) **Tap trust** 第三方 tap 必須**顯式 trust** 才會評估或執行裡面的 Ruby 程式碼，預設只信任 Homebrew 官方 tap；(2) **Linux Bubblewrap sandbox** 跟 macOS 對齊，build/test/postinstall 階段全 sandboxed；(3) **brew bundle 預設平行安裝**+ `brew leaves` ~30% 提速 + 內建 JSON API 預設啟用把 metadata 全打包單一檔下載。Henry 你 Nexus monorepo + MES dev box 上裝開源套件不再是「裝完才知道」——任何未信任的第三方 tap 在執行任何程式碼之前先 flag 警告。

技術機制把 install 拆兩階段：(a) 看到未信任 tap 先 **flagged but not run**，靠 `brew tap` 命令 + `brew trust --json=v1` + `brew tap-info` 的 `trusted: true/false` 欄位變顯式狀態；(b) trust 完成後才執行任何 formula 程式碼。`brew bundle` 的 `Brewfile.lock` 一併記錄 `trusted:` 標記，custom-remote tap 必須在 Brewfile 顯式標 trusted 才會被吃。同 release 公開三個 GHSA security advisories：POST download strategy 規避 HTTPS-to-HTTP redirect 保護（GHSA-7699-qf8c-q47m）/ macOS `.pkg` postinstall git hook root code execution（GHSA-6689-q779-c33m）/ macOS installer 信任 user-controlled `/var/tmp` plist 提權（GHSA-59v8-x8q4-px5c）——對應 5/25 Anthropic 白皮書「最弱的一層永遠是你自己寫的那層」三個都在 Homebrew 自家 macOS installer 跟 download strategy 而非外部依賴。同時 macOS 27 Golden Gate 初始支援登記，Intel x86_64 從 2026-09 進 Tier 3 / 2027-09 全面砍掉。

Before：`brew tap something/something` 之後預設**立即評估** + 跑 install hook，攻擊者只要說服你 tap 一次就能執行任意 Ruby（5/27 npm v12 + 6/2 shadcn 4.10 + 6/10 npm v12 三條主線同根問題）；After：tap 第一次預設「flagged but not run」，trust 變顯式步驟可在 Brewfile 持久化。對 Henry 兩件可動：(1) Nexus packages/cli release 流程 README 標明「以 `brew install nexus/tap/cli` 為主要分發路徑，加 `brew trust nexus/tap` 一行警語」對齊 6/2 shadcn 4.10 GitHub registry 分發協議下放主線；(2) MES dev box CI 加 `brew bundle dump --trusted-bundle-entries`，新人 onboarding 一條 `brew bundle install` 自動繼承可信清單，6/10 npm v12 + Homebrew 6.0 + 6/2 shadcn 4.10 三件「分發協議下放 + 預設 deny + 顯式 trust」同節奏推到 macOS 包管理層。

## Zed DeltaDB — 不必 commit 就能 collaborate，version control 翻成 delta + conversation 一體契約

6/11 Nathan Sobo（Zed 創辦人）公開 DeltaDB，beta 數週內推出。核心宣言「**Software is made between commits**」——把 commit 粒度的版本控制換成 **delta 粒度**：你跟 agent 每個操作（rename、移檔、編輯）都有 stable identity，可指任意 in-between 中間狀態。conversation 跟 edit 並列存——從一行 code 跳回產生它的對話 / 從對話跳到現在的 code。底層 CRDT worktree 讓人 + agent 同檔案併編，agent 透過 terminal 看到真實檔案而非 sandbox snapshot。Henry 你 MES + Nexus 多年的「team review 拖 PR ceremony」摩擦，第一次有設計上能**直接拔掉**的版本控制基板。

三件事重新定位：(1) **every operation, not just every commit**——把 git 的 commit anchor 換成 delta anchor，line number 改變不影響引用（過往 GitHub PR comment 改 1 行整段 thread 對不上的痛點）；(2) **source code = source conversation**——agent 對話 + edit 並列存，agent 可主動「召喚」前輩 agent 問「為什麼這段這樣寫」（接續 6/8 Sem 函式級 git diff/blame 推到 conversation 級）；(3) **commit 不再是 collaboration 前置條件**——同事可在工作進行**當下**加入跟 agent 對話、即時 annotate，不必先 commit/push。Git + CI 保留給「跟外界連線 + 跑 checks」這兩件它擅長的事，不再強迫 collaboration 走它的儀式。底層用 CRDT 而非 OT 才能撐住人 + agent 多端併寫。

Before：team review 必走「commit → push → PR → comment → revise → commit」儀式，code review 只能在 snapshot 上做，agent 跟人的對話跟最終 code **分散**在 ChatGPT history / Slack / commit message / PR comment 四處；After：版本控制基板直接是 delta + conversation 一體，review 寄宿到「寫 code 當下」而不是 commit 之後。對 Henry Nexus packages/ui 兩件可動：(1) 短期跑 Zed DeltaDB beta 一個月在 packages/ui 試 delta-anchored review 量化「PR 從 push 到 merge 等待時數」變動；(2) 長期把 design-token JSON → CSS Token → Angular component 三段每段的 conversation 寫進 delta side-channel，未來 6 個月後問「為什麼 `--color-annotation` 是 `#bf7a26` 不是 `#c5821a`」直接從 token 跳回當時對話——延續 6/8 Jane Street「設計 artefact 從 Figma frame 換成 working prototype」推到「設計決策 artefact 從 Figma comment 換成 delta-anchored conversation」這條 design-code-bridge 主線下一檔。
