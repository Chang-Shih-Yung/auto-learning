## Claude Code v2.1.193——autoMode.classifyAllShell 把 Bash 權限從子字串比對升到意圖分類

你跑 Claude_auto 排程任務時，在 `settings.json` 加一行 `autoMode.classifyAllShell: true`，所有 Bash / PowerShell 命令——不管你之前怎麼寫 `Bash(command:rm*)` deny、`Bash(command:git push --force*)` deny——**一律先過 auto-mode 分類器判斷意圖再執行**。2026-06-25 21:45 UTC release，補的是 6/16 v2.1.178 `Tool(param:value)` 子字串擋 `rm*` 的漏網之魚：以前攻擊者可以靠 `Bash(command:bash -c "rm -rf ...")` 或 `Bash(command:sh ./x.sh)` 包一層繞過，子字串看不見執行時真實意圖；今天分類器先看「這條命令最終會做什麼」（檔案刪除 / 網路存取 / git destructive operation）再決定 deny / ask / allow。同版本另外四件：閒置背景 shell 命令自動釋放記憶體（接續 v2.1.191 streaming CPU -37% 同方向），MCP server 認證 401/403 自動重連（過夜斷網醒來不用從頭跑 OAuth），bash mode（`!`）加 live file path 自動補全（敲檔名不用切回 IDE 查路徑），`claude_code.assistant_response` OpenTelemetry log event 預設 redact——`OTEL_LOG_ASSISTANT_RESPONSES=1` 顯式打開才會 log 完整回應，把 sensitive output 外洩風險定為 opt-in。

技術上「permission 從靜態子字串列表升到動態 classifier 判斷」是這版的結構性變動。v2.1.178 的 `Bash(command:rm*)` 是 glob 子字串比對，attack surface 在於「同樣的破壞性動作可以有無數個拼寫變體」——子字串只認字面，攻擊者順手包一層 `bash -c "..."` 就過。v2.1.193 把 Bash 命令處理流改成兩段：classifier 先解析命令會展開成什麼（包含 shell 內 variable expansion、aliases、pipe 串接後的最終效果），命中危險動作就觸發 deny 或對話框確認。同樣思路推到 background shell：v2.1.181 修好 cloud-synced drive 寫檔截斷、v2.1.191 streaming CPU 砍 37%、今天再修「長 session 背景 shell 佔記憶體不釋放」——把「跑得起來」推到「跑得起來 + 不佔不該佔的資源」連續三版同節奏。MCP 401/403 自動重連是接續 v2.1.186 `claude mcp login --no-browser` headless 路徑——前者把首次認證搬到 SSH，今天把 token 過期後的 transient recovery 補上，整條遠端 MCP 流程從「裝得起來」推到「裝起來不會半夜失敗」這條軸再往前推一格。

## agmsg——multi-agent 協調 substrate 從「protocol daemon」砍到「一個 SQLite 檔」

你跑 Nexus packages/cli 重構任務時，過去要在三個 terminal 來回複製貼上前一個 agent 的輸出當下一個 agent 的輸入。agmsg 把這條流程翻成 **shared SQLite database**：每個 agent 進同一個「room」（一個 .db 檔），post message 寫一筆 row，下一個 agent 讀 thread history 接續工作。**整套 ~500 行 bash + SQLite**，no daemon、no network、no Python——一個 shell 腳本一個 SQLite 檔就完成 multi-CLI agent 通訊。支援 Claude Code / OpenAI Codex / Google Gemini CLI / GitHub Copilot CLI 四種主流 agent，同 room 可以多個同款 agent 並存。GitHub 上 fujibee/agmsg，**stars 從 5 跳到 320+** 後被日本 community 推上 ProductHunt 與 HN（搜尋熱度週升）。Demo 兩個 agent 自動下完一整局 tic-tac-toe 沒人介入——證明 substrate 本身夠穩到不需要 protocol-level 仲裁。

為什麼用 SQLite 當 substrate？三層原因：**Write serialization 內建**——多個 agent 同時寫不會掉訊息，SQLite 一次只讓一個 writer 進、其他 writer 排隊，對 multi-agent 場景天然防 race。**rowid 跟 timestamp 天然 ordering**——agent 拿 thread history 直接 `SELECT * FROM messages ORDER BY rowid` 拿到正確順序，不用自己包 logical clock。**一個檔案就是一個 room**——複製 .db 檔就是 fork 整段對話、刪檔就是結束 room、git 加版就是 audit log。設計刻意不做 protocol-level turn-taking：誰該說話、什麼時候輪到 agent X，由 agent 自己 prompt 決定（「如果上一條訊息是 Claude 寫的就回應，否則 wait」），substrate 只負責保證訊息順序跟不掉訊息。對比 MCP server 需要 daemon + WebSocket + schema 註冊 + OAuth flow 四件 substrate cost，agmsg 把 multi-agent 協調的 substrate cost 砍到「一個 SQLite 檔」的最小可用底線——對應 6/11 CLI-over-MCP「MCP +5k tokens/turn baseline」洞察推到 substrate 層，substrate 不打折但 schema 自然零。

以前 Henry 的 Claude_auto SKILL.md 是單 agent 跑 Step 1-7 一條線——session 結束就 `/clear`、下一次 session 從頭再來，每階段都用同一個 Claude 模型。agmsg 開出第二條路：fetch 階段跑 Claude Code（強 web fetch + 整合 MCP）、filter 階段跑 Gemini CLI（強長 context 篩選，1M context 在這條軸對應 6/18 GLM-5.2 1M 同尺度）、write 階段跑 Codex（強 code generation），**三個 agent 共用同一個 SQLite room**，每階段 hand off 透過 thread history 而非 prompt 重組。SQLite room 同時當 session-log.md 一級資料來源——過去 session-log.md 是 Claude 自己寫的「我做了什麼」摘要，今天可以從 .db 撈出真實 thread history 當 trace contract（對應 6/23「LLM-as-judge 0.85 vs trace-based 0.000」洞察推到 self-evaluation 層）。對應 6/12 MiMoCode「Import from Claude Code 一行 switch CLI」+ 6/18 GLM-5.2 三層 fallback 思路推到下一格——不只是「同 prompt 換 CLI」而是「**不同 CLI 接力同一個 session**」，每個 agent 做自己強的事，sessions 在 SQLite 裡有 traceable 證據鏈、有 audit log、有可分發的 .db 檔當 collaboration unit。

## Scorer vs Decider——LLM 不做決策只打分數，60 行 TypeScript 做完所有決定

你寫 EQS 全球報價系統 100+ 表單前端流程卡控時，過去用「if 表單值 < x 就 reject」確定性規則。LLM 進來想做 inbox 分類、PDF 結構化、客戶回饋分類也想讓 LLM 直接判斷——但 LLM 會偶發出錯、模型升版行為飄、API 中斷整個流程崩。dev.to 上 k08200 公開一份 production email 分類器設計：**LLM 不做決策只打分數**，4 軸 0–1 範圍——**confidence**（對自己評分的信心）、**sender trust**（寄件者可信度，1.0 = 已知聯絡人 / 0.0 = 匿名行銷）、**reversibility**（誤判可逆程度）、**urgency**（時效需求）。決策邏輯寫在 ~60 行 TypeScript `tier-policy.ts`：**confidence < 0.5 → QUEUE；urgency ≥ 0.7 且 confidence ≥ 0.7 → PUSH；sender trust < 0.2 且 urgency < 0.2 且 reversibility > 0.9 → SILENT；reversibility ≥ 0.85 且 confidence ≥ 0.85 且 urgency < 0.5 且 sender trust ≥ 0.5 → AUTO；其他 → QUEUE**。LLM 失敗就 fallback 到關鍵字打分產出同樣 4 軸數字——證明 LLM 不是 load-bearing for correctness。

設計核心翻轉是「問題從『哪個模型推理最強』改成『哪個模型評分最一致』」。前者選 frontier model（貴 + 慢 + 行為飄）、後者選便宜模型（快 + 穩 + 變異小）——因為決策邏輯被搬到確定性 code 裡，模型輸出 variance 變成可量化的工程指標而非可接受的「AI 怪行為」。AUTO 門檻刻意設高（`confidence ≥ 0.85` 且 `reversibility ≥ 0.85` 同時成立）——**結構上保證「不可逆破壞性動作」永遠不會被自動執行**，不靠模型自律。Auditability 是另一層：tier-policy.ts 60 行 code review 一次看完所有路徑、behavior 可預測、可寫單元測試——對比 LLM-as-classifier「給個 label 然後相信它」黑盒，這套設計 model swap（從 Fable 5 換 Haiku 4.5 或 GLM-5.2 自架）只要 variance 還在門檻內就不用改 policy code。Failure transparency 是第三層：LLM rate limit / API 中斷時 fallback 關鍵字打分產出同樣 4 軸數字結構，證明 LLM 是「精度提升器」而非「correctness 來源」。

以前 Henry 的 EQS 表單卡控是「人寫規則 → 規則執行」確定性流——可預測、可審計、可單元測試。Nexus design token 一致性 review 想引入 Claude API 又怕「Claude 偶發說 OK 但其實 token JSON 不一致」——這條矛盾過去靠人工 review 兜底。Scorer vs Decider 開出第三條路：**Claude 對每個 token 變更打 4 軸分數（consistency / breaking change risk / scope / urgency）回 JSON，packages/ui/scripts/token-tier-policy.ts ~60 行 code 拿分數決定 auto-merge / queue / block**——Claude 換 model 升級（Fable 5 升 Opus 4.8 或換 GLM-5.2 自架）只要 variance 還在門檻內就不用改 policy code，policy code 跟 model 解耦。對應 6/23「LLM-as-judge 0.85 vs trace-based 0.000」洞察——judge 從黑盒分數翻 4 軸 trace contract，今天加上「**決策邏輯永遠在 code 不在 model**」這層 production 保險。對 Henry 三條工作脈絡可同時動：（1）Nexus packages/ui design token review 接 4 軸 Scorer vs Decider，Claude 打分、tier-policy.ts 60 行決策、policy 寫進 git 可 review；（2）MES 戰情室 ECharts 異常曲線 AI 註解 PoC 套同一套——Claude 對每個異常點打 4 軸（confidence / business impact / reversibility / urgency），警報邏輯寫在 alert-tier-policy.ts，警報結構不靠模型自律；（3）Claude_auto SKILL.md Step 2a 「入選過濾」其實就是 Scorer vs Decider 雛形——可以正式寫進 frontmatter 把 relevance（1–5）跟 specific-number-found（boolean）當 scoring 軸，is-inclusive 當 decision 軸，policy 寫在 article-tier-policy.ts 而非 prompt 散文。
