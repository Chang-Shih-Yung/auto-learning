# 2026-05-12 學習日誌

## TanStack 84 個惡意版本——你的 CI/CD 也可能正在洩漏發布權限

如果你有一個用 PNPM Workspace 維護的 npm 套件、用 GitHub Actions 自動發版，那麼 5/11 凌晨發生在 TanStack 上的事情就是你可能遇到的攻擊腳本。攻擊者在 19:20–19:26 UTC 之間，透過 TanStack repo 的 `bundle-size.yml` workflow 漏洞，**一次推出 42 個 `@tanstack/*` 套件、84 個惡意版本**到 npm registry——router、history 整個家族全被汙染。從發布到被發現只有 20 分鐘，但 detection 不是內部 alert，是外部研究者撿到的；20:00 開始響應、21:00 公開揭露，期間 npm 還拒絕 unpublish，整個遠端套件市場被卡在「中毒版本仍可被裝」狀態好幾小時。

攻擊鏈三步：第一步，`bundle-size.yml` 用 `pull_request_target` 觸發，這個 trigger 不需要 maintainer 批准就會跑 fork PR 的程式碼；第二步，攻擊者 fork 之後在 PR 裡把惡意程式碼塞進 pnpm store cache，這個 cache 是 GitHub Actions 跨 workflow 共用的——production workflow 後續 restore cache 時就會載入受汙染的依賴；第三步，當 production workflow 拿到 `id-token: write` 權限要發 npm 時，runner 會 lazily mint 一張 OIDC token 到記憶體裡，惡意程式碼把這張 token 抽出來，直接呼叫 npm registry 跳過原本 workflow 的人工批准步驟，把 2.3 MB 的混淆過 `router_init.js` 包進 84 個版本——這個 payload 會掃描 AWS、GCP、Kubernetes、Vault、GitHub、npm、SSH 的本地憑證並透過加密 Session messenger 端點外洩。

以前的 npm 供應鏈攻擊主要是「typosquatting」（搶相近套件名稱）或「maintainer token 被洩」，防守線是「不要把 token 寫進 repo」。現在的攻擊往上游搬一層：攻擊面不是 token，是 **workflow trigger 的權限邊界**——`pull_request_target` 允許 fork 程式碼用 base repo 的權限執行、pnpm store cache 是跨 PR 共用的污染管道、OIDC token 即使是 short-lived in-memory mint 也可以被 in-process 程式碼撈走。對你 Nexus CI/CD 發 npm 套件的流程直接的啟示：審查所有 `pull_request_target` workflow（最好換成 `workflow_run`）、把 cache scope 隔離（不要讓 PR workflow 和 publish workflow 共用 cache key）、npm provenance + trusted publisher 雖然能綁 SHA 但救不了 in-workflow 取 token 的攻擊——所以還是要走「publish 走獨立 protected workflow、PR workflow 永遠拿不到 `id-token: write`」的隔離設計。

## Thinking Machines「Interaction Models」——把「等完整 turn」這個假設拿掉

如果你做過 MES 即時看板那種「機台狀態變化就要立刻反映」的系統，你會立刻看懂 Thinking Machines 在 5/11 發表的 Interaction Models 在解什麼。他們發布的 `TML-Interaction-Small`（**276B 總參數、12B active MoE**）做了一件 GPT、Claude 都還沒做的事：**模型不等使用者講完話、不等視訊播完一段就生反應**。turn-taking 延遲做到 0.40 秒（業界最佳）、interaction quality（FD-bench v1.5）77.8 分對比競品 45.5–54.3、TimeSpeak（時間感知任務）64.7% vs GPT Realtime-2.0 的 4.3%——這個落差不是 fine-tuning 出來的，是把「即時互動」做進模型架構本身。

技術上做了三件事：**Time-aligned micro-turns**——把音訊／影片切成 200ms 的小片段持續餵進模型，不再以「整輪 turn」為單位等待；**Early fusion**——音訊用 dMel 壓縮、影片用 40×40 patches，這些前處理直接和 transformer 一起訓練而非外掛；**Dual architecture**——一個 fast interaction model 處理即時對話、另一個 background model 跑非同步的深度推理。也就是說，turn 不是固定的、感知不會在生成時被凍結、模型可以「邊聽邊講」（同時 input/output stream）。RAG / tool calling / ReAct 那一條路是「外部 orchestrator 圍著一個 turn-based model 轉」，interaction model 把 orchestrator 拆掉、把責任搬進模型本身。

對你 Angular + RxJS + SignalR 那條「即時數據→ECharts 重繪」鏈來說，這篇是同一個工程直覺被搬到 LLM 層：你的 MES 系統不會等使用者「按下查詢」才更新看板、生產數據 stream 進來就 push、ECharts 就重繪，因為「等完整 turn」這個假設在生產線上根本沒意義。Interaction model 把同樣的直覺帶到 AI 互動：使用者半句話講到一半、視訊裡有東西飛過去、麥克風背景有警告聲——這些 200ms 片段不該等使用者「講完一個 turn」才被 model 看見。從這條哲學延伸到瀏覽器端：未來 design tool 裡 AI 助手不該等你「按提交」才幫你 review，你還在拉 Figma 圖層它就該開始講話；MES dashboard 上 AI 不該等你「問問題」才解釋異常，看板數值剛抖就該主動觸發。

## Claude Code v2.1.139 `/goal` + Agent View——讓 Claude 自己判斷任務完成沒

你跑 Claude_auto 排程任務應該有遇過這個痛點：給 Claude 一個 prompt、它跑完最後一個 tool call 就停了，但 task 還沒真的完成。5/11 釋出的 Claude Code v2.1.139 加了 `/goal` 指令，讓你**設一個「完成條件」**，Claude 會跨 turn 持續工作直到 goal 達成——適用 interactive mode、scripts、Remote Control 三種場景。同版本還加了 Agent View（research preview）：跑 `claude agents` 會跳出一個 dashboard，把所有 Claude Code session（active / awaiting input / completed）放在一個面板看；transcript 導覽加了快捷鍵（`?` 開幫助、`{`/`}` 跳 prompt、`v` 切換 panel），plugin 端 `claude plugin details` 會列出每個 plugin 的元件清單和**估算的 token 成本**。

底層的變動更有意思：stdio MCP server 現在會收到 `CLAUDE_PROJECT_DIR` 環境變數，這是 stdio MCP 第一次能在啟動的當下就知道 project root，不必再從 cwd 或 argv 推測；hook 多了 `continueOnBlock` 設定，被擋下時可以把 rejection 原因 feedback 給 Claude 而不是直接斷掉；HTTP/SSE stream memleak 上限拉到 16 MB；mouse wheel scroll 在 Cursor、VS Code 1.92–1.104 都優化過；過期 credentials 的 deadlock prevention 也補了。

Before：你寫 Claude_auto 的 SKILL.md，要在 prompt 裡用「請確認 X、確認 Y、確認 Z」這種文字描述終止條件，Claude 解讀對不對全看 prompt 寫得好不好。After：`/goal "今日 journal 已寫且 push、AnnotationCard MDX 通過驗證、session-log 已更新"`——終止條件變成 first-class 設定，不是 prompt 內嵌邏輯；同樣地，以前 stdio MCP 要知道 project root 得在 hook 裡自己解析環境，現在 `CLAUDE_PROJECT_DIR` 直接給。三件事同一個直覺：**把「靠 prompt 慣例維持」的契約往「first-class 環境契約」搬**——5/11 FastMCP 把 MCP server 從 protocol 層拉到 Python decorator 層、AGENTS.md 把 npm 文件從 README 拓展出機器讀的格式，今天 `/goal` 把「終止條件」從 prompt 內嵌升格為一級設定，全是同一條主線在動。

## 今日總結

今天三條獨立路徑——TanStack 把 CI/CD 發版權限搶走、Thinking Machines 把「等完整 turn」假設拆掉、Claude Code 把「終止條件」從 prompt 內嵌升格為一級設定——指向同一個工程結論：**把「依賴慣例維持的契約」改成「first-class 顯式契約」**。

- **TanStack 攻擊鏈**揭示「workflow trigger 權限邊界 / cache scope / OIDC token 流向」原本都靠「我們約定不會這樣用」維持，攻擊者只要找一個 `pull_request_target` workflow 就把整個 trust assumption 翻過來——契約不顯式宣告、防守線就在你看不到的地方。
- **Interaction Models 架構**揭示「等使用者講完一個 turn」這個 turn 邊界從來不是技術限制、是「我們約定一個 turn 大概 1–3 秒」的隱含契約——一旦把 200ms micro-turn 當第一級單位，turn-taking、視覺主動、同步說話這些行為直接湧現，FD-bench 從 50 分跳到 77.8 分。
- **Claude Code `/goal`**揭示「prompt 跑完 = 任務完成」是 Claude Code 過去靠 prompt 慣例維持的隱含契約——一旦把 goal 變成一級設定、跨 turn 檢查直到滿足，prompt 內嵌的「請記得 push」這種半契約半提醒的混合就可以拆乾淨。

延續 5/11「介面層往機器讀格式重寫」的主線：FastMCP 在 server 介面層做、re_gent 在 agent 行為紀錄做、AGENTS.md 在 lib 文件做——今天再加三條獨立路徑：**權限邊界**（TanStack 教訓）、**互動單位**（Interaction Models 架構）、**終止條件**（Claude Code `/goal`）。共同的設計動作是「把原本『約定俗成、靠 prompt / convention / human reviewer 維持』的契約，升格為『系統能讀、能驗證、能 enforce』的 first-class 物件」——這是工程成熟度從 prototype 過渡到 production 的一個普遍模式，套用範圍從 SaaS CI/CD 一路展開到模型架構本身。

對你 Nexus / Claude_auto 兩個專案的直接行動點：(1) Nexus 的 PNPM publish workflow 立即把 PR workflow 與 publish workflow 拆兩個 file、cache key 不共用、id-token: write 只給 publish workflow；(2) Claude_auto 的 daily-ai-news SKILL.md 把終止條件從文字描述改成 `/goal "journal pushed AND news pushed AND session-log updated"`。
