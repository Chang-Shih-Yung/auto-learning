# 2026-05-17 學習日誌

## Apple Silicon 跑 LLM 比 OpenRouter 貴 3 倍——本地推論的真實經濟學算給你看

5/17 HN 上 290 點的 [Apple Silicon costs more than OpenRouter](https://www.williamangel.net/blog/2026/05/17/offline-llm-energy-use.html) 把「我在 Mac 上跑 Gemma 自己 host 比較省」這個被傳了兩年的直覺用具體數字打臉。作者拿 **Gemma4 31b**(自己評估「幾乎到 Sonnet 等級」)在 **M5 MacBook Pro 64GB**(售價 $4,299)上跑、量電費 $0.18-$0.20/kWh、算出每 million tokens 的真實成本:**悲觀情境 $1.61-$4.79、樂觀情境 $0.40-$1.20**;同一個 Gemma4 31b 走 **OpenRouter 收 $0.38-$0.50/M tokens**——本地比雲端**貴 3-10 倍**。更慘的是吞吐:雲端 **60-70 tokens/sec**、本地 **10-20 tokens/sec**,慢 3-7 倍;就是說你不只多付錢,還等更久。

這份分析最值得拆開來看的是「本地推論看起來免費」這個直覺從哪裡崩的。本地電費直接成本算下來 $0.40-$4.79/M tokens 區間,看似比 OpenRouter $0.40-$0.50 有競爭力——但雲端 GPU 共享高利用率(每張 H100 同時服務數十個 user 平均掉)、本地 GPU 大半時間 idle 卻照吃電,經濟學 fundamentally 是「共享資源 vs 專用資源」的差異。再加上 M5 MBP $4,299 折舊三年攤 ~$3.93/天、每天跑 8 小時平均負載,有效成本還要再往上加。作者結論很務實:**對領薪水的工程師,token 成本差距比一小時薪資還小,雲端更實際;對隱私敏感、合規場景、或本來就要買 Mac 的開發者,本地仍有意義,但別騙自己說「省錢」**。

## agent-inspect——把 multi-agent 失敗從「flat log 看不出哪裡爆」變成可視 execution tree

dev.to 5/17 [Debugging Multi-Agent Systems in TypeScript: From Flat Logs to Execution Trees](https://dev.to/chintanonweb/debugging-multi-agent-systems-in-typescript-from-flat-logs-to-execution-trees-1foo) 用一個 incident response 場景把「multi-agent 系統的真實 bug 在 agent 之間、不在 agent 內」這件事具象化。一個 multi-agent 流程處理 incident:diagnose → execute remediation(database + scaling 兩個 agent 並行)→ resolve conflicts。**第一次跑 47.2s timeout 失敗、第二次修好跑 15.3s 成功**(3 倍快,且穩定)。但 flat log 看不出問題在哪——database agent 跟 scaling agent 各自決策都合理、各自 LLM call 都成功;直到把 execution 攤成 tree:`execute-remediation [41.8s] ✗ → scaling-remediation [41.7s] ✗ → scale-database [39.1s] ✗ "Operation timeout - cluster in inconsistent state"`,才看到兩個 agent 同時動了 database 資源、coordinator 的 conflict resolver 根本沒被觸發到。

這個案例的洞察是 multi-agent debugging 跟 single-agent 是兩個完全不同的工程題。Single-agent 的 bug 通常是 prompt 寫錯 / tool 回不對的格式,問題在「**一個 agent 內**」、看 LLM call 對話可以找到。Multi-agent 的 bug 是 coordination bug,問題在「**agent 之間**」、每個 agent 看單獨都對,合起來爆——你看再多 prompt、調再多 temperature 都修不到,因為**根本的 fix 是加 resource lock、state refresh guards、coordinator-level resource awareness**,是 distributed systems 設計題不是 prompt engineering 題。Execution tree 之所以救命,是因為它把「並行發生什麼、誰碰了誰的資源」直接可視化,把 flat log 那種「a, b, c, d, error...」的時序敘事改成「a → (b 並行 c) → 在 c 內爆」的結構敘事。

Before:你 Claude_auto 排程跑 daily-ai-news 時偶爾遇到「git push 看起來成功但 news 跟 journal 沒同時 push」的詭異情況,看 stdout log 一行一行讀找不出問題、只能加 print 重跑;你 Nexus 想搞 sub-agent(例如一個 design-token agent 一個 visual-regression agent 並行驗證),但不敢做、因為知道萬一兩個 agent 同時改 CSS file 會炸但不知道怎麼 debug。After:agent-inspect 的設計提示了「multi-agent debug 不是改 prompt 是看 execution tree」這個 mental model——你 Claude_auto 接下來可以把每個 SKILL.md 步驟 wrap 成 `step()` 結構並輸出 JSONL trace,本機可視化看哪步在哪步開始/結束,找「兩步 overlap 動同一檔」這類問題就秒解;Nexus sub-agent 設計也要先做 trace 基礎建設、再寫 sub-agent,而不是反過來。

## 今日總結

兩條獨立路徑,一條算 LLM 經濟學帳、一條算 multi-agent debug 帳,但指向同一個工程命題——**「直覺說 X 一定對,但你沒拿數字 / 沒拿可視化去驗證」**這類假設是現在最容易踩坑的地方。

Apple Silicon vs OpenRouter 把「self-host 一定省錢」這個 LLM 圈傳了兩年的直覺用 $1.61-$4.79/M tokens 對 $0.38-$0.50/M tokens 直接打掉(3-10 倍貴 + 3-7 倍慢),break-even 要每月 600M+ tokens 才會贏;agent-inspect 把「multi-agent 失敗多看 log 就行」這個直覺用 47.2s 失敗 vs 15.3s 修好的 execution tree 對比打掉——bug 不在 agent 內、在 agent 之間,flat log 永遠看不到、必須結構化 trace 才看得到。兩條路徑共同的暗線是 **「直覺用得越久越危險,因為你連『該驗證什麼』都已經忘記」**——5/16 那條「過程必須可重現、可量測、可收斂」洞察在今天兩個維度展開:**經濟學維度需要 spreadsheet、debug 維度需要 execution tree**,沒有對應工具的決策都是手感決策。

對 Henry 立刻可動:(1) 用 5/17 這篇分析寫一個 30 行 Python LLM cost calculator 放 Nexus docs 供 self-host 客戶查詢、(2) Claude_auto SKILL.md 每步驟 wrap 成 step 結構輸出 JSONL trace、本機可視化,排程失敗從盲猜變成看 tree。兩個動作把「LLM 用得久之後變成的默契假設」全部翻成可量測、可可視化的工程設施。
