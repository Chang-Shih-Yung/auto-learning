# 2026-05-27 學習日誌

## Claude Code v2.1.152 — Skill 變成「會自我裁減能力」的活物

你正在跑 Claude_auto 排程任務，這次升上 v2.1.152（5/27 釋出），你可以做的事多了一整層：寫一個 SKILL.md 時直接在 frontmatter 加上 `disallowed-tools`，這個 skill 啟動期間 Claude 就讀不到那些工具（例如不准 Bash、不准 WebFetch），不必再靠文字「請勿使用」這種約定。SessionStart hook 可以回 `reloadSkills: true`，意味著 hook 安裝完新的 skill 後同一個 session 就能立刻用它，不必重啟；新增的 `/reload-skills` 指令讓你手動 re-scan，而 `MessageDisplay` hook 可以在訊息顯示給你之前轉換或隱藏文字。另外 `cache_creation_input_tokens` 之前在 `cache_creation` nested 欄位下回報為 0 的 bug 也修了，你的 cache hit rate 看板會看到正確數字。

這次的設計重心可以一句話收斂：把過去靠 prompt 慣例維持的「能力邊界」全部升格為 frontmatter 與 hook 一級欄位。`disallowed-tools` 對應的是「我不希望這個 skill 不小心呼叫 Bash 把檔案刪了」這種隱性契約，現在系統能讀、能 enforce；`SessionStart.reloadSkills` 與 `/reload-skills` 對應的是「skill 是 session 啟動時 snapshot」這個隱性假設，現在 skill 可以在 session 中熱載；`MessageDisplay` 對應「LLM 輸出就直接顯示」這個隱性管線，現在你可以加一層過濾。同版本還補了 fallback model 自動接手（primary model not found 時整個 session 切過去而不是 per-request fail）、Auto mode 不再需要 opt-in consent、Vim mode `/` 反向搜尋對齊 bash/zsh、`/usage` 串流讀取大 session 檔記憶體不爆。

以前你寫 SKILL.md 要在文字裡寫「請不要修改 memory/learning-context.md」「請不要呼叫 git push --force」，靠 Claude 自律遵守；現在這些可以變成 `disallowed-tools` 或 PreToolUse hook 條件，模型根本看不到那些工具。以前 SKILL.md 在 session 啟動才載入一次，你改完 skill 要 ctrl+c 重啟；現在直接 `/reload-skills`。以前 Vercel build 失敗你要從 commit 內容判斷哪一步 hook 沒攔到；現在 `MessageDisplay` 可以在訊息發出前先攔截關鍵字（例如「skipped」「ignored」）。Skill 從靜態 markdown 變成一個有 frontmatter 契約、可熱載、可在訊息層攔截的「會自我裁減能力」的活物。

## Cursor 3 Parallel Agents — Git Worktree 把三個 Refactor Agent 隔離開

你已經會在 Nexus monorepo 用 `pnpm -r` 跑跨 package 任務，現在你可以把同樣的並行思路套到 AI agent：Cursor 3 用 git worktree 把三個 agent 分流，每個 agent 在自己的 worktree branch 上跑，避免檔案級寫入衝突。範例直接給三條：logging agent 把 `console.*` 改成結構化 JSON log、error handling agent 把 try/catch 標準化、test agent 補上漏掉的單元測試。本地 agent 一次 round trip 5-15 秒、cloud agent 適合多小時任務、單一 agent 預算控制在 2 小時內以免 token 燒太兇。Agents Window 用 `Cmd+Shift+P` 搜「Agents Window」打開，列出所有 active session 對應的 task、repo 與執行端（local 或 cloud）。

實作核心是三條 `git worktree add` 命令把同一個 repo 拉出三條獨立工作樹，每個 worktree 綁一條 feature branch，三個 agent 各自跑、各自 commit、不會在檔案系統層撞車。Prompt scope 是第二道防線：每個 agent 明確被告知「Do not touch test files」「Do not change logging calls」這種負向約束，避免它擴張範圍寫到別人的領地。第三道是 merge 順序——文章特別強調「test suite 要在每一次 merge 後跑，不是只在最後一次跑」，因為兩個 agent 各自跑都綠燈、合在一起可能炸。三個 failure mode 都已知：檔案衝突（兩 agent 同檔寫）、branch 漂移（main 在 agent 跑期間前進）、cost 線性放大（並行三個就燒三倍 token）。

以前你要連續跑三個 refactor 任務、各自驗證、各自 commit，每個任務開新 session 從零等模型暖機；現在你可以一次開三個 worktree，三個 agent 在背景平行跑，你只在 Agents Window 監控結果。對 Nexus 的 `packages/ui` / `packages/cli` / `packages/www` 三個包是直接對應的——你可以把「設計 token 同步」「CLI 命令新增」「demo 站元件 showcase 更新」三條獨立 refactor 各派一個 agent 並行跑，原本一週的 PR 量可以壓縮到一天。這是 5/20 Cursor 3.4 multi-repo environments 的下一層：環境隔離好了，現在是執行隔離。

## Nango AI Builder — 用自然語言生成 800+ API 的 TypeScript 整合代碼

你已經會在 Nexus 寫 MCP server、會跑 Figma → JSON → CSS Token 的 SSOT 工程鏈，現在 Nango（9,000+ stars，今天一天爆增 +860，v0.70.4）給你另一條視角：把整合代碼本身變成 AI 生成物。你描述用例（「同步 Salesforce 的 contact 到我的資料庫，每小時跑一次」），AI builder 產出可讀的 TypeScript function——不是黑箱，而是你能 review、edit、進 git 的代碼。架構只有三個 primitive：Auth（OAuth / API keys）、Proxy（已認證請求）、Function（TypeScript runtime）。背後吞 billions of API requests，per-tenant 隔離、自動 retry、內建 observability，Replit、Ramp、Mercor 已經在 production 用。

技術重點是把「整合」這個動詞拆成三層：authentication 層由 Nango 標準化（OAuth flow、token refresh、credential storage 全部代管）、transport 層由 Proxy 抽象（你的代碼直接打 `nango.proxy.get('/v1/contacts')`，token 自動帶上）、business logic 層才是你寫的 TypeScript function。AI builder 的角色是把第三層自動化——它讀懂你的描述、產出符合 Nango function 介面的代碼，但「黑箱」這件事被刻意避開：代碼可讀、可版控、可手改，這是它跟 Zapier 那種「黑盒 connector」的核心差別。對 monorepo 工作流意義特別大，因為產出物是純 TypeScript，等於你的 packages/integrations/ 就是版控的單一真相。

以前你要接一個新的第三方 API（Stripe、Salesforce、Notion）要從 OAuth 配置開始踩雷，token refresh 要自己寫 cron，rate limit 要自己 backoff，integration code 寫完一個月就會過時；現在你描述需求 → 拿到 TypeScript function → 改成你要的樣子 → push 到 git。對 Nexus 的延伸是：當你要把 Figma → JSON → Token 工作流連到企業客戶的 design system（Figma、Adobe XD、Storybook 各種來源），不用一個一個寫 connector——Nango AI builder 產出第一版，你 review 完就上線。這延續了 5/26 Veso 8 postulate 的「constraints are physics」哲學：整合不是創造性工作，把它交給 AI 生成、把人類審查放在 PR 階段。

## Agent Memory Standard Model — 把 Memory 從「儲存倉」升級成「承重結構」

你已經會用 Claude_auto 的 `memory/session-log.md` 記錄每天討論紀錄，現在 Daniel Nwaneri 提出一個四層架構直接打中你那份 markdown 的設計極限：第一層 Instrumented Capture（在動作當下記錄意圖，不只記成敗）、第二層 Temporal Mirror（事後跑反思 pass 找出語意不像但因果相關的條目）、第三層 Forensic Receipt（用 deterministic UUID edge 取代額外 embedding 把因果連結固化）、第四層 Observer's Tax（instrumentation 必須便宜到能留在 production，不能每個 tool call 加 400ms）。實作上他用 Cloudflare Workers 跑 vectorize-mcp-worker（hybrid vector + BM25 + cross-encoder rerank + Gemma 4 MoE 反思層），event-driven 觸發——只在寫入帶 error state / resolution marker / state transition 時才跑反思 pass。

核心洞察叫「The Sequencing Problem」：因果關係只在事後才看得見。你今天記錄一個 deploy 失敗，當下還沒有 fix；fix 可能是幾天後在另一個 session 才出現的條目。vector search 找不到這條連結，因為失敗和 fix 在 embedding space 中相距甚遠（一個是 stack trace、一個是 config patch），但結構上它們屬於同一條因果鏈。傳統「寫入時打 tag」也救不了——你要打的那個 tag（因果關係）在當下根本不存在。Standard Model 的解法是反過來：寫入時只 capture 意圖，事後跑反思 pass 找出可能的因果配對，用 UUID edge 把它們直接連起來，retrieval 時從 probabilistic 相似匹配變成直接 lookup。

這對你的 Claude_auto session-log 是直接的下一步。現在你的 `memory/session-log.md` 是平面 markdown，「14 天視窗」是固定 cutoff，每天的洞察彼此語意相似但因果分散——5/20「層級分解」和 5/26「驗證機制升格」之間是同一條主線推進，但 session-log 看不到這條 edge。Standard Model 給你一個工程化的升級路徑：保留 markdown 作為 capture 層（你已經在做），加一層 Cloudflare Worker（或 Vercel Edge Function）跑 nightly 反思 pass 把語意不像但因果相關的條目用 UUID edge 連起來。以前 session-log 是「我希望未來能找到」的儲存倉，14 天後就 evict；以後它是「下一個 session 一定看得到上一個洞察怎麼長出來」的承重結構。

## 今日總結

四篇文章今天匯到同一條主線：**把「靠人類記得」維持的契約全面升格為系統能讀、能 enforce 的一級結構**。Claude Code v2.1.152 把 skill 能力邊界（`disallowed-tools`）、生命週期（`/reload-skills`）、訊息層攔截（`MessageDisplay`）三件事從 prompt 約定變成 frontmatter / hook 欄位；Cursor 3 parallel agents 把「三個 refactor 不要互相干擾」這條人類自律拆成 git worktree 三條獨立工作樹 + 負向 prompt scope + per-merge test 三層 enforce；Nango AI builder 把「OAuth + token refresh + rate limit」這套人類重複寫的整合套路升格為 Auth/Proxy/Function 三 primitive + AI 生成 TypeScript，PR review 取代 connector 維護；Agent Memory Standard Model 把「session-log 跨日洞察靠人腦串」這條認知負擔升格為 capture / mirror / receipt / tax 四層 + UUID edge，retrieval 從 probabilistic 變 deterministic。

延續 5/26「驗證機制本身升格為一級工程動作」洞察推到下一層——5/26 是 slash command 層 / approval gate 層 / multi-model review 層 / agent spec 層 / registry schema 層五個維度同時升格，5/27 是把這個動作往「skill 內部能力邊界」「並行執行的隔離邊界」「整合代碼的生成邊界」「跨 session memory 的因果邊界」四個新維度推進。對應 5/12「契約顯式化」的延伸——契約不只升格為 first-class 物件，這些 first-class 物件本身的「能不能修改 / 在不在乎範圍 / 由誰負責 / 怎麼跨時間連結」四個屬性也要升格。

立即可動的三個應用點：(1) Claude_auto SKILL.md 把 learning-context.md 禁令從文字升格 PreToolUse hook + 加 `disallowed-tools` 限制 skill 期間能存取的工具；(2) Nexus packages/ui / packages/cli / packages/www 用 `git worktree` + 三個 Claude sub-agent 並行跑 refactor；(3) `memory/session-log.md` 旁邊建一個 Cloudflare Worker 跑 nightly reflection pass 把跨日因果寫進 UUID edge，下次 session 一啟動就能 traverse 過去 90 天洞察的演化鏈。
