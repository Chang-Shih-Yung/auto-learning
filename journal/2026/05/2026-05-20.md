# 2026-05-20 學習日誌

## 1. Claude Code v2.1.145：背景任務與排程從約定升格為 first-class data

你每天用 Mac mini 跑 Claude_auto 這種 daily AI 抓新聞的排程任務 — v2.1.145（5/19 release）新增 `claude agents --json`，把當前所有 live session 用 JSON 吐出來，可以直接餵給 tmux-resurrect / 狀態列腳本 / 自製 session picker。Stop 和 SubagentStop hook 的 input 從這版開始多了 `background_tasks` 和 `session_crons` 兩個欄位 — 你的 SKILL.md 第一次能精準知道「現在還有哪些背景任務在跑、下一次 cron 何時喚醒」，不再靠 PID 解析或猜測 grace timeout。同版本還補了一個 permission-prompt bypass 漏洞（裸 variable assignment 給非白名單環境變數本來會被自動放過）、修了 17 個 bug，包括 task list 隨機順序、語音 push-to-talk 在 agent view reply pane 不能用、PowerShell 5.1 cross-project resume hint、Read tool 整檔超過 token limit 時改回 partial view 不再 hard error。

這版的主軸是把「子 agent 與背景任務」這層原本還靠約定維持的東西全面 first-class 化。OTEL spans 加上 `agent_id` 和 `parent_agent_id` 屬性，背景 subagent 的 trace 終於能正確 nest 在派發它的 Agent tool span 底下 — Datadog / Honeycomb / Tempo 這些分散式 trace 工具第一次能看出 agent 樹的真實層次。Status line JSON input 自動帶入 GitHub repo 與 PR 資訊，狀態列腳本不必再 `gh pr view` 二次查詢。`/plugin` Discover 與 Browse 螢幕在安裝前就列出 plugin 的 commands / agents / skills / hooks / MCP server / LSP server，套件決策不再是黑盒。一個被忽略但實際很關鍵的修復：`claude agents` tab 標題顯示等待輸入計數，Alt+Tab 切回視窗就知道誰在等人。

以前要寫 Claude_auto 這種長時排程任務，光是「現在還有沒有 background 在跑」這個基本問題就要解析 `ps` 輸出、自己維護 PID file、賭 grace timeout；現在 hook 直接拿到 `background_tasks` 與 `session_crons` 結構化陣列。OTEL trace 從「Agent A 後接 Agent B 後接 Agent C」的扁平假象，變成樹狀真實結構。延續 5/19「層級分解是 AI workflow 工程化的下一步」洞察 — Claude_auto SKILL.md 過去用 `ls` 和 PID 解析湊出來的 idempotency 檢查，現在可以用 `background_tasks` 欄位直接判定，從約定到契約、從 PID 到 first-class structured data。

## 2. Anthropic Cache Diagnostics API：prompt cache miss 從「我也不知道」升格為 production signal

你跑 Claude_auto 每天跑 daily AI digest，每次 session 有沒有打到 prompt cache 直接影響成本與延遲 — Anthropic 在 2026-05 開放 Cache Diagnostics API public beta：每次 Messages request 加上 `diagnostics.previous_message_id`（傳上次 response 的 id），response 就會回一個 `cache_miss_reason` discriminated union 欄位，明確告訴你前綴在哪一段 diverge（system_changed / tools_changed / model_changed / messages_changed 四種 type），附帶 `cache_missed_input_tokens` 估算這次掉了多少可緩存前綴 token 數。Anthropic 官方工程文章直白寫「cache misses are production incidents」 — cache miss 不再是 nice-to-have 的優化點，是 production 級別的事件訊號。

以前要找出「為什麼這次沒打到 cache」只能靠經驗猜：是不是 system prompt 換了一句話、是不是 tool schema 多了一個欄位、是不是 message history 結構漂掉 — diagnostics API 把這個過程做成 structured signal。每種 divergence 是一個明確 type tag、每種都附帶 `cache_missed_input_tokens` 數字（從 byte length 推算，當量級指標而非 billing 數）。第一個 turn（previous_message_id: null）一定回 null，因為 cache 是在 write 不是 read。Fingerprint 對 previous_message_id 的 lookup 有 TTL（短時間），所以要在連續請求之間呼叫才有效。

以前 prompt cache miss 是 Claude_auto 帳單上隱形的成本（每天 14 條目錄串接讀檔，read message history 漂一個 byte 就整段 prefix 重算，但你不會發現，只是 token 帳單默默變大）；現在 cache miss 升格成「可診斷、可定位、可量化損失」的 production signal。Anthropic 把 cache 失誤從「使用者自己摸索」推到「平台給結構化原因」這條線，跟 Claude Code v2.1.145 把 background task 升格成 first-class data 是同一個工程哲學的兩個維度展開 — context 層、排程層雙雙從 implicit 變 explicit、從手感變可量測訊號。

## 3. Cursor 3.4 Cloud Agent Environments：multi-repo agent 環境第一次有 audit log

做 Nexus monorepo（packages/ui + packages/cli + apps/demo + apps/www 四個 package）的時候，cloud agent 跨 repo 跑任務一直是個盲點 — Cursor 3.4（5/13 GA）的 cloud agent environments 把這層補上：一個 environment 定義可以同時掛 multi-repo（建在 multi-root workspaces 之上），agent 跨 session 重用環境定義。Dockerfile 配置加入 build secrets — 讓 agent 在 build step 安全存取私有 package registry，build secret 嚴格 scope 在 build 階段，不會被傳進 runtime agent 環境。Layer caching 升級，只重 build 改動的層、cache hit 時 build 速度快 70%。

這版的工程亮點是把「dev environment 本身」當作一級可治理物件。每個 development environment 都有自己的 version history，user 可以 review 和 rollback，admin 可限制 rollback 權限只給 admin。Audit log 紀錄 team member 對 environment 做的每一次修改，安全團隊第一次有完整 visibility「誰、什麼時間、改了哪個 environment 的什麼配置」。Egress（出網規則）與 secrets 可以 scope 在 environment 層 — 一個 environment 配的 secret 不會被另一個 environment 拿到，避免「公司內部 dev env 的 secret 不小心被客戶 demo env 吃到」這種跨 environment 污染。

以前在 monorepo 跑 cloud agent，要嘛把所有 repo 塞進一個 mega image（build 30 分鐘改一行就要重 build），要嘛切一堆獨立 environment（cross-repo task 跑不了）；Cursor 3.4 解開這個 trade-off：multi-repo 環境定義 + per-environment audit log + per-environment egress scope，讓 cloud agent 跑跨 package 的修改也能保留完整 audit trail。對 Nexus 這種要推企業客戶的元件庫，「我們的 AI 自動化工作流有 audit log + 每個 environment 獨立 egress 控制」從口號變成可勾選的配置 — 延續 5/15「責任邊界正在被工程化拆解」洞察推到「cloud dev environment 也是責任邊界」這個維度。

## 4. Google AI Edge Gallery：MCP 整套搬進 Android、reasoning 留裝置只送 structured call

拿一台配備現代 GPU 的 Android 手機（Pixel、Galaxy 都行）就能跑 — Google AI Edge Gallery 在 5/19 把 MCP（Model Context Protocol）整套搬進 Android 端，用 Gemma 4 模型透過 LiteRT-LM backend 跑，prefill 速度 3,000+ tokens/s on modern phone GPUs，session reconstruction（重啟 app 載入舊聊天）近乎即時。Streamable HTTP 是當前 transport（Android 限定，iOS coming soon），同一條 HTTP/SSE 通訊協定讓 MCP server 接進來不需要 mobile-specific 改寫。

這個架構的關鍵設計是把 reasoning 與 tool calling 拆成兩件事。模型把 MCP tool definitions 拉進 system prompt，所有 reasoning、tool selection、request 生成、notification scheduling、chat history 全部在裝置上做，只有最終的 structured API call 出網。對比 cloud agent 把整段對話送上雲端，這版只送結構化請求出去（例如「呼叫 calendar.create_event(title='Team Sync', time='2026-05-21T14:00')」），不送原始 query 和 reasoning context。外部 MCP server 看不到使用者的原始問題，只看到結構化函數呼叫。

以前 mobile AI agent 要嘛只能本地、不接外部工具（變成單機計算器），要嘛接外部工具、整段對話送雲（醫療 / 法律 / 個資場景直接出局）；現在 Google 把 reasoning 留本地、structured request 出網的拆法 — 是 healthcare / legal / 任何「原始 query 不能離開裝置」場景的解法。對 Nexus 推企業客戶時的「設計 token / 元件 metadata」這類「結構化資料是 API contract」哲學，這版在 OS 層用同一個直覺：context 留在裝置、介面用結構化資料對外 — 跟你在元件層用 token JSON 取代 pixel diff 是同一個工程支點。

## 今日總結

四條獨立發佈（Claude Code v2.1.145 / Anthropic Cache Diagnostics API / Cursor 3.4 Cloud Agent Environments / Google AI Edge MCP on-device），同一個工程動作：**把原本「implicit、靠約定維持、出問題只能猜」的訊號層，全面升格為 explicit、structured、可診斷的 first-class data。**

- Claude Code v2.1.145 把 background_tasks 與 session_crons 從「自己解析 PID」升格為 hook 直接拿到的結構化欄位
- Cache Diagnostics 把 prompt cache miss 從「我也不知道」升格為四種 type tag + token 量化的 production signal
- Cursor 3.4 把 cloud agent environment 從「拼 Dockerfile + 賭環境變數」升格為 version-controlled、可 audit log、可 per-env egress scope 的一級物件
- Google AI Edge MCP 把 mobile agent 從「對話整段送雲 vs 完全本地離線」二選一，升格為「reasoning 本地 + structured call 出網」的拆分契約

延續 5/19「層級分解是 AI workflow 工程化的下一步」洞察推到「每一層的訊號表示也該層級分解」——觀測層（OTEL trace）、context 層（cache miss 結構化原因）、環境層（per-env audit log）、傳輸層（structured tool call vs raw query）四個維度今天同時動。對應的 Claude_auto 直接受益點：SKILL.md 幂等性檢查改用 background_tasks 欄位、收 cache_miss_reason 進 14 天看板、把抓資料 / 寫文章拆成不同 agent environment、Nexus 元件 metadata 用 MCP tool schema 暴露給 on-device 設計師 agent。
