## Anthropic 把整套華爾街工作流拆成 10 個 vertical agent，全開源 Apache-2.0

**來源：** [Agents for financial services — Anthropic](https://www.anthropic.com/news/finance-agents) ｜[anthropics/financial-services GitHub](https://github.com/anthropics/financial-services)（19K stars、2.5K forks、Python 86.4%、Apache-2.0）

你現在如果是 Goldman Sachs 的 analyst，每週要花 8 小時手刻 pitchbook、4 小時做 month-end reconciliation、3 小時跑 KYC 流程；Anthropic 在 5/5 紐約的金融服務簡報會發表了 10 個 vertical agent template，每一個都對應一個被點名的「最耗時間的工作項目」——Pitch Agent、Meeting Prep、Market Researcher、Earnings Reviewer、Model Builder、Valuation Reviewer、GL Reconciler、Month-End Closer、Statement Auditor、KYC Screener。這 10 個 agent 都是 plugin 形式，可以在 Claude Cowork 與 Claude Code 裡載入，也可以用 cookbook 部署到 Claude Managed Agents——repo 達 19K stars 不到一週，Apache-2.0，企業可商用。Jamie Dimon 站台、Moody's 數據與 LSEG / S&P Global 預先做好 partner-built plugin。

repo 的結構是 Henry 你寫前端架構會立刻看懂的設計：`/plugins/agent-plugins/` 是按工作流命名的單一 agent（month-end-closer、kyc-screener）、`/plugins/vertical-plugins/` 是按業務領域打包的 skill bundle（investment-banking、private-equity、wealth-management、fund-admin），`/plugins/partner-built/` 留給第三方資料商接入。同一個 codebase 同時提供 horizontal slice（單個 agent）和 vertical slice（整套 workflow），讓 deploy 粒度從「上整套 stack」降到「先試 KYC 這一個」——介接成本從月降到天。

以前要在金融機構導入 AI，你的選擇是「客製化開發 6 個月」或「買 SaaS 把資料送出 firewall」；現在你有第三條路——把 `anthropics/financial-services` clone 下來、改 vertical-plugin 的 system prompt、套用自家 data 來源、留在自家 infra 跑。對 Henry 你在東捷 EQS 做過 100+ 表單流程卡控的經驗直接對標：金融工作流的本質不是 LLM 多強，是 domain knowledge 怎麼 codify 成可重複的步驟——Anthropic 把 codify 那一步替你做完了，留下「把自家業務規則套進去」的空間。

## Microsoft 365 add-ins GA：Claude 跨 Excel/PowerPoint/Word/Outlook 共享同一份 context

**來源：** [Anthropic deepens push into Wall Street — Fortune](https://fortune.com/2026/05/05/anthropic-wall-street-financial-services-agents-jamie-dimon/) ｜[Anthropic Wall Street 推進 — CIO Dive](https://www.ciodive.com/news/Anthropic-deepens-financial-services/819638/)

你在開 Excel 處理 Q1 財報數據、切回 PowerPoint 做投影片、再切到 Word 寫 credit memo——以前每切一個 app 就要重新貼上下文、重新解釋「我要做的是什麼」；5/5 上線的 Claude for Microsoft 365 add-ins（Excel/PowerPoint/Word GA、Outlook public beta），讓同一個 Claude agent 跨四個 app 共享 context，在 Excel 改了一個數字、PowerPoint 投影片的數字自動跟著動、Word 的 credit memo 也即時對應更新。具體場景包括：Excel 建模並對連結工作表的公式做交叉驗證、PowerPoint 自動同步底層數字、Word 套自家 template 編輯 credit memo、Outlook 當 chief of staff 分類信件並用使用者語氣回信。

技術上這不只是 plugin 加總——Anthropic 把 Microsoft 365 的四個 app 視為「同一個工作環境的不同 view」，所有 Claude agent 共用一份 conversation state 與 file context。當你在 Excel 編輯了一個 formula，PowerPoint 端的 agent 看到的不是「新檔案」而是「同一個 workflow 的新狀態」，所以投影片可以即時 reflow。這套架構直接對應 Henry 你 Nexus 在推的 Single Source of Truth——Figma → JSON → CSS Token → 元件 是一條 SSOT 鏈，「跨 app 共享 context」是 SSOT 在 OS 層的展開。

以前生產力工具的 AI 整合是「Excel 有 Copilot、PowerPoint 有 Copilot、各自獨立」；現在 Claude 把它變成「整個 Office 是一個 agent 環境」。對 Henry 你做設計系統的 SSOT 哲學是直接驗證：設計 Token 從 Figma 同步到 CSS 變數再到 Angular 元件這條鏈，跟 Excel 數字 → PowerPoint slide → Word memo 是同一個「資料只該有一個來源」的工程直覺，只是領域不同。

## Opsera + Cursor 把企業 DevSecOps 嵌進 IDE：高速 AI codegen 撞上 SOX 治理的折衷方案

**來源：** [Opsera and Cursor Partner — PRNewswire](https://www.prnewswire.com/news-releases/opsera-and-cursor-partner-to-embed-autonomous-ai-agents-directly-into-ai-sdlc-workflows-for-next-gen-ai-driven-development-302762277.html)

你的開發者用 Cursor 一天可以寫 2000 行 production code，但 enterprise security team 還在 review 你三天前的 PR——5/5 Opsera 跟 Cursor 宣布合作，把 Opsera 的 DevSecOps Agents 直接嵌進 Cursor IDE，讓「AI 寫 code」跟「企業合規檢查」在同一個編輯器裡同步發生，不是事後才被擋下。簡單說：你按 Cursor 的 generate，generated code 進入 staging 之前先過 Opsera 的 SOX / PCI-DSS / SOC 2 policy 檢查，違反 policy 的修改在 IDE 內就被擋下並標出原因，不會跑到 PR review 才被擋下浪費 24 小時。

這條路徑跟你 Henry 在前公司用 GitLab + SAST 白箱資安整合的經驗有直接對話——SAST 是「程式碼進 main branch 前的最後守門員」，治理是 CI 層的事；Opsera + Cursor 把這道守門員前移到 IDE 層，「最後守門員」變「第一個 reviewer」。差別不只是時間軸——SAST 在 CI 層看到的是「整個 file diff」，IDE 層看到的是「使用者正在編輯的那一段」，policy enforcement 的粒度可以細到行而不是 file。

以前 enterprise codebase 引入 AI codegen 是個 trade-off：要嘛開放、賭使用者不違反 policy、賠時間在 PR review；要嘛全擋、賠生產力；現在第三條路是「在 IDE 層即時 enforcement」——這對 Nexus 未來要推到企業客戶時是個直接參考：Nexus 元件庫如果在 generated code 進 monorepo 前就跑 design token 一致性檢查，就能避免「使用者改了 hardcoded color、CI 才擋下」這種事後處理。

## 今日總結

5/5 是 Anthropic 大幅展示「vertical AI 工作流」的一天——三條獨立線索匯流到同一個工程結論：**AI 整合的下一個瓶頸不是模型強度，是工作流邊界怎麼切**。

1. **vertical 比 horizontal 重要**：anthropics/financial-services（19K★）把同一個 codebase 切成 horizontal slice（10 個獨立 agent）+ vertical slice（按業務領域打包的 skill bundle），讓 deploy 粒度從「整套 stack」降到「先試一個 workflow」——介接成本從月降到天。
2. **跨 app context 共享是 OS 層的 SSOT**：Claude for MS365 把 Excel/PowerPoint/Word/Outlook 視為「同一個 agent 環境的四個 view」，跟 Henry 你推 Nexus 把 Figma 與 Angular 視為「同一份設計資料的兩個介面」是同一個工程直覺。
3. **治理從 CI 層下移到 IDE 層**：Opsera + Cursor 把 DevSecOps policy enforcement 搬到 keystroke 層，從「事後 PR review 擋下」變成「編輯時即時阻擋」——這個路徑可直接套用到 Nexus 未來推給企業客戶時的設計 token 守門設計。

應用點：把 financial-services repo 的 plugin 結構作為下一次 Nexus 重構的參考；把「跨 app 共享 context」的 architecture 寫進 Nexus 設計 token 同步機制的 RFC；把 Opsera 的 IDE-layer policy enforcement 寫進 Nexus 「企業版」roadmap。
