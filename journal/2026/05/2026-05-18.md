## Semble——給 AI agent 用的 code search,98% 少 token、p50 latency 1.5ms

5/17 Show HN 上的 [Semble](https://github.com/MinishLab/semble)（1.5K stars / MIT / Python）把「給 LLM agent 用的 code search」這條工程題打開——同樣是找一個 function 定義,你 Claude Code 過去 grep+read 三五次工具呼叫吃掉 5,000-8,000 tokens、把一堆無關片段塞進 context 讓模型自己篩；裝 Semble + 設好 MCP server 後同樣查詢直接回 5-10 段最相關 snippet 吃 150-200 tokens——**98% 的 token 節約**,且品質沒掉(NDCG@10 0.854,等於 CodeRankEmbed Hybrid 99% 的搜尋品質)。query latency p50 **1.5ms**(CodeRankEmbed 的 11× 快)、索引建置 **263ms**(218× 快),所有運算 CPU 跑、不用 GPU、不送任何資料到雲端。直接 `pip install semble` 或 `uv tool install semble`,MCP server 對 Claude Code / Cursor / Codex / OpenCode 都接得進去。

技術上 Semble 兩個 retriever 並行:**semantic retrieval 用 Model2Vec 嵌入 (potion-code-16M 這個輕量 quantized 模型)、lexical 用 BM25 抓 identifier 與 API name**,結果用 Reciprocal Rank Fusion 融合、再走一層 code-aware reranker 微調——adaptive weighting(symbol query vs natural-language query 給不同權重)、definition boost(symbol 宣告位置加分)、identifier stem matching(`getUser` 跟 `getUserById` 視為同根)、file coherence(同檔多 hit 連帶提權)、對 test 跟 legacy code 打負分。整套 retrieval 跑在 CPU 上完全不呼叫 LLM,這是為什麼能塞進 MCP server、跟 Claude Code 同進程跑而幾乎不增加延遲——換句話說,它是「把 5/2 Context Gateway 那個 proxy SLM 壓縮思路下沉到 IDE 工具層」的具體實作。

Before:你 Claude Code 在 Nexus monorepo 找一個元件用法、找一條 design token 定義、找一個 hook 在哪些 file 被 import,grep 撈一堆無關 match 燒 token、Claude 再花一輪自己篩、不確定有沒有漏——大型任務動輒 50K tokens 燒在 code search 一個動作上。After:裝 Semble 後 search 從「列出大量檔案讓 LLM 自己篩」改成「先精準篩好再給 LLM 看」,token 帳單直接降一個量級,而且因為輸出量小、Claude 不必 compact context,recall 也跟著穩。對你 Nexus packages/ui、packages/cli、apps/demo、apps/www 四個 package 結構,可以各裝一份獨立 Semble index,Claude Code 跑 `/qa` 或 `/review` 時先 narrow 到對應 package 再 search,token 與召回率雙贏。

## $20 Claude Pro 的真實成本是 $200-400——AI 訂閱經濟學的 reset 是 when 不是 if

5/17 HN 上 365 點的 [AI subscriptions are a ticking time bomb for enterprise](https://www.thestateofbrand.com/news/ai-subscription-time-bomb) 把你「月付 $20 用 Claude Pro 跑 Claude_auto 排程」這件事的真實經濟學算出來:**Anthropic 用戶平均消耗 $8 of compute for every $1 of subscription revenue**(這個比例就決定訂閱不可能永遠維持)、典型 knowledge worker 的 Claude Pro 使用實際對應 **$200-400/月的 API 成本**、ChatGPT Plus 報導指出 **每用戶服務成本超過 $100**、GitHub Copilot 在 $10/月訂閱上 Microsoft **每位用戶虧 $20**(power user 虧到 $80)。換句話說你訂閱費低於 sustainable price 至少 10×——這個訂閱定價必然會 reset、不是「會不會」是「什麼時候」。Anthropic 2026 年化營收已經 **$30B**(從 2025 年底 $9B 翻 3.3×)、OpenAI 預估 **2029 累積燒 $115B 現金**、Oracle 為 OpenAI 數據中心一年內背 **$43B 債**、Goldman Sachs survey 顯示企業 AI 預算「超支量級不只 1-2 倍」、企業未來 12 個月平均 AI 支出預估 **$207M**(YoY 翻倍)。

訂閱經濟學失衡的成因有三條疊在一起:(1) **agent workload 吃 token 是指數而非線性增加**——你 Claude_auto 每次 wakeup 跑一輪 daily-ai-news 燒掉的 token 比一次手動對話多 10-50×,因為 agent 反覆 read/write/verify;(2) 訂閱定價是 2023-2024 在「人類對話為主」假設下訂的,而現在實際 workload 是「agent 自跑」、是另一個量級;(3) cloud provider 為搶 GPU 容量過度承諾未來營收(Oracle / MS / Amazon / Google 鎖容量都是同個 dynamic)、debt 滾出來必然轉嫁到使用者端。三個結構性壓力加總意味著 IPO 前的一兩年內訂閱重新定價、subscription 升級到 metered usage、或對 agent workload 另立計費,三選一是必然事件。

Before:你假設 Claude Pro $20/月可以一直用、Claude_auto 排程任務的成本永遠是 fixed monthly,所以 SKILL.md 裡 hardcode `claude --model opus` 沒設計「換 provider」這條 escape hatch——一旦 Anthropic 改成 metered 計費,你每天三條 workflow 的成本可能從 $0 (in subscription) 變 $30-100/月。After:這份報告把假設拆掉——你應該現在就在 SKILL.md 把 LLM provider 從 hardcode Anthropic 改成 model-agnostic abstraction、試一次同份 SKILL.md 在 Anthropic / Gemini 2.5 Pro / GPT-5 三家跑 daily-ai-news 並量化結果差異(也許 Gemini Pro 跑這種 news curation 夠用且便宜 5×)、把 Anthropic 帳單接 webhook 設「月超預算 50% 自動告警」、把 5/10 Hermes 那套 model-agnostic harness 哲學提前落地。等於把 5/7 val.town 從 Clerk 搬到 Better Auth 那條「library-first 避免 SPOF」直覺,在 LLM provider 層提前做防禦。

## Transformers.js 在瀏覽器跑 LLM——參數量不預測 INP,encoder-only 才安全

dev.to 5/17 [I Ran AI Models Directly in the Browser and Measured What It Did to Core Web Vitals](https://dev.to/mspk97/i-ran-ai-models-directly-in-the-browser-and-measured-what-it-did-to-core-web-vitals-4adj) 把「on-device AI 塞進前端」這條走了好幾年但一直沒人量化的設計題用具體 INP 數字壓住了。你 Mac 16GB MacBook Pro 上開 Chrome、Next.js 頁面 import Transformers.js (Hugging Face 走 WASM)、載入一個 INT8 quantized (q8) 模型,實測:**DistilBERT (66M) sentiment 分析 INP 27.8ms**(Google「Good」門檻是 &lt; 200ms,直接過)、記憶體只多吃 59.6MB、memory pressure 2.5%;**BERT-base (110M) feature extraction INP 85ms**(「Needs Improvement」邊緣)、+65.3MB;**MobileViT-S (5.7M) 圖片分類 75.6ms**、+37MB、輕但堪用;**Whisper Tiny (39M) 語音辨識 540.3ms**——直接「Poor」級別、雖然 params 最少。

這份實驗最反直覺的結論是 **「參數量不預測 INP」**——Whisper 才 39M、比 DistilBERT 66M 小一半,卻 INP 慢 20 倍。原因是 encoder-decoder 架構需要 **autoregressive token generation**(一個 token 生完才能生下一個),整個過程鎖死 main thread;DistilBERT 是 encoder-only,一次 forward 就出結果不阻塞。所以選 in-browser 模型的設計約束從「越小越好」變成「**優先選 encoder-only、autoregressive 一律塞 Web Worker**」。同時這些數字是高階 M-series Mac 量出來的,**mid-range Android 預期 INP 3-5× 更糟**——你開發階段過的測試到使用者手上不見得過,所以實測標準要拉到「mobile + 3G throttle + 5-year-old device」這條 baseline。

Before:你 Nexus 想加「即時情感分析」「自動標 tag」「對話 UI 即時翻譯」這類 AI 互動,直覺只有兩條路——上 OpenAI / Claude API(資料外洩 + 延遲 + 訂閱費)或想過「跑在 client 端」但沒具體數字、不敢做設計決策。After:這份實驗給你直接可決策的 INP 門檻——DistilBERT 級 encoder-only 模型可以同步觸發、不必 Web Worker;BERT-base 級要 defer 到 post-interaction;Whisper 級 encoder-decoder **必須**塞 Worker、且 mobile 上要實測;模型挑「encoder-only + INT8 q8」當設計約束就過 Core Web Vitals。對應 Nexus 元件庫,可以做一組 `<AIField>` 元件預設帶 DistilBERT INT8 走 Transformers.js、跑本地不上雲、failure mode 退回 input field 不掉功能——把「on-device AI」做成 default 元件能力而不是 add-on,跟你 5/13 Needle 那條「26M 小模型超越 270M-600M 大模型」是同個工程結論的兩個面。

## Aggregate Benchmarks Lie——700 AI 函式分 5 個 security domain,「最會寫」跟「最會修」是兩種能力

dev.to 5/17 [Aggregate Benchmarks Lie: What 700 AI Functions Look Like by Security Domain](https://dev.to/ofri-peretz/aggregate-benchmarks-lie-heres-what-700-ai-functions-look-like-by-security-domain-1hgj) 把「該用哪個模型寫哪種 code」這件事用真正細粒度的數字壓住——研究團隊跑 **700 個 AI 生成函式 × 5 個 security domain × 5 個模型 (Claude Haiku 4.5 / Opus 4.6 / Sonnet 4.5 / Gemini 2.5 Flash / Pro)**,用 ESLint 系列 security rule(332+ 條 / 18 plugin)當判定標準,每個 domain 跑 7 iteration、各 28 data point。結果反直覺到讓「選最強模型」這個直覺整個失效:**Database 操作**最差生成是 Haiku(39% 漏洞率),但 **最佳 remediation 是 Gemini Pro 93% 修復率**;**JWT 認證**最佳生成是 Gemini Flash 直接 0% 漏洞;**File I/O** Gemini Pro 寫 86% 漏洞但 Opus 73% 修復;**Configuration & Secrets** Gemini Flash 寫 21% 漏洞、Opus/Flash 同 100% 修復;**Command Execution 整個業界沒解**——所有模型修復率都 &lt; 20%,必須人工 review。

這份研究 surfacing 出的真正設計問題是 **「aggregate benchmark 把 domain expertise 平均掉」**:SWE-bench / HumanEval / MBPP 給你一個總分、你照分數選模型,但實際工作場景每個 domain 的行為大不相同——同一個 Gemini Pro 在 File I/O 寫程式漏洞率 86%(最差),在 Database 改程式修復率 93%(最佳),「總分」這個 metric 把這兩個極端拉到中間、誰也對不上現場。更重要的是研究跑完整 generation + remediation cycle 後,**Opus 從 aggregate 第 4 名爬到第 1 名、淨剩漏洞率 25.7%**(Haiku 初始 49% 退到第 4)——揭露真正的設計題不是「選最強的模型」、是「**不同任務階段選不同模型**」:生成階段一個模型、remediation 階段另一個模型、Command Execution 強制人工。

Before:你 Nexus / Claude_auto 直覺都用 Sonnet 或 Opus 一條道走到底、覺得「比較貴就比較好」;這份數據告訴你 (1)「寫」跟「修」是分開的選型題、(2) 不同 security domain 適合不同模型、(3) command execution 這類任務不管哪個模型都要人工 review、別自動 merge。After:對你 /qa /review /codex 三層工作流可以直接套用 5/16 那條「結構性切割 per-module fresh session」具體 routing 規則——packages/cli(有 shell execution)強制 codex + 人工雙審不自動 merge、packages/ui(DOM 操作)Sonnet 寫 Gemini Pro 修、apps/www(auth flow)Gemini Flash 寫 Opus 修、apps/demo Haiku 寫 Opus 修。把 5/8「AI Router 41% 成本降幅」從 task 層(chat vs code)推到 security-domain 層的細粒度路由,等於把 5/16 SWR-Bench「跑 N 次 aggregate recall +118%」這條「同模型多次 sample 增訊號」的直覺,搬到「**不同模型分階段增訊號**」這個新維度。

## 今日總結

四條獨立路徑指向同一個工程命題——**「LLM 用得越多,工具選型 / 模型選型 / context 餵法 / 訂閱經濟學」這四件事從可以靠默契維持的 background assumptions,升格為必須顯式設計、量化驗證、提前防禦的工程一等公民**。

Semble 把 code search 從「給 LLM 自己 grep 完慢慢篩」拉到「先精準索引、再給 LLM 看」(98% token 節約 / 1.5ms p50);AI subscription time bomb 把「$20/月可以一直用」這條 background 假設拆掉($8 compute per $1 revenue / $200-400/月真實成本 / 訂閱 reset 是 when 不是 if);Transformers.js Core Web Vitals 實測把「on-device AI 大概可以塞」變成可決策的 INP 門檻(encoder-only 27.8ms safe / encoder-decoder 540ms must Worker / 參數量不預測延遲);700 函式 security domain 研究把「選最強模型就好」這條 background 直覺拆掉(Gemini Pro File I/O 86% 漏洞但 Database 修復 93% / Opus 從 aggregate 第 4 爬到 cycle 後第 1 / Command Execution 業界沒解必須人工)。

延續 5/16 那條 4 條獨立路徑匯流的洞察——**「責任邊界拆好後,過程屬性(契約評估時機 / drift 偵測 / recall 收斂 / docs 目標讀者)是新的工程設計題」**——今天 4 條獨立路徑往再下一層:**「過程設計好後,『所用工具的成本結構 / 所選模型的 domain 適配 / 所餵 context 的索引品質 / 所付訂閱的可持續性』是再下一層的工程設計題」**。對 Henry 立刻可動的四個動作:(1) Nexus packages/ 各裝 Semble index + Claude Code MCP 接;(2) Claude_auto SKILL.md 把 hardcode Anthropic 換成 provider-agnostic 抽象;(3) Nexus packages/ui 加 `<AIField>` 元件預設 DistilBERT INT8;(4) `.claude/agents/routing.yaml` 寫 per-package 寫/修/人工三段 routing。四個動作獨立,但都對應同一條主線:**把所有「過去靠手感與訂閱補貼撐起來的便利」,改成顯式工程化的可量測能力**。
