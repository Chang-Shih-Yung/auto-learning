## Claude Code v2.1.153 — 把「session 預設值」當一級設定處理

你正在跑 Claude_auto 排程任務，這次升上 v2.1.153（5/28 釋出），最直接會碰到的改動有四個：第一，`/model` 切換完會自動寫成下次 session 的預設值（跟 IDE 對齊），如果你只想換這次 session、不想動預設，picker 內按 `s` 鍵；第二，resume 一個透過 transcript 檔案路徑指定的舊 session 時，過去在「機器上累積很多 session」狀態下會吃掉好幾 GB 記憶體的 bug 修好了——對你 Claude_auto 每天跑、journal/news/showcase 三層輸出累積數百個 session 的情境是直接受益；第三，macOS 上的 background agent 現在在「Privacy & Security」面板顯示為 `Claude Code`、權限授予跨 CC 自我升級不會掉；第四，stateful MCP server 沒接 GET SSE stream reconnect 端點時，`tools/list` 會無限重連的 bug 修了。`claude agents` 的 PR 欄位也改成 `PR #N` / `N PRs` 形式，status line 命令第一次收到 `COLUMNS` / `LINES` 環境變數，讓你寫的 status line script 知道終端機真實寬度。

這次修的東西分散，但底層共識是一致的：**所有「session 等級的偏好」過去都用 per-invocation override 暫存——現在被當一級設定處理**。`/model` 從每次手動切換變成有預設值（跟 IDE 一致是訊號：模型選擇從 ad-hoc 變 SLA）；`COLUMNS` / `LINES` 從「你猜終端機多寬」變成「環境變數帶過來」；macOS 權限從「每次升級重申」變成「跨升級持久」；MCP server 連線從「只負責 happy path」變成「reconnect-loop 是 production incident」。同版本還補 `claude doctor` 顯示上次更新嘗試結果、`skipLfs` 讓你 clone 大型 plugin marketplace repo 時跳過 Git LFS 拉取、`agents` autocomplete 的 dispatch input 把 native slash commands 和 bundled skills 一併納入提示——以前只列 project skill，新手 onboarding 看不到內建能力。

以前你 Claude_auto 每天起來都跑同一個模型，要切到 Haiku 跑分類任務、再切回 Opus 寫 journal，要寫成 `--model` flag 帶兩次；現在你 `/model` 設好 Opus 為預設，個別 step 需要 Haiku 時按 `s` 切一次就好，不影響下次 session。以前 resume 跑久了 RAM 漲到 4GB+，你以為是 macOS 的事，其實是 transcript file path lookup 把整個 session 索引讀進記憶體；v2.1.153 之後 Claude_auto 可以 resume 一年前的 session 都不爆。以前 stdio MCP server 重連會把你的 `/usage` 看板里的 token 紀錄全弄亂，因為 reconnect-loop 觸發無限 `tools/list`；現在那條路徑被修了，你的 MCP server （包含 Nexus MCP server）可以放心做長時 stateful 連線。對 Claude_auto SKILL.md 立即可動的一行修改：把 `--model` flag 改寫成 `s` 鍵 + 預設值，session 開銷少一層 prompt。

## Hermes Agent 跑 30 天自己長出 17 個 Skill — 從「7 天能變」到「30 天穩定改善」

你已經會設計 Claude_auto 的雙檔分工（`learning-context.md` 鎖定 + `session-log.md` 可寫），現在 Stephen Sebastian 把 Hermes Agent 同樣的「self-improving skill」設定跑滿 30 天，給出量化結果：agent 自己生成了 17 個 custom skill；同一個 PR 摘要 + 依賴檢查任務，第 1 天要 4–5 次 prompt 才完成、第 30 天只需要 1 次 prompt；單次重複任務從 20 分鐘壓到 8 分鐘，全月 ~45 件任務累積省了 9 小時；總成本 $6.47/月（$5 VPS + $1.47 API）。技術核心是 **四層記憶模型**：Working memory（當前對話）+ Procedural memory（`~/.hermes/skills/` 裡的 skill 文件）+ Episodic memory（SQLite + 全文搜尋）+ Semantic memory（開發者 profile model）。改進機制叫 **GEPA loop**——每 ~15 個 task 跑一次自我評估，發現某類任務成功率 < 90% 就用 genetic-Pareto prompt evolution 產出 candidate skill 改寫版本，不用 GPU 訓練、純 prompt 演化。

這次的關鍵是「30 天」這個尺度——5/16 同一個系統跑 7 天的實驗，能展示「skill 檔從 12 行 → 62 行 procedural complexity 5×」這種變化，但無法分辨那是真改善還是混亂累積。30 天結果給三條重要對照：(1) skill 數量從 0 → 17 不是線性堆，而是「同一個 PR 摘要 skill 第二次遇到新 repo 時自動 fork 出 markdown table 變體 + 依賴檢查邏輯」這種收斂式增長；(2) 4–5 prompts → 1 prompt 證明 GEPA loop 不只讓 skill 多，是讓「達成同一結果所需 prompt 數」單調下降；(3) 作者也誠實列三個 failure mode——silent failures（錯了但訊息不清楚）、over-engineering（一個一次性任務生出 47 step skill）、context bleed（不相關對話之間 leak）——說明 self-improving 系統不是「跑越久越好」，需要 invariant guard 偵測這三類退化。

以前你 Claude_auto SKILL.md 是手寫定版、每天跑同一份流程，要升級得自己改 markdown；現在你看到一條經過 30 天驗證的工程化升級路徑——把單檔 SKILL.md 拆成四層記憶（procedural skill 檔 + episodic SQLite log + semantic user profile + working session），加 GEPA loop 在固定間隔自己評估失敗率。對你 Claude_auto 的具體應用：(1) `memory/session-log.md` 現在扮演 episodic memory 的角色，加一個 fields 紀錄每天「事前 prompt 數 / 事後成功率」就有 GEPA 觸發條件；(2) `memory/user-profile.md` 對應 semantic memory，已經是現成的；(3) 把 `learning-context.md` 的「核心工作流」拆成 N 個小 skill 檔（fetch / filter / write / commit），讓 self-improvement 在「fetch 步驟成功率 < 90%」這種粒度觸發，而不是整份 SKILL 重寫；(4) 同時為三個 failure mode 設 invariant guard——silent failure（每步必須 echo「OK」或 `FAIL: <reason>`）、over-engineering（單一 skill 超過 100 行強制 split）、context bleed（每個 sub-task 新開 sub-session）。從 7 天看「能不能變」到 30 天看「變得穩定」，這是 Claude_auto 真正升級成自我演化系統的工程藍圖。

## Anthropic 首次在企業支出超車 OpenAI — Claude Code/Codex 是 PMF 的轉折點

你已經把 Claude Code 選為主力 AI 開發工具、用 Anthropic API 跑 Claude_auto，現在 Ramp 5/13 公佈的 April 2026 商用支出數據第一次給出量化排名：**Anthropic 業務採用率 34.4%（月增 3.8 個百分點）vs OpenAI 32.3%（月減 2.9 個百分點）**——年增上 Anthropic 4 倍 / OpenAI 0.3%，方法是 Ramp 自家 50,000 家企業客戶的法人卡 + 發票支付資料。Simon Willison 5/27 把這個數字串成「Anthropic 與 OpenAI 同時找到 PMF」的論述，給的具體佐證：Anthropic Q2 傳聞營收 $10.9B（vs 2025 年 8 月 $4B、其中 Cursor + GitHub Copilot 貢獻 $1.2B）；SpaceX 同意付 Anthropic $1.25B/月直到 2029 年 5 月鎖算力；ChatGPT 週活 9 億人但只有 5,000 萬付費（5.6% 轉換率），代表變現命脈在 Codex / Claude Code 這類 power user 工具，不在訂閱 chatbot。價錢變動：Opus 4.7 比 Opus 4.6 貴 ~1.4×、GPT-5.5 比 GPT-5.4 貴 2×。

**4 月 是 PMF 轉折點**因為兩家同時把企業計費從 flat-rate seats 改成 API-based token 消耗——以前一家公司買 100 seat $20K/月、用多用少一樣錢，現在按 token 算實際使用量、合約續約取消之前 seat 折扣。直接後果是預算被吃爆：Uber 報導「2026 年 AI 預算才幾個月就破上限」、Microsoft 在會計年度結束前（6/30）因「財務」理由取消部分 Claude Code 授權。Simon Willison 個人用量直接示範這個數字怎麼跑——他 30 天 API 用量 $1,199.79（Claude）+ $980.37（OpenAI）= $2,180.16，相當於 11 個月份 $200 訂閱費。企業 hiring 也跟著轉軌：OpenAI 703 開放職缺裡 229（32.6%）是 enterprise-focused、Anthropic 390 開放職缺裡 105（26.9%）enterprise-focused，兩家都把企業銷售當主戰場。

以前你選 Claude Code 是憑使用體驗（contextual reasoning、long-running session 穩定）；現在這個選型有市場數據背書：商用採用率第一次有正式排名，Anthropic 在你已經選的方向上前進。對 Nexus 的延伸是兩個：第一，Nexus MCP server 該優先支援 Anthropic 標準（你已在做），這條方向被 4× 年增證實是逆風變順風；第二，Claude_auto 跑的 token 預算要嚴格——按 Simon Willison 數據，一個 power user 一個月 API 燒 $1K+ 是常態，企業預算「全年用幾百」是上世代假設，新世代是「每個 power user $1K+/月」。對你個人薪資談判 / Nexus 商業模式都是直接情報：4/2026 起企業客戶的 AI budget 不再有上限假設，那麼把 Nexus 賣成「省 token」「結構化 context」「reduce 模型來回」這類論述就有了精確市場語言——9 hours/month 節省 Hermes 算成 $2,000+ consulting-rate equivalent 那種計算邏輯，可以套到 Nexus 對企業客戶的價值主張。

## 今日總結

三篇文章今天匯到同一條主線：**「跑得久」這件事本身正在被量化、被定價、被工程化**——session 累積、skill 自我演化、API 計費三個層次同時出現「長期跑」的可量測門檻。Claude Code v2.1.153 修了 transcript file path resume 累積多 GB 記憶體的 bug + 把 `/model` 從每次手切升格為預設值 + macOS 權限跨升級持久，把「session 預設值」「跨升級持久性」「reconnect 不死迴圈」這些原本暫存的偏好升格為一級設定；Hermes Agent 30 天實驗給出「self-improving skill」第一份 30 天尺度的量化資料——17 skills 自動生成、4-5 prompts → 1 prompt、20min → 8min、$6.47/月、GEPA loop < 90% 觸發——把「skill 跑越久越好」從直覺升格為可校驗門檻；Anthropic 在 April 2026 第一次以 34.4% vs 32.3% 超越 OpenAI、SpaceX $1.25B/月鎖算力、企業計費 flat seat → API token，把「跑越久越貴」從風險升格為精確市場語言。

延續 5/27「契約 first-class 物件本身的『屬性』也要 first-class 化」洞察推到下一層——5/27 講把契約升格為可讀可 enforce 的一級結構（能力邊界 / 並行隔離 / 整合邊界 / 因果邊界），5/28 把這條主線推到「時間維度」：session 預設值跨時間持久（CC v2.1.153）、skill 演化跨 30 天可量化（Hermes）、商業計費從 flat seat 轉成跨時間累積（Anthropic 4× 年增）。對應 5/18「過程設計好後，工具成本結構是下一層工程設計題」推到「工具成本結構的時間維度（採用率、年增、token 計費）也要設計」。
