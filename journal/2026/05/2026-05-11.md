## FastMCP v3.2.4：MCP 伺服器的「FastAPI 等級」開發體驗，70% 的 MCP server 都用它

如果你已經會用 Python 寫 FastAPI，現在用 FastMCP 寫一個 MCP server 只需要學 `@mcp.tool` 一個裝飾子——把函式的 type hint 自動轉成 JSON Schema、把 docstring 自動轉成參數說明、stdio / Streamable HTTP / SSE 三種傳輸格式自動切換。FastMCP 在官方 MCP 生態裡的地位不是「另一個選項」：Prefect 維護的這套框架 25,102 stars、1,998 forks、每天被下載一百萬次、社群統計顯示「跨所有語言、70% 的 MCP server 由 FastMCP 寫成」，並已被併入官方 MCP Python SDK。最新 v3.2.4（4 月 14 日發布，代號 "Patch Me If You Can"）補了三個安全洞、改善了一個常見的設計痛點。

技術面三個重點：第一，FileUpload 從只看「字串長度」改成驗證實際 base64 解碼後的大小，繞過了「填超大字串繞過大小限制」的攻擊路徑。第二，AuthKit 開始遵守 RFC 8707 自動綁定 token 的 audience，意思是「給 server A 的 token 不能拿去打 server B」——這是 OAuth 多 server 場景下的標準防越權做法。第三，Keycloak OAuth provider 正式進入框架內建選項，企業環境的 SSO 整合不再需要自己拼。同時還有兩個 DX 提升：tool 的參數說明現在會自動從 docstring 抽出來（不必再重複寫 description），ctx.elicit() 開始回傳更完整的 metadata。

以前要寫一個 production 等級的 MCP server，你要自己處理 JSON Schema 生成、stdio / HTTP 雙傳輸協議解析、OAuth 流程、tool/resource/prompt 三種 MCP 物件的註冊機制——光是 boilerplate 就上百行。現在 FastMCP 把「best practice 內建到框架」當設計準則，把 MCP 從「協議實作」抽象到「Python function + decorator」這個你已經熟悉的層級。對 Nexus 的 MCP server 來說，這意味著從「為了支援 Claude 寫一份 protocol-level 程式碼」升級成「直接把 ui-token / component-spec 變成 Python function，FastMCP 自動暴露給 LLM」——和你用 Angular CDK 抽象掉 DOM 細節的設計哲學是同一個。

## re_gent：給 AI Agent 用的 Git，三個指令把「哪個 prompt 改了這行」變成可查的 blame

re_gent 解決一個很具體的問題：當你跑 Claude Code 跑半天、agent 做了 30 個檔案改動，git log 只會告訴你「Claude 在某個時間點 commit 了一坨」——它不會告訴你「第 18 行是被哪個 prompt 改的、改之前的版本長什麼樣、那輪對話上下文是什麼」。re_gent 不取代 git，而是在旁邊跑一條獨立的時間線：每個 tool call 自動產生一個 step，整個 session 就是一張有向無環圖（DAG），存在 `.regent/` 目錄裡。它用 BLAKE3 內容定址雜湊做去重、用 SQLite 索引讓 `rgt blame` 在毫秒級回應、多個 agent 平行跑各自占獨立分支不會打架。三個核心指令：`rgt log` 看 step 歷史、`rgt blame <path>:<line>` 找出哪個 prompt 改了這行（含上下文）、`rgt rewind` 做非破壞性的時光倒流（即將推出）。

技術骨幹是把 git 的「commit = 一份 snapshot + 父 commit + author」改寫成「step = 一份 workspace snapshot + 父 step + conversation delta + tool metadata + session ID」。和 Claude Code 整合的關鍵是「hook 驅動捕捉」——你不需要手動 commit，agent 每跑一個 tool 就自動產生一個 step，整個過程透明不打斷。這條路線跟 4/30 的 Tilde.run（atomic transaction sandbox）解的是同一個問題的兩面：Tilde 從「事前可逆」切入（agent 跑完才 commit），re_gent 從「事後可查」切入（agent 跑的時候每步都記錄），兩個都在補 git 對 AI agent 「太粗糙」的不足。

以前 agent 跑壞了，你只能回頭翻 Claude Code 的 transcript、把「對話」和「檔案改動」自己腦補對上去——這在多 agent 並行（你已經有 `worktree.baseRef=fresh` 的設定）會變得無法 trace。re_gent 把「prompt → tool call → file change」這條因果鏈直接做成可查資料結構。對 Claude_auto 這類排程任務，意義是稽核從「commit message 自我描述」升級到「每個 step 都有獨立的 audit record」——這延續了 5/4 的「稽核訊號必須由獨立稽核層產生」這個結論，把它從 fixture / workflow SHA256 這類靜態 invariant 延伸到 agent 執行過程的動態軌跡。

> ⚠️ 目前 347 stars，新工具，使用前請自行確認安全性。

## AGENTS.md：到了 2026，你 npm package 的主要讀者已經不是人

shimmer-trace（React skeleton loader）的作者 jeetvora331 上週做了一個一次性決定：在 npm tarball 的 `files` 陣列裡加入一份 AGENTS.md，跟 README 並列。他的觀察是 2026 年大多數「讀」你 lib 文件的不再是人類，而是 Cursor、Claude Code、Codex 這類 coding agent，但 README 的寫作慣例（marketing 開頭、安裝指令、API table）對 LLM 來說資訊密度太低、敘事順序也錯——LLM 要的是「export 列表 + 完整 type 定義 + 編號 usage pattern + 決策樹 + 常見錯誤對照」，這跟人類讀者要的「為什麼用這個」是兩件事。作者花了大約 2 小時寫了一份六段式的 AGENTS.md，shipped 之後回報的 issue 數明顯下降，agent 推薦這個 lib 的頻率也提升。

六個 section 的結構值得直接抄：（1）一段話總結這個 lib 是做什麼的，（2）完整 export 列表，（3）每個 export 的 type 定義與 props，（4）編號的 usage pattern（不是隨意排列，要有編號讓 LLM 引用），（5）「何時用哪個 pattern」的決策樹，（6）常見錯誤對照——錯誤實作配對正確實作（作者稱這是「祕密武器」）。第 6 點的設計邏輯是 LLM 容易學壞 example、會把錯誤模式記成「合法用法」，所以你必須主動把錯誤模式跟正確模式擺在一起，逼模型在生成時做對比判斷。AGENTS.md 不是 README 的替代，是 README 旁邊另一條獨立的訊息通道，給機器讀。

以前你寫 npm package 的文件，目標讀者是「會主動 google 你 lib 的工程師」——你優化的是 conversion、文案、安裝門檻。現在你的 lib 大多是被 LLM 「順手」推薦的，模型決定要不要用、怎麼用，全靠它能不能讀懂你的 type 定義和 usage pattern。AGENTS.md 是把這個轉變顯式化的第一個社群慣例。對 Nexus 這種「給工程師用的 UI 元件庫 + Token 系統」尤其重要——你已經把 Figma 設計編譯成結構化 JSON Token，再多一份 AGENTS.md 把元件 API + 常見錯誤對照寫清楚，Claude 在使用者問「Nexus 的 button 怎麼用」時，會給出比現在準確得多的範例。

## 今日總結

三條獨立路線匯流到同一個觀察：**AI 工程生態的「介面層」正在從人類讀的格式，往機器讀的格式重寫。**

- **FastMCP v3.2.4** 把 MCP server 的開發體驗從「協議實作」拉到「Python decorator」，70% MCP server 都用它、每天一百萬下載、RFC 8707 audience binding 補上多 server 場景的越權洞——MCP 已從早期協議推廣期進入框架成熟期。
- **re_gent**（347 stars）把 git 的 blame / log 模式抽象再做一份給 agent，BLAKE3+DAG+SQLite 做底層，三個指令 `rgt log/blame/rewind` 對應 git 的核心心智模型——「agent 行為的版本控制」這個工程題已有可用 prototype。
- **AGENTS.md 慣例** 把 npm package 文件從「README 給人看」拓展出第二條獨立的「AGENTS.md 給機器看」訊息通道，六段式結構（總結 / export / type / usage / 決策樹 / 常見錯誤對照）兩小時可寫，可直接套到 Nexus 每個 workspace 包。

**核心應用點：** FastMCP 是 Nexus MCP server 從零到一的最佳起點；re_gent 的 step DAG 概念可借來設計 Claude_auto 的 audit log；AGENTS.md 是 Nexus 對外 lib 文件的下一個明確 todo——三件事都直接對應到你已經啟動的工程鏈，不需要新學技能，只是把現有資產用 AI-readable 的格式再 mirror 一份。

延續 5/8「prompt engineering 的天花板：控制流比 prompt 更重要」這個結論，今天三條線索把它推到更上游：**控制流的設計，從 agent 內部往外延伸——server 介面（FastMCP）、agent 行為紀錄（re_gent）、lib 文件結構（AGENTS.md）三者都是「給 LLM 一份結構化、可預測、可稽核的工程契約」的具體實作。** 機器讀的介面層，是 2026 年的設計系統。
