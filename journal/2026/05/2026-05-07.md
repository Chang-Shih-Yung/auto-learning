## Claude Code v2.1.132：Bash subprocess 拿得到 session ID 了

你今天在 Claude Code 按 Ctrl+C 中斷一個跑很久的 sub-agent，以前有時候會殘留半啟動的 MCP 子程序——v2.1.132 把外部 SIGINT 改成走正常 shutdown 流程，子程序會收到正確的清理訊號。同步修了：plan-mode 用 `--resume` 回到舊 session 時 `--permission-mode` flag 失效的回歸 bug、Bash tool 子程序現在會收到 `CLAUDE_CODE_SESSION_ID` 環境變數（hook 裡可以拿來精準關聯日誌）、stdio 的 MCP server 記憶體洩漏徹底修掉、Bedrock 和 Vertex 開 prompt caching 時偶發 400 錯誤也修了。整版 30+ 修復都是長時運行 agent 的基礎設施題。

這版改的 30 多項裡，三個是 AI Workflow 的關鍵基礎設施修復：(1) SIGINT 正確 shutdown 對排程任務（像 Claude_auto）至關重要——如果 cron 主程序被 SIGTERM 但 sub-process 沒清乾淨，下次啟動會撞到 stale lock；(2) `CLAUDE_CODE_SESSION_ID` 注入 Bash subprocess，意味著 hook 寫的稽核 log 可以直接用 session ID 對應到後台的 trace 紀錄——稽核訊號終於能跨進程綁定；(3) MCP stdio memleak：長時間跑的 Claude Code session（超過幾小時）以前會看到 RSS 一路攀升，這版直接堵住。

以前你寫 Claude_auto hook 想精準對應 session log，得自己解析 Claude Code 主進程的 PID、讀 ~/.claude 暫存——脆且不可移植。現在 Bash 子進程收得到 session ID 環境變數，hook 直接 `echo $CLAUDE_CODE_SESSION_ID` 進日誌就能跨進程綁定。這代表「稽核訊號」的傳遞鏈條從手寫腳本變成 first-class 環境變數，正好對應 5/4 那條洞察「稽核訊號必須由獨立稽核層產生」。

## Simon Willison：當 vibe coding 與 agentic engineering 開始分不清

你今天打開 Claude Code 寫 Claude_auto 的 daily-ai-news skill——Simon Willison 在這篇文章把這種工作型態叫「agentic engineering」：你有 25 年（他自己）寫 code 經驗，知道怎麼審 AI 生成的程式碼、知道哪段不能信。對比之下「vibe coding」是 non-programmer 直接讓 AI 寫，自己不去看實作。Simon 主張這兩者越來越難區分——隨著 agent 可信度上升，連專業工程師也會懶得審 production code。文章具體節奏對照：以前每天 200 行手寫，現在 agent 出 2,000 行/天，「逐行審」這個習慣根本來不及。

他的論點關鍵在「責任歸屬」：vibe coding 之所以倫理上可接受（用在個人小工具）、agentic engineering 之所以可接受（用在 production），是因為兩者責任邊界不同——前者錯了影響本人、後者錯了使用者倒楣。當 agent 跑出 2,000 行/天，工程師如果還是用「我審 200 行」的舊節奏，他事實上已經在 vibe coding，只是名稱還寫著 engineering。瓶頸從寫 code 上移到「需求 / 設計能不能餵清楚」。

以前 review code 是在每個 PR 上花 30 分鐘逐行看；現在 Claude Code 一個 sub-agent 跑完丟回 600 行 diff，「逐行看」根本來不及。Simon 給的解法不是放棄審查，是「像對待可信賴的團隊成員」——不審每一行、但保有最終責任。對應 Henry 的 Claude_auto：每次 daily 跑完，自動 push 到 main、Vercel auto-deploy——你已經把信任邊界建在 invariant guards（MDX bracket 對稱檢查、git commit 幂等性、檔案路徑驗證）上，而不是手動逐字審稿。

## Tilde.run：把「整個 agent run」做成可 rollback 的 transaction

你在 Claude_auto 跑自動排程，有時候 sub-agent 一不小心 git push 了不該 push 的東西、或寫壞了 journal 檔案，得手動 git revert——Tilde.run 把這個情境搬到產品級：每次 agent 執行都進一個獨立 sandbox container，把 GitHub repo、S3 bucket、Google Drive 三種資料源 mount 進同一個 `~/sandbox` 路徑，所有 file write 都被 staged，clean exit 才 commit、有 error 就整個 transaction discard。網路請求過 policy 層，未授權的 outbound 直接擋（連 cloud metadata endpoint 也擋）。每個 agent 拿到的權限走 RBAC policy 而非 user 權限，agent 之間互相隔離。

背後是 lakeFS 團隊（treeverse/lakeFS 開源資料版本控制專案）做的——他們本來就在資料 lake 上做 Git for data，這次把同一套 commit / branch / rollback 模型搬到「agent 工作目錄」這個層級。技術重點不是雲端 sandbox（市面上一堆），是「filesystem 層的 atomic transaction」——agent 在 sandbox 裡看到的是普通 `~/sandbox` 路徑，不需要改腳本、不需要懂版本概念，但底層每個寫入都進 staging，最後一刀 commit / discard。

以前 Henry 寫 Claude_auto invariant guards——MDX bracket 對稱、journal 路徑驗證、git commit 重複偵測——是「事後檢查」型 guard。Tilde 的設計則是「事前預設可逆」——agent 跑完不對勁，整個 transaction discard，不需要 guard 也不需要逐行 review。這條路線對應 5/2 的洞察「context infra 是獨立工程層」：agent 的可逆性也是獨立基礎建設層，不該每個工作流自己寫 invariant guard。

## val.town 的 auth 三段史：Supabase → Clerk → Better Auth

你想想當年在 EQS 寫過 100+ 表單卡控，每張表的權限路由、session 失效都得自己處理——val.town 把同一條痛苦的路重走了三遍：2023 年 Supabase 出發、年底搬 Clerk、2026 年 5 月落腳 Better Auth（28,181★ TypeScript）。Clerk 的具體痛點是 5 req/sec rate limit（社交頁面要顯示多個使用者頭像直接撞牆）、99.9% uptime 雙倍代表 8.7 小時/年 downtime + Clerk 全當機就所有登入使用者掉線、Clerk 把 user table 跟 session manager 綁死導致資料庫還得另開一張 table 存 username / 設定。

Better Auth 的設計選擇是「auth 是一個 library 不是一個 service」——TypeScript 函式庫、自包含 session、可以離開原廠完全 self-host，付費的 Infrastructure add-on 是可選且 stateless。對比 Clerk 的「auth 是一個 SaaS」——你的 session refresh 必須走他的 API，Clerk 一倒你全倒。三年路徑不是技術錯誤，是基本架構假設的錯誤：把 auth 當外部 service 會引入單點故障、把 auth 當 library 則只是另一段 import。

val.town 用 LLM 輔助跑了 2 週的雙系統並行，把 user 一個一個搬過去——這是「LLM 真正改變開發節奏」的具體例子：以前雙系統並行的 mapping 邏輯每加一個 edge case 要寫 1-2 小時，現在用 LLM 寫 mapping function 縮到分鐘級。對 Henry：Claude_auto 將來要加使用者登入（追蹤誰看了哪篇 journal、私人筆記）的話，library-first 的選型可以省去「發現 SPOF 後再搬」這條經典坑。

## 今日總結

今天的六條線索匯流到三個層次：

**底層算力與 runtime 升級。** Anthropic 雙倍 5h limit + Colossus 1 的 220K NVIDIA GPU + Claude Code v2.1.132 的 SIGINT 正確 shutdown / `CLAUDE_CODE_SESSION_ID` 注入 / MCP stdio memleak 修復——這三條同時上線，意味著 Anthropic 把「Claude Code 是長時運行 agent 工具」這個假設從產品宣傳工程化到底層基礎設施。Henry 的 Claude_auto 排程從這次更新直接受益：跑得更久（雙倍 limit）、跑得更穩（SIGINT / memleak）、跑得更可稽核（session ID 注入）。

**責任邊界 / 可逆性 / library-first 三個 AI workflow 設計支點。** Simon Willison 把 vibe coding vs agentic engineering 的混合理論化、Tilde.run 把 agent 執行做成 transactional sandbox、val.town 從 Clerk 搬到 Better Auth——三條獨立線索匯流到同一個結論：AI workflow 不是把工具堆起來就贏，是要設計清楚「什麼層級該由人審查（責任邊界）、什麼層級該透過 transaction 自動可逆（可逆性）、什麼模組該變 library 不變 service（library-first）」。Henry 的 Claude_auto + Nexus 工作流，已經在這三個維度上各有實踐——這篇日誌可以拿來校對自己的設計選擇。

**OSS 自雇的可驗證 milestone。** jdx 把 mise 全職化的數字（27K 星 → 月入 600 USD baseline → 離職 Figma + 多元變現規劃）給 OSS 維護者一個可驗證的「能否離職」門檻，而不是空泛的激勵。對 Henry 維護 Nexus + Claude_auto 兩個 side project 是直接可參照的 milestone：先跑出小額可驗證收入線，再決策離職時機。
